# ADR 0014: 말풍선 서식과 펼침

## 상태와 범위

**승인 (2026-10-16, 사용자 결정 D-074 — 끝의 "사용자 결정" 참고).** [M13 완료 기준](../progress/milestones.md)의 1번이다. [ADR-0013](0013-plugin-lines.md)의 대사 ID·선택 순서·캐릭터별 덮어쓰기를 유지하면서 2·4·6·7번 구현 경계를 정한다. 1–5장은 **추천**안이 채택됐고, 6장은 펼침 방식 설정(`expandBehavior`)을 빼고 채택됐다. `packages/plugin-sdk/src/v1/` 규약과 기존 외부 플러그인 입력은 바꾸지 않는다.

## 1. 앞말·내용·끝말을 어디에 적는가

| 안 | 형식 | 평가 |
|---|---|---|
| **A. 변형 하나를 문자열 또는 세 필드 객체로 작성 (추천)** | 기존 `"문장"` 또는 `{ "prefix": "주인님,", "content": "출석 완료(09:58)", "suffix": "완료입니다" }` | 변형별 구조와 줄 경계가 분명하고 기존 문자열을 그대로 읽는다. 목록·팩·설정의 변형 타입과 검증·편집기를 함께 확장해야 한다. |
| B. 문자열 안에 전용 구분 기호 | `"주인님,|출석 완료(09:58)|완료입니다"` | 저장 형식 변화는 작지만 실제 대사에 쓰는 기호의 이스케이프·오입력·미리보기 해석이 필요하다. |
| C. 변형 배열과 별도 `formats` 지도 | 변형 인덱스로 구조를 찾음 | 기존 문자열 파서는 유지하지만 변형 순서 변경·삭제 때 구조가 다른 문장에 붙을 수 있다. |

**추천 A의 구체안.** 플러그인 `lines.json`의 `lines[].variants`, 캐릭터 `voice.json`의 `lines[lineId]`와 `templates[kind]`, 개인 `settings.json`의 `lineOverrides[packId][lineId]`에 같은 변형 합집합(`string | {prefix: string; content: string; suffix: string}`)을 허용한다. 세 필드는 모두 문자열이고 앞말·끝말은 빈 문자열을 허용하며 내용은 비어 있으면 거부한다. 객체의 모르는 키는 거부하고 기존 변형 개수(1~8)·선언된 변수·400 코드 포인트 상한은 세 필드의 **템플릿 문자를 합친 값**에 적용한다. 문자열 변형은 구조가 없는 대사다. 예를 들면 `{"id":"jungle.attendance-complete","variables":[],"variants":[{"prefix":"주인님,","content":"출석 완료(09:58)","suffix":"완료입니다"}]}`이고, `voice.json`의 종류별 예시는 `{"done":[{"prefix":"주인님,","content":"{task} → {result}","suffix":"완료입니다"}]}`다. 실제 저장 형식과 오류 규칙은 구현 시 허용·거부 예시를 파서 테스트로 고정한다. 현재 목록·팩·설정이 모두 `string[]`이고 검증 경로가 나뉘어 있다(`packages/core/src/lines.ts:4-11,48-60`, `packages/core/src/voice.ts:5-7,38-80`, `apps/desktop/src/main/settings.ts:56-64`).

`{task}`·`{result}`·`{folder}`·`{message}` 같은 바뀌는 값은 **내용에만** 둔다. 목록의 변수 이름은 해당 `lines.json` 항목의 `variables`에 선언되어야 하고, 종류별 템플릿은 기존 네 슬롯만 쓴다. 앞말·끝말은 캐릭터의 어투이며 고정 문자열이다. 값이 없으면 그 변형을 건너뛰고 다음 변형·다음 계층으로 가는 현 규칙을 유지한다. 선택·치환·정규화 후 세 부분을 따로 보관하고, 줄바꿈을 뺀 단일 문장 `text`도 만든다. `text`의 공백·문장부호는 템플릿의 각 부분을 다듬어 **비어 있지 않은 부분 사이에 공백 하나**를 넣는 규칙으로 고정한다. 화면은 비어 있지 않은 앞말 / 내용 / 끝말을 각각 별도 줄로 그린다. `content` 안의 의미 있는 줄바꿈은 보존한다. 현재 목록은 단일 줄바꿈을 보존하고 종류별 템플릿은 모든 공백을 한 칸으로 접으므로 이 차이는 객체 변형에서도 각 출처의 기존 규칙을 따라야 한다(`packages/core/src/lines.ts:66-68`, `packages/core/src/voice.ts:103-110`, [ADR-0013 4장](0013-plugin-lines.md)).

문장 선택 순서는 **사용자 대사 → 팩 대사 → 플러그인 목록 기본 대사 → 이벤트 `text`**, `line`이 없는 이벤트만 **종류별 템플릿 → `text`**다. 객체 변형은 선택된 그 계층의 구조만 사용한다. 뒤 계층의 구조를 앞 계층 문자열에 합성하지 않는다. 이는 ADR-0013의 사용자 결정과 현재 `applyVoice` 경로에 맞는다(`docs/adr/0013-plugin-lines.md:157-169`, `apps/desktop/src/main/voice.ts:19-40`).

[어투] 탭에서는 구조 변형을 앞말·내용·끝말 입력 세 개로, 기존 문자열 변형을 기존 문장 입력 하나로 보여 준다. 변형마다 `한 문장/줄 나눔` 선택을 두고 변환 전후의 실제 미리보기를 보여 주며, 사용자가 명시적으로 전환할 때만 형식을 바꾼다. 구조 변형의 변수 안내는 내용 입력 옆에 두고, 미리보기·다음 변형·보내 보기·되돌리기는 지금의 대사별 조작을 유지한다. 저장 전 미리보기와 보낸 말풍선이 같은 부분과 문장을 쓰게 한다(`apps/desktop/src/renderer/voice-panel.ts:225-233,254-326`, `apps/desktop/src/main/settings-service.ts:411-431,493-515`).

## 2. 기존 입력과 120자 계약

| 안 | 호환 방식 | 평가 |
|---|---|---|
| **A. 구조를 명시한 변형만 줄 분리 (추천)** | 기존 `lines.json` 문자열, `voice.json` 종류별·대사별 문자열, `lineOverrides` 문자열, 외부 v1 `text`, 직접 보낸 HTTP `/event`의 `text`는 지금처럼 한 덩어리 | 모르는 문장의 앞말·끝말을 추측하지 않는다. |
| B. 문장부호·공백으로 자동 분리 | 기존 글도 새 화면처럼 보임 | 한국어 어미·Slack 본문·경로의 경계를 안정적으로 판단할 수 없다. |

추천 A: 구조가 없는 문장은 화면에서 기존 줄바꿈만 따른다. v1 플러그인이나 일반 HTTP 이벤트가 명시한 `text`에서 구조를 추론하지 않는다. `voice`가 있는 v1 이벤트가 **새 구조 객체를 가진 현재 캐릭터의 종류별 템플릿**으로 성공적으로 치환될 때만 구조 표시가 가능하며, 기존 문자열 템플릿은 그대로다. 외부 v1 `text` 자체를 변환하지 않는다. v1 SDK는 `line`을 받지 않고 그 계약을 바꾸지 않는다(`packages/core/src/contracts.ts:5-25`, `apps/desktop/src/main/voice.ts:35-40`, `docs/adr/0013-plugin-lines.md:164-166`).

`PetEvent.text`의 120 유니코드 코드 포인트 제한은 그대로 둔다. 구조 문장을 평문으로 접었을 때 **앞말+사이 공백+내용+사이 공백+끝말의 합계**에 적용한다. 화면의 줄바꿈은 길이에 세지 않는다. 송신자가 보낸 초과 `text`는 종전처럼 검증에서 거부하고, 내부에서 선택한 대사·어투의 초과분만 120자로 맞춘다. 120자 이하의 `text`와 구조 메타데이터는 함께 생성하되 구조가 120자 텍스트와 다른 말을 표시하면 안 된다. 자세한 자르기 우선순위는 다음 장에 둔다. 현 스키마는 `text.maxLength=120`, `detail`은 문자열이고, 렌더러는 치환 뒤 120자로 제한한다(`packages/core/src/schemas.ts:24-26`, `packages/core/src/lines.ts:83-94`, `packages/core/src/voice.ts:85-110`).

## 3. 어디에서 어떻게 자르는가

현재 말풍선은 글의 줄 수를 제한하지 않는다. 훅이 시킨 일 24자·짧은 문장 전체 80자로 먼저 자르고 `…`를 붙인다. 종류별 어투는 치환 뒤 120자로, 플러그인 대사도 120자로 자른다. Slack은 제목 120자와 본문 잔여 공간을 계산해 자른다. 화면은 최대 폭 280 DIP에서 줄바꿈만 하고 글 줄 수는 제한하지 않는다(`docs/hooks/hook-message.mjs:4-9,71-95`, `packages/core/src/voice.ts:85-110`, `packages/core/src/lines.ts:91-92`, `plugins/slack/src/index.ts:75-81`, `apps/desktop/src/renderer/bubble.css:3-20`, `apps/desktop/src/main/bubble-position.ts:6-7`).

| 안 | 새 표시 규칙 | 평가 |
|---|---|---|
| **A. 원문과 표시문을 분리하고 구조 문장은 내용부터 줄임 (추천)** | 송신자/코어의 현재 상한은 지키고, 화면 줄 제한이 필요하면 내용에 `…`를 붙인다 | 어투를 남기면서 펼칠 원문을 보관해야 한다. |
| B. 최종 합성 문자열을 끝에서 자름 | 구현이 간단하다 | 짧은 내용 뒤에 있는 끝말이 먼저 사라지고 구조의 뜻이 무너진다. |
| C. 화면에서만 CSS로 숨김 | 원문 전달은 간단하다 | 어느 부분이 잘렸는지·펼칠 글이 실제 있는지 판단하기 어렵다. |

추천 A의 **두 단계**: (1) 구조 문장을 만드는 내부 렌더러는 우선 앞말·끝말을 보존하고 내용의 끝에서 코드 포인트 단위로 잘라 `…`를 넣어 평문 120자에 맞춘다. 내용이 1자도 들어갈 수 없으면 해당 구조 변형을 사용하지 않고 기존 다음 변형·계층으로 간다. 구조 없는 문자열은 현재의 끝 자르기를 유지한다. (2) 말풍선은 설정된 최대 폭에서 실제 줄을 측정해 닫힌 상태의 최대 줄 수를 넘으면 **구조 문장의 내용만** 줄여 `…`를 표시한다. 구조 없는 문장은 끝에서 줄인다. 자동 줄바꿈만 일어나고 숨겨진 글이 없으면 `…`를 붙이지 않는다. 앞말·끝말만으로 줄 예산을 넘으면 어투를 잘라 없는 것처럼 보이게 하지 말고, 그 말풍선에서는 줄 제한보다 어투 보존을 우선하며 작업 영역 높이에서는 스크롤한다. 이 예외를 설정 설명에도 명시한다. 버튼은 글자 자체를 자르지 않으며, 버튼 배치가 필요한 폭은 별도로 계산한다(`apps/desktop/src/renderer/bubble.css:23-39`, `apps/desktop/src/main/bubble-window.ts:59-65`).

송신자에서 이미 자른 글은 화면 폭을 넓혀도 되살아나지 않는다. 훅의 24·80자와 Slack의 자체 잘림은 별도 원문이 없으면 `…`만으로 복원하지 않는다. 구현 task는 각 송신자가 가진 더 긴 값을 `detail` 또는 내부 표시 원문으로 안전하게 전달할 수 있는지 점검한다. 바꾸기 전까지는 다음 장의 `detail` 범위까지만 펼칠 수 있다.

## 4. 펼칠 내용의 출처와 경계

| 안 | 펼침 내용 | 평가 |
|---|---|---|
| **A. 원문이 있는 곳에서 명시적으로 전달 (추천)** | 내부 구조 문장은 자르기 전 합성문, 외부·훅·묶음 알림은 `detail`이 있으면 그 값 | 복원할 수 없는 원문을 만들어 내지 않고 현재 `detail`을 활용한다. |
| B. `text`에 `…`가 있으면 다시 조회 | 데이터 전달은 적다 | 이벤트가 사라졌거나 출처가 꺼졌을 때 조회할 수 없고 쓰기/권한 경계가 커진다. |
| C. 항상 `detail`을 원문으로 간주 | 표시 구현이 작다 | `detail`이 부가 설명·경로일 수 있어 정확한 동일 문장이라고 오해시킨다. |

추천 A: 화면에 **실제로 더 표시할 값**이 있고 닫힌 문구와 다를 때만 펼침 표시를 둔다. 내부 렌더 결과는 `shortText`(120자 이하)·`fullText`(자르기 전 합성문)·`parts`를 함께 보관하고, 큐의 병합·교체·즉시 표시를 거쳐 현재 말풍선으로 전달한다. 외부/HTTP `text`는 `detail`이 있을 때만 그 내용을 펼친다. 묶음 알림의 `detail`은 구성원별 `text` 목록이므로, 묶음 제목 아래 자세한 목록으로 보여 준다. `detail`이 없으면 말줄임표가 있어도 펼칠 거리가 있다고 가정하지 않는다. `detail`이 단순한 설명일 수 있으므로 조작 이름은 **“자세히 보기”**로 하고, 내부 `fullText`가 있을 때만 “전체 문장”이라고 부른다(`packages/core/src/notify-queue.ts:134-139`, `apps/desktop/src/main/delivery.ts:14-20,149-157`).

훅은 현재 전체 작업 폴더 경로, 시킨 일 최대 300자, 결과 최대 500자를 `detail`로 보내며, 주석에도 말풍선이 아직 보여 주지 않는다고 적었다. 따라서 펼침은 **전달된 detail의 전체**를 보여 줄 수 있으나 300·500자 이전의 원본까지 보장하지 않는다. 기준 2의 “전체 글”을 엄밀히 만족하려면 훅 송신 단계의 상한을 재검토하고, 원본을 보낼 수 없으면 UI에 “자세히”라고 표시해야 한다(`docs/hooks/hook-message.mjs:8-10,98-105`). `PetEvent.detail`에는 현재 길이 제한이 없지만 무제한 창 크기를 뜻하지 않는다(`packages/core/src/schemas.ts:24-26`).

`detail`에는 폴더 절대 경로·작업 결과·외부 알림 본문 같은 개인정보가 들어갈 수 있다. 닫힌 말풍선·툴팁·상태 출력·로그에는 새로 `detail`을 복사하지 않는다. 사용자의 명시적 펼침 조작 뒤 현재 말풍선에서만 텍스트 노드로 표시하고, 새 이벤트·닫힘·앱 종료 때 렌더러의 지난 내용을 지운다. HTML로 해석하지 않는다. 접힌 표시와 펼친 표시 모두 펫이 있는 모니터의 작업 영역 안에 놓고, 펼친 높이가 작업 영역을 넘으면 **본문만 세로 스크롤**하며 버튼과 닫기 조작은 보이게 둔다. 현재 배치는 작업 영역으로 창 경계를 줄이지만 렌더러에 스크롤이 없어 긴 내용은 그 아래가 잘릴 수 있다(`apps/desktop/src/main/bubble-position.ts:25-41`, `apps/desktop/src/renderer/bubble.css:1-20`, `apps/desktop/src/main/bubble-window.ts:155-176`).

## 5. 클릭·닫힘 충돌

| 안 | 조작 | 평가 |
|---|---|---|
| **A. 본문 첫 클릭 펼침, 다시 클릭 접힘 + 명시적 닫기 (추천)** | 펼칠 내용이 없는 본문·꼬리 클릭은 종전처럼 닫음 | 기준 2의 다시 클릭 동작과 기존 빠른 닫기를 함께 만족한다. |
| B. 항상 본문 클릭은 닫기, 별도 자세히 버튼만 펼침 | 클릭 뜻이 일정함 | “잘린 글을 클릭”하는 기준 2와 다르다. |
| C. 본문 첫 클릭 펼침, 다음 클릭 닫기 | 단계가 적음 | 펼친 내용을 접어 원래 크기를 볼 수 없고 오조작으로 사라질 수 있다. |

추천 A: 펼칠 값이 있을 때 `#text`의 첫 클릭은 펼치고 두 번째는 접는다. 펼친 상태의 **[닫기]**는 알림을 닫는다. 펼칠 값이 없으면 본문·꼬리 클릭으로 닫는다. 펼칠 값이 있는 꼬리는 닫기로 유지하고, 액션 버튼은 지금처럼 해당 액션만 실행한다. 새 이벤트가 오거나 자동으로 닫히면 펼침 상태를 지워 다음 알림에 이어지지 않게 한다. 창의 크기를 다시 측정·배치한 뒤 화면에 표시하며, 클릭 처리 중 오래된 측정 응답이 새 콘텐츠를 덮지 않도록 현재 버전을 확인한다. 현재 본문·꼬리 클릭은 곧바로 dismiss이고 액션은 별도 이벤트를 쓴다(`apps/desktop/src/renderer/bubble.ts:45-68`, `apps/desktop/src/main/bubble-window.ts:71-80,155-168`).

## 6. 설정 키·범위·기본값

| 안 | 저장 구조 | 평가 |
|---|---|---|
| **A. `settings.display.bubble` 및 `settings.display.badge` (추천)** | 표시 관련 설정을 한곳에 둠 | M13-3 배지 칩 설정과 이름을 먼저 합의해야 한다. |
| B. `settings.bubble`·`settings.badge` 최상위 | 기존 최상위 키와 비슷함 | 표시 항목이 늘수록 최상위가 더 넓어진다. |

추천 A는 다음과 같다. `settings.display.badge`는 **M13-3 소유**이며 이 ADR에서는 이름만 예약한다. 모든 폭은 Electron 화면 좌표와 같은 DIP이다. 숫자는 유한한 정수만 받으며 범위 밖·형식 오류는 해당 키의 기본값으로 돌아가고 한국어 설정 오류를 표시한다. 기존 `settings.json`에 `display` 또는 개별 키가 없으면 아래 기본값으로 해석하며, 로드만으로 파일을 다시 쓰지 않는다. 설정 저장 후 **다음 말풍선부터** 적용하고 재시작 뒤 유지한다. 현재 `DeskpetSettings`는 `display`가 없고 없는 키를 기본값으로 파싱하며 파일 저장은 원자적으로 한다(`apps/desktop/src/main/settings.ts:9-28,45-55,169-191`).

| 키 | 허용값 | 기본값 | 적용 |
|---|---|---|---|
| `display.bubble.maxWidthDip` | 정수 180~600 | 280 | 닫힌·펼친 말풍선의 상한. 모니터 작업 영역 폭이 더 작으면 거기에 맞춘다. 현재 상한 280 DIP와 같다(`apps/desktop/src/main/bubble-position.ts:6-7,25-29`). |
| `display.bubble.maxLines` | 정수 3~12 | 4 | 닫힌 본문 전체의 목표 줄 수. 구조 문장에서는 내용부터 줄이며 앞말·끝말 예외는 3장과 같다. |
| ~~`display.bubble.expandBehavior`~~ | — | — | **채택 안 함(사용자 결정).** 펼침은 5장 A의 본문 클릭 방식 하나만 둔다. |

기본 줄 수 4는 **설계 제안값**이다. 구현 시 현 280 DIP에서 내장 알림·버튼과 긴 Orca 결과를 실제 렌더러로 확인하고, 말풍선이 자동으로 잘리는 범위가 과하지 않으면 확정한다. 폭 180~600은 버튼을 담을 최소 공간과 일반 화면에서의 상한을 위한 제안이며, 작은 작업 영역에서는 항상 화면 경계를 우선한다. 새 대기 시간·타이머 값은 제안하지 않는다.

## 기존 ADR과 다른 부분 및 승인 시 정리할 일

- [ADR-0001](0001-pet-event.md)은 `text` 120 코드 포인트와 `detail`을 정한다. 이 초안은 그 공개 필드의 의미·상한을 바꾸지 않고 내부 렌더 결과와 말풍선 전달값만 늘린다. `detail`을 항상 동일 문장의 원문으로 해석하면 ADR-0001의 “상세 보기 내용”보다 뜻이 좁아지므로 그렇게 하지 않는다(`docs/adr/0001-pet-event.md:14-25`, `packages/core/src/schemas.ts:24-26`).
- [ADR-0003](0003-plugin-manifest-and-api-v1.md)의 v1 API는 그대로 둔다. 구조는 v2 대사 목록·캐릭터 팩·내부 화면 데이터에만 적용하고, 외부 v1의 `text` 경로는 유지한다(`docs/adr/0003-plugin-manifest-and-api-v1.md:32-34`).
- [ADR-0013](0013-plugin-lines.md)은 `variants: string[]`와 `lineOverrides[packId][lineId] = string[]`을 승인했고 구현했다. 이 초안의 **객체 변형 추가는 그 저장 형식의 확장**이다. 승인되면 ADR-0013의 적용 순서·기존 문자열을 유지하면서 형식 확장을 명시해 충돌을 정리해야 한다. 승인 전에는 객체 변형을 유효한 데이터로 취급할 수 없다(`docs/adr/0013-plugin-lines.md:70,157-169`, `packages/core/src/lines.ts:4-11`, `packages/core/src/voice.ts:5-7`).

## 사용자 결정이 필요한 질문

1. 변형마다 문자열 또는 세 필드 객체를 허용하는 **1장 A**를 승인할까? 선택지는 문자열 구분 기호(B), 별도 형식 지도(C)다.
2. 구조 없는 기존 문장은 한 덩어리로 두는 **2장 A**, 원문·표시문을 구분하고 내용부터 줄이는 **3장 A**를 승인할까? 자동 문장 분리와 최종 문자열 끝 자르기가 대안이다.
3. 내부 원문 또는 전달된 `detail`만 펼치고, `detail`에는 “자세히 보기”를 쓰는 **4장 A**와 본문 첫 클릭 펼침·재클릭 접힘·명시적 닫기의 **5장 A**를 승인할까? 훅의 300·500자 상한 전 원문은 현재 복원할 수 없다.
4. `display.bubble`의 폭 180~600 DIP(기본 280), 줄 3~12(기본 4), 펼침 `click|button`(기본 `click`)과 `display.badge` 예약이라는 **6장 A**를 승인할까? 최상위 `bubble`·`badge`가 대안이다.

## 사용자 결정 (2026-10-16, D-074)

질문 4개를 하나씩 물어 정했다.

1. **문장 구조:** 1장 A — 변형마다 문자열 또는 `{prefix, content, suffix}` 객체. 바뀌는 값은 내용에만.
2. **호환·잘림:** 2장 A + 3장 A — 구조 없는 기존 문장·외부 v1·HTTP `text` 는 한 덩어리 그대로, 120자는 세 부분 합계, 줄 수를 넘으면 어투는 남기고 내용부터 `…`.
3. **펼침·클릭:** 4장 A + 5장 A — 자르기 전 원문이나 전달된 `detail` 이 있을 때만 펼침(`detail` 은 "자세히 보기"), 본문 첫 클릭 펼침·재클릭 접힘·펼친 상태의 [닫기], 펼칠 게 없으면 지금처럼 클릭 = 닫기. `detail` 은 로그·툴팁·상태 출력에 복사하지 않는다.
4. **설정:** 6장 A 에서 폭·줄 수만 — `display.bubble.maxWidthDip`(180–600, 기본 280), `display.bubble.maxLines`(3–12, 기본 4, 구현 때 실측으로 확정). 펼침 방식 설정은 두지 않는다. `display.badge` 는 M13-3 이 쓴다.

## 구현 결과 (M13, 2026-10-17)

- **펼친 동안 자동 닫힘 멈춤 (D-075):** 펼치면 그 말풍선의 타이머가 멈추고, 접으면 남은 시간(최소 3초)부터 다시 센다. 펼친 상태는 최대 5분 뒤 닫힌다. 교체되면 펼침·멈춤 상태는 지운다.
- **펼친 높이 상한 (D-077):** 펼친 본문은 약 10줄(210px)과 작업 영역 높이 중 작은 값까지 커지고, 넘치면 본문만 휠로 스크롤된다. [닫기]·버튼·꼬리는 항상 보인다. 상한은 설정이 아닌 상수다. 묶음 알림을 골라 처리하는 목록은 백로그(M14 후보).
- **대사 데이터 나누기 (D-076):** 앞말은 호칭·부름만, 끝말은 혼자 한 줄로 읽히는 맺음말만 둔다. 주어와 서술어를 떼지 않는다. 내장 플러그인 기본 대사는 문자열로 두고, wolf-maid 템플릿·lines 가 구조를 가진다.
- **편집기 구조 보존 (D-078):** [어투] 탭의 플러그인 대사 편집기와 상황별 어투(템플릿) 편집기 모두 앞말·내용·끝말 세 칸 편집과 한 문장/줄 나눔 전환을 지원한다. 문자열 변형은 문자열로, 객체 변형은 객체로 저장한다. 상황별 어투 저장은 기존 voice.json 을 읽어 templates 만 교체하고 lines·기타 키를 보존한다. 개발자 모드에서 내장 팩을 고치면 원본 파일이 그 자리에서 바뀐다.
- **바뀌는 값은 내용 칸에만:** `{task}`·`{result}` 같은 슬롯은 content 에만 쓸 수 있다(앞말·끝말에 쓰면 그 변형은 저장 때 버려진다). 끝말·앞말은 잘리지 않고 내용만 줄이는 규칙(3장)을 지키기 위해서다. 저장이 막혔을 때 이유를 보여 주는 안내는 백로그.
- **배지 칩 위치:** 위 배치에서는 펫 창 위쪽에 투명 여백 70px, 옆 배치에서는 양쪽 220px 을 둬 간격(0–40)이 실제로 반영된다. 발 위치는 바뀌지 않는다.
