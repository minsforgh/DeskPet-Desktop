# ADR 0009: 화면 지형과 이동

## 상태

**승인 (2026-10-09, 사용자, D-052). 12장 잠정 채택도 함께 확정. Q6 은 17장(D-054)으로 대체됐다. 구현에서 확정·변경된 점은 20장(M8 종료)에 있다.** 11장 질문 8개의 답을 반영했다: Q1 PowerShell 상주, Q2 평소 500ms·움직인 직후 1초는 100ms, Q3 보이는 구간만 발판, Q4 제외 앱은 실행 파일 이름, **Q5 아래로 나가면 위에서 나옴 — 추천 (a) 와 다름, 바닥 규칙은 "세게 던질 때만 한 번 통과"**, Q6 오르기만 높이 한도, Q7 확률은 캐릭터별(팩 behavior + characterBehavior)·켜기와 제외 앱은 전역, Q8 처음 상태 켜짐. 12장 잠정 채택은 승인할 때 함께 확인한다. 아래는 초안 때의 설명이다. M8 완료 기준 1(`docs/progress/milestones.md`)의 초안이다. 사전 결정 4개(D-051, `docs/progress/decisions.md`)는 바꾸지 않는다: ① 발판은 보이는 모든 창(제외 앱은 설정) ② 창은 지형으로만 쓰고 창 안의 내용·제목은 읽지 않는다 ③ 화면 끝 넘김은 모니터들을 합친 전체 화면 기준 ④ 새 동작이 팩에 없으면 기존 그림으로 대체(`fallbacks`)하고 새 그림은 아트로 병행한다. 결정은 사용자가 한다. 11장 질문 8개는 사용자가 답하기 전까지 결정이 아니고, 12장 "잠정 채택"은 사용자가 승인할 때 함께 확인한다.

표기: "후보"는 근거 없이 제안하는 값이다(코드에 이미 있는 값은 출처를 적는다). "실험 사실"은 이 초안을 쓰며 작은 실험으로 확인한 것이고(2절), "추측"은 확인하지 못한 것이다. 각 설계 항목의 `[기준 n]` 은 쓰이는 M8 완료 기준 번호다(6 발판 목록, 7 서기·낙하·따라가기, 8 걷다 만나는 낭떠러지·벽, 9 던지기·착지, 10 화면 끝 넘김, 11 애니메이션, 12 설정, 13 공존·위치 복원, 14 CPU).

## 1. 맥락

### 1-1. 지금 코드가 하는 일

- **펫 창 하나, 위치는 발(anchor) 기준.** 펫은 투명 창 하나(`petWindow`, `apps/desktop/src/main/index.ts`)다. 창 크기는 `windowSize()`(`cellSize × scale`), 발 위치는 `currentFoot()` = `footFromWindow(petWindow.getBounds(), currentOffset())`, `currentOffset()` 은 매니페스트 `anchor × scale` 이다(`apps/desktop/src/main/position.ts` 의 `footOffset`·`footFromWindow`·`windowFromFoot`). 보이는 캐릭터의 경계는 `characterPack.contentRect`(`character.ts` 의 `scaledContentRect`)이고 `currentContentRect()` 가 팩이 없을 때의 값(38,47,180×180)을 채운다. 모든 좌표는 Electron 의 DIP 이다.
- **모니터.** `displays()` 가 `screen.getAllDisplays()` 를 `{id, bounds, workArea, scaleFactor}` 로 줄인다(`DisplayArea`). `displayForPoint` 는 `workArea` 와의 거리가 가장 가까운 화면, `clampWindowToDisplay`·`clampWindowForMovement`(`position.ts`)는 보이는 캐릭터가 작업 영역 안에 있게 한다. 이웃 화면이 이어져 있으면(겹치는 변이 캐릭터 높이·너비 이상) 둘을 하나의 범위로 합쳐 경계를 넘어 걷게 한다. `placeFoot` 은 저장된 발 위치를 현재 화면 구성에 맞춘다.
- **이동 경로 하나.** 모든 창 이동은 `moveWindowTo` → `petWindow.setBounds({x, y, ...windowSize()})` + `correctWindowSize`(M2 의 배율 전환 버그 대응: 화면 배율이 다른 곳으로 옮기면 DIP 크기가 어긋나 크기를 다시 맞춘다)를 지난다. `moveWindowBy`(걷기)와 `moveDragCursor`(드래그)는 둘 다 `moveWindowWithScaleChange` 로 모이고, 화면이나 배율이 바뀌면 `pet:scale-changed` 를 보낸다. 새 이동은 이 경로를 우회하지 않는다.
- **걷기.** `CharacterAnimationMachine`(`packages/core/src/character-animation.ts`)이 `walk` 에 들어갈 때 방향과 속도(`movement`)를 정하고 `walkDurationMs` 가 지나면 `idle` 로 돌린다. 실제 창 이동은 `index.ts` 의 `tickAnimation` 이 한다: 50ms 간격 타이머(`startAnimationTimer`)가 `advanceClock` → `tickAnimation` 을 부르고, 한 번에 최대 250ms 만큼(`elapsed`)만 이동 거리 `speed × dt` 를 계산해 `moveWindowBy` 로 옮긴다. 화면 가장자리에서 못 가면(`after - before < pixels`) `walkDirection` 을 뒤집는다.
- **시계.** `clockMs` 는 보이는 동안만 실제 시간으로 흐르고(`advanceClock`) 개발 제어 `clock`(`pause`/`resume`/`advanceMs`)으로 멈추거나 당길 수 있다(`index.ts` 의 `request.cmd === "clock"`). `advanceMs` 는 `tickAnimation` 을 한 번만 부르므로 큰 값을 한 번에 주면 `elapsed` 상한 250ms 때문에 이동은 250ms 분만 간다.
- **드래그.** `startDrag(cursor, injected)` 가 시퀀스를 끊고(`stopSequence(true)`) `machine.startDrag`, 16ms 타이머로 `screen.getCursorScreenPoint()` 를 읽어 `moveDragCursor` 한다(개발 제어는 `injected` 로 커서를 직접 줌). `stopDrag` → `machine.endDrag` → `fitCurrentPosition` → `savePosition`. 놓는 순간의 속도는 어디에도 기록되지 않는다.
- **위치 저장.** `savePosition()` 이 `{foot, display:{id, bounds}}` 를 `userData/pet-position.json` 에 임시 파일 + `rename` 으로 쓴다(`SavedPosition`). 복원은 `placeFoot(savedPosition?.foot ?? defaultFoot, ...)`(`index.ts` 850행대). 걷기가 끝날 때와 걷는 중 2초 이상 지났을 때 저장한다.
- **말풍선.** `bubbleAnchor()` 가 `{content, foot, displays}` 를 돌려주고 `moveWindowTo` 가 `bubbleWindow?.refresh()` 를 부른다. 그래서 펫 창이 `moveWindowTo` 로 움직이면 말풍선은 이미 따라간다(`bubble-position.ts` 의 `placeBubble`).
- **전체 화면 감지.** `FullscreenWatcher`(`apps/desktop/src/main/fullscreen-watcher.ts`)는 `powershell.exe -NoProfile -NonInteractive -EncodedCommand` 상주 프로세스 하나에서 `SHQueryUserNotificationState` 를 2초마다 읽고 **바뀔 때만** stdout 한 줄을 쓴다. 실패하면 한 번 다시 띄우고(`MAX_RESTARTS = 1`) 두 번째 죽음이면 `false`(안전한 값)로 두고 가만히 있는다. 자식 프로세스 표면(`PowerShellChild`)과 타이머(`FullscreenWatcherHost`)를 주입해 단위 테스트한다. 개발 제어 `setFullscreenForTest` 와 `DesktopApp.launch` 가 e2e 에서 값을 고정한다(`apps/desktop/e2e/desktop-app.ts`, AGENTS.md "e2e 는 PC 환경 입력을 고정").
- **설정.** `DeskpetSettings`(`apps/desktop/src/main/settings.ts`)에 `doNotDisturb`·`characterId`·`characterBehavior`·`developerMode` 등. 설정 창 탭은 [일반]·[캐릭터]·[알림]·[플러그인]이고 [캐릭터] 아래 하위 탭에 [행동]이 있다(`apps/desktop/src/renderer/settings.html`). 행동 수치는 `packages/core/src/behavior.ts` 의 `BEHAVIOR_RANGES`·`DEFAULT_BEHAVIOR`·`resolveBehavior`(코드 기본 < 팩 `behavior` < 사용자 `characterBehavior`)가 해석한다(ADR-0008 4장·13장).
- **발 위치 검사.** `pnpm sprites:check` 와 앱이 같은 `inspectSpriteFootFrame`(`packages/core/src/sprite-foot-check.ts`)을 쓴다. 상태·프레임마다 발 y 와 발 x 중심이 `anchor` 에서 허용 오차 이내인지 본다(ADR-0008 7-6).

### 1-2. 문제

1. 펫은 발 밑이 언제나 "화면 작업 영역의 같은 높이"다. 위치는 드래그로만 바뀌고, 놓으면 그 자리에 머문다. 다른 창은 지형이 아니다.
2. 다른 창의 위치를 읽는 코드가 없고, Electron 에도 그 기능이 없다(2절).
3. 걷기는 좌우뿐이고 중력·낙하·착지·던지기가 없다. 화면 끝은 막힌 벽이다.

## 2. 목표와 비목표

### 목표

- 앱이 보이는 창들의 윗변을 발판으로 알고(기준 6), 공중의 펫이 떨어져 가장 가까운 발판에 서며(7), 걷다 끝을 만나면 확률로 내려가거나 올라간다(8). 놓은 속도로 날아가 착지하고(9), 전체 화면 끝을 넘으면 반대쪽에서 나온다(10).
- 새 동작은 선택 필드만 팩에 더한다(`apiVersion` `"1"` 유지, 11). 기능 전체를 끄면 M7 동작 그대로다(12).
- 다른 창에서 읽는 것은 위치·크기·보임 여부와 (제외 앱 판정용) 실행 파일 이름뿐이고, 제목·내용·경로는 읽거나 남기지 않는다. 조회가 실패하면 이 기능만 꺼지고 앱은 산다.

### 비목표

- 창 안의 내용·제목에 반응하기, 창 옆면에 매달리기, 창 위의 창 안(여러 창에 걸친 물체) 상호작용, 창을 밀거나 움직이기. 펫이 다른 창을 조작하지 않는다(읽기 전용).
- macOS·Linux(`process.platform !== "win32"` 면 기능이 없고 M7 동작).
- 보조 펫, 사운드, wolf-maid 의 새 동작 그림(아트로 병행, 완료 기준 아님).
- `packages/plugin-sdk/src/v1/` 와 `PetEvent` 변경. 이 ADR 의 어떤 결정도 그곳을 바꾸지 않는다.
- 펫이 창 안쪽으로 걸어 들어가거나 창 뒤로 숨는 동작(펫 창은 항상 위, `setAlwaysOnTop(true, "screen-saver")`).

## 4. 다른 창의 위치 읽기 [기준 6, 14]

### 4-1. 방식 비교

Windows 에서 다른 최상위 창의 위치는 `EnumWindows`(z 순서 위→아래로 순회) + `GetWindowRect`/`DwmGetWindowAttribute(DWMWA_EXTENDED_FRAME_BOUNDS=9)`(보이는 경계; `GetWindowRect` 는 Win10/11 에서 투명한 크기 조절 테두리를 포함한다고 알려져 있다)와 `IsWindowVisible`·`IsIconic`·`DwmGetWindowAttribute(DWMWA_CLOAKED=14)` 로 읽는다.

| 방법 | `fullscreen-watcher.ts` 와 같은 구조: `Add-Type` 으로 user32/dwmapi 호출 스텁을 컴파일하고 루프에서 조회, 바뀔 때만 stdout 한 줄 | 의존성(`koffi` 등)을 main 에 추가해 같은 Win32 함수를 앱 프로세스 안에서 호출 | `screen`(모니터만), `BrowserWindow`(자기 창만), `desktopCapturer.getSources({types:['window']})`(창 이름·썸네일, 위치 없음), `app.getAppMetrics`(프로세스) |

**실험(PowerShell 5.1, 이 PC, 파일은 커밋하지 않음).**

- 사실: `Add-Type` 으로 `EnumWindows`·`IsWindowVisible`·`IsIconic`·`GetWindowLong`·`DwmGetWindowAttribute`(cloaked, extended frame)를 부르는 스텁을 컴파일하는 데 약 419ms, 이후 1회 전체 순회+필터 평균 0.225ms(200회 평균). 필터 통과 창은 이 PC 에서 2개뿐이라 창이 수십 개일 때의 값은 **미측정**이다(순회 비용은 창 수에 비례할 것이라는 추측).
- 사실: 같은 프로세스에서 순회를 100ms 주기로 6초 돌리자 프로세스 CPU 시간 109ms(약 1.8% 코어), 500ms 주기에서는 16ms(약 0.27% 코어). 순회 없이 `Start-Sleep -Milliseconds 100` 만 돌린 빈 루프도 94ms 라 100ms 주기의 비용 대부분은 PowerShell 루프 자체다. 주기를 늘릴수록 비용이 크게 준다는 것만 확인했고 정확한 수치는 기기에 따라 다르다.
- 사실: `powershell.exe` 의 기본 DPI 인식은 **0(인식 안 함)** 이다. 스크립트에서 `SetThreadDpiAwarenessContext(-4)`(per-monitor V2)를 부르면 2(per-monitor)로 바뀐다. 이 PC 는 `GetSystemMetrics(SM_CXSCREEN)` 이 두 경우 모두 2560 이라 배율 100%로 보이며, **배율이 다른 모니터에서 좌표가 실제로 가상화되는지는 이 PC 에서 확인하지 못했다**(추측: 인식 안 함이면 125%·150% 모니터에서 좌표가 줄어든다). 그래서 스크립트가 시작할 때 인식을 켜는 것을 설계에 포함한다(6장).
- 미실험: 보안 프로그램 영향, 창이 많을 때의 비용, 창 드래그 중 `DwmGetWindowAttribute` 반환 시점의 지연, Electron 44.5.1(`package.json`)의 `screen.screenToDipRect` 정밀도.

**결론(질문 Q1).** (a)를 추천한다. 추가 의존성이 없고 이미 같은 방식이 운영 중이며 실패해도 기능만 꺼진다. (b)는 CPU 가 더 작고 지연이 짧을 수 있지만 네이티브 모듈 패키징과 앱 크래시 위험을 앱에 들이고, M8 은 설치 파일이 범위 밖이라 그 이점이 지금은 쓰이지 않는다. (c)는 불가능하거나 사전 결정에 어긋난다. 조회 코드는 `TerrainSource` 같은 작은 인터페이스(`start`/`stop`/`onSnapshot`) 뒤에 두어 나중에 (b)로 바꿔도 이동 로직은 그대로다.

### 4-2. 구성: 스크립트는 읽기만, 계산은 main

- **스크립트(`apps/desktop/src/main/terrain-watcher.ts`, 후보 이름)** 는 `FULLSCREEN_WATCHER_SCRIPT` 와 같은 모양의 문자열 상수다. 책임은 하나: 창 목록을 z 순서대로 훑어 **필터를 통과한 창**의 `{id, x, y, w, h}` 만 stdout 에 JSON 한 줄로 쓴다. 이전 결과와 같으면 쓰지 않는다(변화 감지). `id` 는 이번 실행 동안의 불투명한 창 식별자(HWND 숫자)이고 서 있던 창을 따라가는 데만 쓴다(7-4). 디스크·로그에 남기지 않는다.
- **main 의 순수 함수(`packages/core/src/terrain.ts`, 후보 이름)** 가 스냅샷에서 발판 목록(가려진 구간 제거, 최소 폭, 머리 위 공간 검사)을 계산한다. 시계·파일·Electron 이 없어 단위 테스트가 쉽다. 주입된 가짜 스냅샷으로 e2e 도 같은 함수를 지난다(14장).
- **자식 프로세스 표면.** `PowerShellChild`·`SpawnPowerShell`·`FullscreenWatcherHost`(`fullscreen-watcher.ts`)를 그대로 쓰거나 공용 파일로 옮겨 재사용한다. 재시작 한 번, 두 번째 죽음이면 불활성이라는 정책도 같다.
- **인자.** 스크립트는 시작할 때 ① 앱의 프로세스 id(자기 창 제외용) ② 제외 앱의 실행 파일 이름 목록을 받는다(15장). 제외 목록이 바뀌면 스크립트를 다시 띄운다(약 0.4s 컴파일, 설정 변경은 드물다).

### 4-3. 갱신 주기 (후보, 질문 Q2)

| 상황 | 후보 주기 | 근거 |
|---|---|---|
| 대기 | 500ms | 실험의 500ms 루프가 약 0.27% 코어. 새 창이 열리거나 사용자가 창을 옮겨도 사람이 알아채는 지연은 반 초 안팎 |
| 변화가 보인 직후 | 100ms, 마지막 변화 뒤 1초 동안 | 창 드래그 중 펫이 창 위에 붙어 따라가야 한다(기준 7). 100ms 는 실험상 약 1.8% 코어지만 변화가 있는 동안에만 쓴다 |
| 숨김·전체 화면 보류·기능 꺼짐 | 조회 없음(스크립트 정지) | CPU 목표 1% 미만(plan.md 대기 상태 CPU). 숨김은 창이 안 보이는 동안 발판이 필요 없다 |

주기 전환은 스크립트 안에서 스스로 한다(변화 감지 카운터). main 이 stdin 으로 지시하는 방식은 PowerShell 의 비동기 stdin 처리가 복잡해 택하지 않는다. 100ms 구간에서 펫 창이 따라가는 지연은 "창 이동 → 최대 100ms 뒤 스냅샷 → 펫 이동"이라 눈에 띌 수 있다. 서 있는 동안은 main 이 다음 스냅샷 사이에 마지막 창 이동 속도로 예측하지 않고(복잡도), 값이 오면 그 위치로 간다. 실제 체감은 H 기준이다(백로그: 사용자가 쓰다가 보고).

## 5. 발판 규칙 [기준 6]

### 5-1. 창을 거르는 규칙(스크립트에서)

스크립트가 아래를 모두 통과한 창만 보고한다. 하나라도 걸리면 보고하지 않는다(발판도 가림도 아님). 8번만 예외로, 발판에서만 빠지고 가림으로는 남는다(5-2).

| # | 규칙 | 이유 |
|---|---|---|
| 1 | `IsWindowVisible` 거짓이면 제외 | 숨은 창 |
| 2 | `IsIconic`(최소화)이면 제외 | 기준 6 |
| 3 | `DWMWA_CLOAKED != 0` 이면 제외 | 가상 데스크톱에 있는 다른 창·UWP 유령 창이 보이는 창으로 잡히는 것을 막는다 |
| 4 | `WS_EX_TOOLWINDOW`(도구 창) 제외 | 팔레트·툴팁류 |
| 5 | `WS_EX_TRANSPARENT`(클릭 통과) 제외 | 오버레이. 누를 수 없는 투명 창 위에 서면 사용자가 이상하게 본다 |
| 6 | 완전 투명 `WS_EX_LAYERED`(알파 0) 제외 후보 | 보이지 않는 창. 구현 때 `GetLayeredWindowAttributes` 로 확인할 수 있는지 확인하고, 안 되면 규칙 없이 간다 |
| 7 | 앱 자신의 창(펫·말풍선·설정·확인 창 등) 제외 | 앱 프로세스 id 와 같은 `GetWindowThreadProcessId` 면 제외. 같은 앱의 모든 최상위 창이 한 프로세스에 속한다(**추측**, 구현 때 확인) |
| 8 | 제외 앱 설정에 든 실행 파일이면 **발판에서만** 제외(가림은 유지) | 5-2 |
| 9 | 크기가 0이거나 확장 프레임 경계를 못 얻으면 제외 | 방어 |

화면 전체를 덮는 창(전체 화면, 바탕화면 창 `Progman`/`WorkerW`)과 작업 표시줄은 클래스·제목을 읽지 않고 **크기와 위치**로 거른다(5-3). 그래서 창 클래스도 읽지 않는다.

### 5-2. 가림과 발판 구간(main 순수 함수에서)

- 스크립트는 z 순서(위→아래)를 유지한 채 목록을 준다. 각 항목에는 "발판 후보인가(제외 앱이 아닌가)" 표시 하나가 붙는다. 제외 앱의 창은 **발판은 아니지만 아래 창을 가리는** 창으로 남는다. 이유: 제외했는데 그 뒤에 가려진 창의 윗변이 갑자기 발판이 되어 펫이 보이지 않는 곳으로 가면 이상하다.
- 한 창의 윗변 y 에서 구간 `[x, x+w)` 를 만들고, **그 창보다 z 순서가 위에 있는** 모든 창(제외 앱 포함, 5-1 필터를 통과한 것) 가운데 `top ≤ y < bottom` 인 창이 덮는 x 구간을 뺀다. 남은 구간이 "보이는 윗변"이고 이것만 발판이다(`[기준 6]` 요청: 가려진 구간은 발판이 아님).
- 남은 구간 중 폭이 최소 폭 미만이면 버린다. 후보: `max(48 DIP, 캐릭터 보이는 너비의 1/2)`. 너무 좁은 틈에 펫이 서면 눈에 띄게 어색하다. 값은 써 보고 조정(H 기준).
- **머리 위 공간.** 발판 y 위로 캐릭터의 보이는 높이(`contentRect.height`)가 들어갈 공간이 같은 화면 작업 영역 안에 있어야 한다. 최대화된 창의 윗변은 작업 영역의 맨 위라 공간이 없어 자연히 발판이 아니다.
- 창은 서로 겹치므로 같은 x 에 발판 여러 개가 있을 수 있다. 낙하 중 착지는 위에서 아래로 처음 지나치는 발판이다(7-3).
- 가림 계산은 창 수 N 에 대해 O(N²)이고 N 은 수십 개다. 스냅샷이 바뀔 때만 계산한다.

### 5-3. 작업 표시줄과 화면 바닥, 전체 화면 창

- 작업 표시줄은 별도 발판으로 다루지 않는다. `screen.getAllDisplays()` 의 `workArea` 가 이미 작업 표시줄을 뺀 영역이라 **화면 바닥 = 그 화면 `workArea` 의 아래 변**이고 사실상 작업 표시줄 윗면이다. 작업 표시줄이 위·옆에 있어도 `workArea` 가 그것을 반영한다. 작업 표시줄 창이 스냅샷에 오더라도 윗변이 바닥과 같은 높이라 겹치는 발판이 하나 더 생길 뿐이다. 자동 숨김 작업 표시줄은 `workArea` 가 화면 전체라 바닥이 화면 끝이다.
- **화면 바닥 발판의 범위.** 화면 한 대의 `workArea` 아래 변은 그 화면의 x 범위 전체에 걸친 발판이다. 위아래로 이웃한 모니터가 있으면 그 x 열 안에서 가장 아래 `workArea` 의 바닥이 "바닥"이다(8-2).
- **전체 화면 창.** 창 경계가 어떤 화면의 `bounds` 와 같거나(±1 DIP) 그보다 크면 발판에서 제외한다. 가림으로는 남는다(전체 화면 위에 다른 창은 안 보이므로 아래 창들의 윗변은 구간이 비어 발판 없음). `QUNS_*` 전체 화면 보류 상태(13장)와는 별개의 판단이다.

### 5-4. 읽는 것과 읽지 않는 것

| 읽음 | 읽지 않음 |
|---|---|
| 창 핸들(이번 실행 동안만 쓰는 id) | 창 제목(`GetWindowText`) |
| 확장 프레임 경계(위치·크기) | 창 클래스 이름 |
| 보임·최소화·cloaked·확장 스타일 비트 | 프로세스 경로 전체(전체 경로를 `QueryFullProcessImageName` 으로 얻더라도 스크립트 안에서 파일 이름만 남기고 버림) |
| 소속 프로세스 id(자기 창 판정) | 창 안의 내용, 화면 캡처, 입력 |
| 제외 앱 설정이 비어 있지 않을 때에 한해 실행 파일 이름(스크립트 안에서만 비교, stdout 으로 내보내지 않음) | |

제외 앱 설정에 필요한 최소 식별자는 **실행 파일 이름(경로 없음, 대소문자 무시)** 이다(Q4). 목록 입력은 설정 창이 "실행 중인 앱에서 고르기"를 하려면 이름을 보여 줘야 하는데 이 때문에 창 제목이 필요해 보일 수 있다. 고르기 목록은 **실행 파일 이름만** 보이고 제목은 보이지 않는다(15장).

**로그에 남기지 않는 것.** 창 위치·크기, 창 id, 실행 파일 이름, 창 수의 변화 기록. 로그에는 기능이 켜졌다/꺼졌다, 조회 프로세스가 시작/종료/재시작/포기했다 같은 생명 주기와 오류 종류만 남긴다. `console.error` 로 스냅샷을 찍지 않는다. 개발 제어(`state` 응답)는 테스트용으로 발판 목록을 돌려줄 수 있으나(14장) 개발 제어는 `--dev-control` 을 준 개발 실행에서만 열린다(`index.ts`).

## 6. 좌표계 [기준 6, 7, 10]

- **스크립트 좌표는 물리 픽셀.** 스크립트는 시작할 때 `SetThreadDpiAwarenessContext(DPI_AWARENESS_CONTEXT_PER_MONITOR_AWARE_V2 = -4)` 를 불러 가상화되지 않은 좌표를 받는다(4-1: 기본은 인식 안 함이라 필요). 이 호출이 PowerShell 5.1 의 모든 환경에서 같게 동작하는지는 실험 전이다(**추측**).
- **main 에서 DIP 로 바꾼다.** Electron 의 Windows 전용 `screen.screenToDipPoint`/`screenToDipRect`(문서 기준, 44.5.1 에서 정밀도 **미확인**)로 창 경계를 DIP 로 바꾼다. 같은 변환을 펫 창에도 쓰므로(`getBounds()` 는 DIP) 지형과 펫이 한 좌표계에서 만난다. 화면마다 배율이 달라 한 창이 두 모니터에 걸쳐 있으면 변환 결과가 두 화면 중 하나의 기준이다. 걸친 창의 윗변은 걸친 부분에서 약간 어긋날 수 있다(위험).
- **정수 반올림.** 지형은 DIP 실수를 `Math.round` 로 정수화해 `setBounds` 정수 요구(`moveWindowTo` 가 `{x, y, ...windowSize()}`)와 맞춘다. 다른 배율로 넘어갈 때 `correctWindowSize` 가 크기를 맞추는 기존 경로를 쓴다. 지형 이동이 이 경로를 우회하지 않는다(1-1).
- **서는 기준은 발.** 펫의 서 있는 위치 = `currentFoot()`(= window + `anchor × scale`). 발판 높이 `platformY` 에 서려면 `foot.y == platformY`, 즉 `window.y = platformY - offset.y`. 발 위치 검사(`inspectSpriteFootFrame`)가 이미 모든 프레임의 발이 `anchor` 에 있도록 보장하므로 상태가 바뀌어도 발이 떨리지 않는다.
- **보이는 경계는 가로 판정과 머리 위 공간에만 쓴다.** 발판 구간에 서 있는지는 `foot.x` 가 구간 안에 있는지로 본다(보이는 몸의 가장자리가 구간 밖으로 반쯤 나가도 서 있는다 — 화면 가장자리의 `clampWindowForMovement` 가 보이는 경계를 화면 안에 두는 것과 다르다). 머리 위 공간과 오르기 벽 판정은 `currentContentRect()` 의 높이를 쓴다. "발 기준 서기, 보이는 몸 기준 충돌"이다.
- **화면 배율이 다른 모니터 사이의 이동.** 발이 다른 모니터의 작업 영역으로 넘어가면 `moveWindowWithScaleChange` 가 `pet:scale-changed` 를 보낸다. 지형 계산은 DIP 에서 한 번에 하고, 배율 전환은 기존 경로에만 맡긴다. 낙하·던지기 중에도 매 이동이 `moveWindowTo` 를 지난다.
- **모니터 구성이 바뀔 때.** `screen.on("display-added"|"display-removed"|"display-metrics-changed")`(`index.ts`)의 `handleDisplayChange` 가 기존 `fitCurrentPosition` 을 부른다. 그 뒤 지형 스냅샷도 다시 변환한다(변환 기준이 바뀌었으므로 다음 스냅샷을 즉시 요청).

## 7. 이동 모델 [기준 7, 8, 9]

### 7-1. 상태

이동 상태는 **애니메이션 머신(`CharacterAnimationMachine`)과 별개의 순수 상태 기계**(`packages/core/src/movement.ts`, 후보 이름 `PetMovement`)가 가진다. 머신은 "어떤 그림을 재생하나"를, `PetMovement` 는 "발이 어디에 있고 어떻게 움직이나"를 책임진다. `PetMovement` 가 머신에 `request(state)` 로 재생할 상태 이름을 알린다(9장 이름). 기능이 꺼져 있으면 `PetMovement` 는 만들지 않고 기존 `tickAnimation` 걷기 코드 경로 그대로다(기준 12).

| 이동 상태 | 뜻 | 재생 요청 이름 |
|---|---|---|
| `grounded` | 발판 또는 바닥에 서 있음(서 있음·걷기는 머신의 `idle`/`walk`/`blink`/`sleep` 이 담당) | (머신 자동) |
| `climb-ready` | 오르기 전 짧은 준비(웅크림). 길이 후보 400ms | `climb-ready` |
| `climbing` | 목표 발판 높이로 올라가는 중 | `climb` |
| `descending` | 낭떠러지에서 아래 발판으로 내려가는 중 | `descend` |
| `falling` | 공중에서 중력으로 떨어지는 중 | `fall` |
| `landing` | 착지 직후 짧은 시간(후보 300ms) | `land` |
| `thrown` | 놓을 때 속도가 있어 날아가는 중(속도에 위로 성분이 있거나 수평 속도가 큼). 정점을 지나 아래로 향하면 `falling` | `thrown` |
| `dragging` | 사용자가 잡고 있음 | `drag`(기존) |

### 7-2. 전이

| 지금 → 사건 | 다음 |
|---|---|
| (모든 상태) 사용자가 잡음(`startDrag`) | `dragging`. 시퀀스·반응은 기존대로 끊김(ADR-0008 6-6) |
| `dragging` → 놓음, 놓을 때 속도 ≈ 0 이고 발이 발판 위(오차 ±2 DIP) | `grounded`(제자리에 섬) |
| `dragging` → 놓음, 발이 발판 위 아님 또는 속도 있음 | 속도 있으면 `thrown`, 없으면 `falling` |
| `thrown` → 속도의 y 성분이 아래로 향함 | `falling` |
| `falling`/`thrown` → 발이 발판 윗변을 위에서 아래로 지남(7-3) | `landing` (후보 300ms) → `grounded` |
| `falling` → 화면 끝 넘김(8장) | 같은 상태, 속도 유지 |
| `grounded` + 걷기(머신 `walk`) + 발이 발판 끝을 벗어남 | 확률 판정(7-5): 내려가기(`descending`) 또는 돌아섬 |
| `grounded` + 걷기 + 앞을 막는 벽(7-5) | 확률 판정: 오르기(`climb-ready` → `climbing`) 또는 돌아섬 |
| `climb-ready` → 시간 경과 | `climbing` |
| `climbing` → 목표 발판 높이에 도달 | `grounded`(`land` 없이 바로) |
| `descending` → 목표 발판(또는 바닥) 도달 | `landing` → `grounded` |
| `grounded` + 서 있던 발판이 사라짐(창이 닫힘·최소화·가려져 구간이 없어짐) | `falling` |
| `grounded` + 서 있던 창이 움직임 | 같은 창을 따라감(7-4) |
| 펫 숨김(`hidePet`) | 상태 유지, 시계 정지. 다시 보이면 이어감(13장) |

머신의 자동 행동(깜빡임·걷기 시작·잠들기)은 `grounded` 일 때만 일어난다. 다른 이동 상태에서는 `request` 가 와도(말풍선 `talk` 등) 이동 상태가 이길지 재생 상태가 이길지 정해야 한다. 잠정: **공중(`falling`/`thrown`)과 오르내리기 동안은 이동 그림이 이긴다**(`talk`·반응 재생은 착지 뒤로 미룸). 단, 알림 말풍선은 그대로 뜬다(말풍선 표시는 그림과 별개). 13장.

### 7-3. 물리 (후보 수치, H 기준으로 조정)

모든 값은 DIP·초 단위이고 후보다. 코드 상수 한 곳에 모으고 `characterBehavior` 처럼 사용자가 바꾸게 하지 않는다(12장 잠정).

| 값 | 후보 | 비고 |
|---|---|---|
| 중력 | 2,000 DIP/s² | 발 높이 200 DIP 낙하 약 0.45초 |
| 종단 속도 | 1,800 DIP/s | 아래 방향 속도 상한 |
| 던지기 최대 속도 | 2,200 DIP/s(벡터 크기) | 이상값 방어 |
| 던지기 속도 측정 | 놓기 직전 표본 100ms 창 | 드래그 중 매 이동(`moveDragCursor`, 16ms)에서 `(clockMs, 발 위치)` 를 링 버퍼(후보 8개)에 기록. 놓을 때 100ms 이내 표본의 처음과 끝 차이 / 시간. 표본이 2개 미만이면 속도 0 |
| 속도 무시 문턱 | 80 DIP/s | 이하이면 가만히 놓은 것으로 취급(기준 9: 가만히 놓으면 그 자리에서 떨어짐) |
| 낙하 갱신 주기 | 16ms 타이머(공중에서만) | 현재 `startAnimationTimer` 는 50ms 라 최대 낙하 속도에서 한 틱 90 DIP 를 건너뛰어 눈에 띄게 끊김. 공중·오르내리기 동안만 16ms 로 올리고 땅에 서면 50ms 로 돌림(CPU 비용은 14장) |
| 시간 단위 | `clockMs` | 기존 개발 제어 `clock.advanceMs`(`index.ts`)로 당길 수 있어야 하므로 실제 시간 대신 `clockMs` 를 쓴다(14장). 단 `advanceMs` 가 한 번에 큰 값을 주면 `tickAnimation` 이 `elapsed` 를 250ms 로 제한하는 기존 동작 때문에 이동이 모자란다. 이동은 `clockMs` 차이를 고정 시간 간격(후보 16ms) 단위로 나눠 적분하는 `PetMovement.advance(untilMs)` 로 하고 250ms 제한을 적용하지 않는다 |

- **적분.** 고정 간격 `dt` 마다 `v.y = min(v.y + g·dt, terminal)`, `foot += v·dt`. 수평 속도는 공기 저항 없이 유지하되 착지·벽 충돌에서 0으로 만든다(잠정; 튕김 없음).
- **착지 판정은 "지나가는지"로 본다.** 한 틱에서 `prevFoot.y ≤ platformY < nextFoot.y`(위에서 아래로 지남)이고 `foot.x` 가 그 발판의 보이는 구간 안일 때만 착지한다. 위로 올라가는 중이나 이미 아래에 있을 때는 지나치지 않는다(발판을 아래서 통과 가능). 같은 틱에서 여러 발판을 지나면 가장 위의 것(y 가 가장 작은 것)이 이긴다. 한 틱 이동량이 발판 사이 간격보다 커도 놓치지 않도록 구간 교차로 검사한다(터널링 방지).
- **착지 y.** `window.y = platformY - offset.y`. 이후 한 번 `moveWindowTo` 로 확정한다.
- **화면 바닥 착지.** 모든 발판을 놓치면 해당 x 열의 바닥(5-3)에 착지한다. 단 세게 아래로 던진 비행은 바닥을 한 번 통과한다(8-2, D-052).

### 7-4. 서 있는 동안 창이 움직이면

**D-055 로 변경(2026-10-10):** 서 있던 창의 위치가 2 DIP 이상 바뀌면 따라가지 않고 그 자리에서 `falling` 으로 떨어진다. 크기만 바뀌고 발이 보이는 윗변 구간 위에 남으면 그대로 선다. 아래 원래 설명은 기록으로 남긴다.


- 착지하면 `PetMovement` 가 그 발판의 창 id 와, 발이 창 윗변에서 떨어진 상대 위치(`foot.x - window.left`)를 기억한다.
- 새 스냅샷이 오면 같은 id 의 창을 찾고 이동량만큼 펫을 같은 상대 위치에 옮긴다(`moveWindowTo`, 부드러운 보간 없이 즉시). 창이 매우 빨리 움직이면 100ms 마다 계단식으로 보인다(4-3).
- 창 크기가 바뀌거나 가려지는 구간이 변해 발 위치가 보이는 구간 밖이 되면 `falling`. 상대 위치가 구간 안이면 계속 선다.
- id 가 스냅샷에서 사라지면(닫힘·최소화·cloaked) `falling`. 같은 창이 다른 화면으로 옮겨져도 id 가 같으면 따라간다.
- **같은 창의 윗변이 아래로 내려가는 쪽으로 움직이면** 펫이 창 안에 파묻히지 않도록 같은 방식으로 따라 내려간다(발이 윗변에 붙음). 창이 위로 올라가 머리 위 공간이 없어지면 `falling` 이 아니라 그대로 윗변에 붙어 있는다(펫이 화면 밖으로 밀려나면 `clampWindowForMovement` 가 작업 영역 안으로 당긴다).

### 7-5. 걷기 중 낭떠러지와 벽 (기준 8)

걷기 한 틱마다(`tickAnimation`) 이동 후 다음을 본다. 확률은 사용자 설정 `climbChance`·`descendChance`(10장, 둘 다 0–1)다. **설정이 0이면 해당 동작을 절대 하지 않는다**(기준 8).

- **낭떠러지.** 걷는 방향으로 한 걸음(보이는 구간 끝) 뒤 `foot.x` 가 현재 발판 구간을 벗어난다 → 한 번만 확률 판정(`random() < descendChance`): 참이면 `descending`, 거짓이면 반대로 돌아선다(`walkDirection` 뒤집기). 판정은 같은 낭떠러지 앞에서 한 걷기당 한 번만 한다(반복 판정으로 확률이 올라가는 것 방지).
- **내려가기 경로(`descending`).** 낭떠러지에서 걷는 방향으로 수평 거리 `descendDx`(후보 펫 보이는 너비의 0.5)만큼 가며 아래로 `descend` 그림을 재생하며 이동한 뒤, 거기서 `falling` 처럼 떨어져 아래 발판에 착지한다. 높이 한도(Q6 (a)): 내려가기에는 낙차 한도가 없다. `descend` 그림 안에서 이동하는 높이는 최대 펫 보이는 높이까지이고 나머지 낙차는 자유 낙하로 간다. 아래에 발판이 없으면 화면 바닥까지.
- **벽(앞을 막는 창).** 걷는 방향 앞에 다른 발판(이 발판보다 높은 윗변)이 있어 `foot.x` 가 그 발판의 수평 범위에 닿고(그 발판의 `left` 또는 `right` 변이 한 걸음 안) 그 윗변이 현재 발판보다 높다면 "벽". 높이 차 `h = currentY - wallTopY`.
  - `h ≤ maxClimbHeight`(후보: **캐릭터 보이는 높이 × 1.0**)이면 확률 판정(`random() < climbChance`): 참이면 `climb-ready` → `climbing`, 거짓이면 돌아섬.
  - `h > maxClimbHeight` 이면 오르지 않고 돌아선다(Q6 (a)).
- **오르기 경로(`climbing`).** 벽의 윗변 위로 `climb` 그림을 재생하며 수직으로 `h` 만큼 올라간 뒤 수평으로 한 걸음 더 가서 윗변 위에 선다(`grounded`). 올라가는 중 벽 창이 움직이거나 사라지면 `falling`. 속도는 후보 120 DIP/s(수직). 속도·이동 길이는 그림의 프레임 수·fps 와 맞아야 하므로(9장) 구현 때 `climb` 상태의 한 주기와 이동 시간을 일치시키는 방식과 고정 속도 방식을 고른다(**남은 구현 결정**).
- **내려가기·오르기가 가능한 방향의 조건.** 목표 발판에 발이 설 만큼 보이는 구간이 있어야 한다(5-2 최소 폭).
- **같은 화면 끝.** 걷다 화면 끝에 닿으면 기존처럼 돌아선다(`walkDirection` 뒤집기). 던져졌을 때만 넘김(8장).

### 7-6. 시계

이동 갱신은 모두 `clockMs` 를 쓰고(`Date.now()` 를 이동 계산에 쓰지 않는다. 현재 `savePosition` 의 재시도 지연이 `Date.now()` 를 쓰는 것은 파일 쓰기 간격이라 별개다), `PetMovement.advance(untilMs)` 는 내부 고정 간격 적분이다. 지형 스냅샷의 도착은 실제 시간(자식 프로세스)이지만 시계를 당기는 e2e 에서는 가짜 지형을 쓰므로(14장) 서로 간섭하지 않는다.

## 8. 화면 끝 넘김 [기준 10]

기준은 **모든 모니터 경계(`display.bounds`)의 합(합집합) 의 바깥 상자(bounding box)** 가 아니라 **합집합 자체의 가장자리**다. 가장자리를 넘는다는 것은 이동 중 발이 합집합 밖으로 나가는 순간을 뜻한다.

### 8-1. 언제 넘기나

넘김은 **던져진(`thrown`)/낙하(`falling`) 상태**에서만 일어난다. 걷기는 기존처럼 화면 끝에서 돌아선다(7-5). 드래그 중에는 넘김이 없다(손으로 끌어다 놓는 것이므로 클램프). 이유: 걷다가 갑자기 반대편에 나타나면 놀랍고, 기준 10 은 "넘기면"(던진 결과)을 말한다.

### 8-2. 규칙

| 사건 | 규칙 |
|---|---|
| 왼쪽/오른쪽으로 합집합 밖으로 나감 | 반대쪽 끝 화면에서 나온다. 나올 y 는 나가는 순간의 발 y 를 유지하되, 반대쪽 끝 x 열 위의 모니터 중 그 y 를 포함하는 `workArea` 가 있으면 거기, 없으면(모니터 배치가 어긋남) 가장 가까운 화면의 작업 영역 안으로 y 를 맞춘다(`displayForPoint` 와 `clampWindowToDisplay` 규칙 재사용) |
| 위로 나감 | 아래 가장자리(그 x 열 합집합의 맨 아래 `workArea` 바닥 위)에서 나와 계속 떨어진다 |
| 아래로 나감 | **결정(D-052, Q5 (b) + 바닥 규칙): 세게 던졌을 때만 바닥을 통과해 위에서 나온다.** 평소에는 화면 바닥이 발판이다(걷기, 낙하 착지, 가만히 놓았을 때). 던져진 상태에서 바닥에 닿는 순간의 아래 방향 속도가 바닥 통과 문턱(후보 1,500 DIP/s) 이상이면 바닥에 착지하지 않고 통과해, 그 x 열 합집합의 맨 위에서 속도를 유지한 채 나와 다시 떨어진다. **한 번의 던지기에서 바닥 통과는 한 번만**이다: 통과한 뒤에는 바닥이 다시 발판이라 다음에 닿으면 착지한다(무한 반복 없음). 창 윗변 발판은 통과 대상이 아니다(위에서 아래로 지나면 속도와 관계없이 착지, 7-3). 종단 속도(1,800 DIP/s) 때문에 높은 곳에서 그냥 떨어지기만 해도 문턱을 넘을 수 있으므로, 통과 조건에 "던져서 시작한 비행(`thrown`)이고 놓을 때 아래 방향 속도 성분이 양수"를 함께 둔다(가만히 놓거나 발판이 사라져 떨어진 낙하는 통과하지 않는다) |
| 합집합의 빈 영역(모니터 배치가 어긋나 생긴 틈) 안으로 들어감 | 가장 가까운 화면의 작업 영역 안으로 넣는다. 그 위치로 "나오는 것"과 같다 |
| 속도 | 넘김 직후에도 속도(방향·크기)를 유지한다. 중력은 계속 적용 |
| 연속 넘김 | 넘긴 직후 같은 틱에 다시 넘기지 않도록 한 틱 면제(후보). 한 방향으로 매우 빠르게 던졌을 때 반복 순환은 허용(공중에 오래 있지 않도록 낙하가 끝난다) |
| 넘김과 클램프 | 기존 `clampWindowForMovement` 는 "화면 안에 보이는 캐릭터를 둔다"는 규칙이라 넘김과 충돌한다. 공중에서는 클램프 대신 넘김 검사를 하고, 착지·걷기·드래그에서 클램프를 쓴다 |
| 모니터가 하나일 때 | 합집합 = 그 화면. 좌우는 반대쪽에서, 위는 아래에서 나온다 |

보이는 몸이 가장자리에 걸쳐 일부가 화면 밖일 때: 넘김 판정은 **발 위치**가 합집합을 벗어난 순간이다(몸 일부가 먼저 밖에 나가도 넘기지 않는다). 나올 때 발이 반대쪽 가장자리 안쪽에 오도록 한다.

## 9. 애니메이션 [기준 11]

### 9-1. 새 상태 이름과 기본 대체

새 이름은 `climb-ready`·`climb`·`descend`·`fall`·`land`·`thrown`(ADR-0008 7-3 의 이름 규칙 `^[a-z][a-z0-9-]{0,31}$` 에 맞는다). 앱이 뜻을 아는 이름이 9개(`idle`·`blink`·`walk`·`sleep`·`happy`·`surprised`·`worried`·`talk`·`drag`)에서 15개로 늘고, 팩 `states` 상한 32개 안이다(검증기 `validateCharacterManifest`).

| 새 상태 | 의미 | 기본 대체(앱 내장 `fallbacks`) | 팩 `fallbacks` 가 없을 때 마지막 |
|---|---|---|---|
| `climb-ready` | 오르기 전 준비 | `surprised` | `idle` |
| `climb` | 오르는 중 | `walk` | `idle` |
| `descend` | 내려가는 중 | `walk` | `idle` |
| `fall` | 낙하 | `drag` | `idle`(`drag` 가 없으면) |
| `land` | 착지 | `idle` | `idle` |
| `thrown` | 던져짐 | `fall` → `drag` | `idle` |

대체는 기존 해석 `resolve()`(`CharacterAnimationMachine`)가 `manifest.fallbacks` 를 따르는 방식과 같다. **앱 내장 기본 대체**는 팩 `fallbacks` 에 해당 키가 없을 때만 적용하는 코드 상수 표다(`packages/core`, 후보 `DEFAULT_MOVEMENT_FALLBACKS`). 팩 `fallbacks` 가 우선한다. 기존 팩 4개는 수정 없이 그대로 유효하고 새 상태가 없으면 위 표에 따라 기존 그림으로 대체해 동작한다(사전 결정 ④). 재생 중 `land` 가 `idle` 이면 착지 순간 그림이 `idle` 이다.

### 9-2. 동작 → 상태/시퀀스 매핑과 착지 방식 [팩 선택 필드]

ADR-0008 의 `behavior`(4장)·`reactions.json`(12장)과 같은 방식으로, **매니페스트에 경로 문자열 선택 필드 하나**(`motions`, 값 `"motions.json"`)를 두고 별도 파일에 둔다(Q5가 아니라 잠정 채택, 12장). 이유: 시퀀스 id 참조를 포함하고 `interactions`·`sequences`·`reactions` 와 같은 저장 흐름(`ensureEditable` → 안전 JSON → 파서 → `writeFile` → `updateManifest`)·한도(`validatePackJsonLimits`)를 그대로 쓴다.

```json
{ "version": 1,
  "motions": {
    "climb":  { "play": "climb" },
    "fall":   { "sequence": "falling-flail" },
    "land":   { "play": "land" }
  },
  "landing": "soft" }
```

- `motions` 의 키는 위 6개 이동 동작만, 값은 `{ play }`(상태 이름) 또는 `{ sequence }`(시퀀스 id) 하나. 키가 없으면 기본(위 표의 같은 이름 상태 + 내장 대체). `play` 는 `fallbacks` 를 따르고 없으면 `idle`. 시퀀스 매핑은 이동 동작 길이가 이동 모델에 묶여 있으므로(오르기·내려가기·착지) **그림만 재생하고 길이를 따르지 않는다**: 이동이 끝나면 시퀀스를 끊고(ADR-0008 6-6) `idle`. `thrown`·`fall` 같은 공중 동작은 시퀀스 마지막 단계에서 반복한다(후보; 구현 때 결정). 시퀀스 매핑을 처음부터 허용할지는 Q가 아닌 구현 결정으로 남긴다.
- `landing` — 착지 방식(`"soft"` 사뿐 | `"normal"` 일반, 기본 `"normal"`). 사뿐이면 낙하 속도와 상관없이 `land` 길이가 후보 400ms(느리게 내려앉는 그림이나 시간 늘림), 일반이면 후보 200ms 에 낙하 속도가 클수록 조금 길게(최대 400ms). 구체 값은 H 기준. wolf-maid 는 `"soft"`(기준 11).
- **파생 팩(`extends`).** ADR-0008 6-2·12-2 와 같다: 파생 팩이 자기 `motions` 를 가지면 원본 것을 통째로 대체하고, 없으면 원본 것을 읽는다(`pack.ts` 병합 목록에 `motions` 추가).
- **왜 `behavior` 에 넣지 않나.** `behavior` 는 수치 5개의 키 단위 병합 규칙이다. 상태 이름·시퀀스 id 참조를 같은 객체에 섞으면 병합 규칙이 복잡해진다. 오르내리기 확률은 수치라서 `behavior` 에 둔다(10장).
- **`apiVersion`.** `"1"` 유지(선택 필드 추가, ADR-0002 버전 정책). 기존 유효한 매니페스트는 모두 그대로 유효하고 같은 결과를 낸다. 이전 앱이 새 팩을 읽으면 `motions`·`landing` 필드를 무시하고 기존 동작(추측: 이전 앱은 모르는 필드를 허용·무시, ADR-0008 1-1 `additionalProperties: true`). `packages/plugin-sdk/src/v1/` 에는 캐릭터 매니페스트 타입이 없고 이 설계는 그곳을 바꾸지 않는다.

추가(2026-10-12, D-060): `motions.json`의 선택 필드 `afterLand: { play: "<state>" }`는 착지가 모두 끝난 뒤 비반복 상태를 한 번 재생한다. 없거나 상태가 없거나 반복 상태면 기존처럼 `idle`로 돌아간다. `apiVersion`은 `"1"`을 유지하며 이전 앱은 이 필드를 무시한다.

### 9-3. 설정 창 편집 [기준 11]

[캐릭터] 아래 하위 탭 [이동](후보 이름)에서 동작 6개마다 "재생 상태"(없음/상태)·"동작(시퀀스)"(없음/시퀀스)와 착지 방식(사뿐/일반)을 고르고 저장한다. 구조는 [알림 반응] 탭(ADR-0008 12-4)과 같다: 한글 이름, `idle` 로 떨어지는 이름 경고, [▶ 미리보기](실제 펫을 움직이지 않고 설정 창 안에서 재생. 이동을 직접 보는 것은 개발 제어나 실사용). 새 IPC 채널(후보 `settings:motions-load`·`settings:motions-save`)은 허용 채널 목록 갱신 대상이다(게이트: 설정 창 IPC 채널 추가). 저장은 `createPackService` 에 `saveMotions`(후보)를 `saveReactions` 와 같은 흐름으로 더한다.

### 9-4. 발 위치 검사와 새 상태의 관계

`pnpm sprites:check` 와 앱의 시트 교체 검사(`inspectSpriteFootFrame`)는 **모든 상태·프레임의 발이 `anchor` 근처**인지 본다. 새 상태에도 그대로 적용된다. 단 `climb`(벽을 오르는 그림)처럼 발이 `anchor` 에 있지 않은 동작이 정당하게 있을 수 있다. 그래서:

- 이동 상태 중 발이 땅에 닿는 것(`land`·`climb-ready`·`thrown` 의 마지막 프레임·`descend` 의 마지막 프레임)은 검사를 그대로 받는다. 발이 닿는 순간 어긋나면 착지할 때 펫이 한 번 튄다.
- 공중 동작(`fall`·`thrown` 중간, `climb` 중간)은 발 위치 검사를 건너뛰는 선택 규칙이 필요한지 구현 때 판단한다(**남은 구현 결정**). 건너뛰면 `states.<이름>` 에 새 선택 필드가 필요한데 이는 `apiVersion` "1" 의 선택 필드 추가라 가능하지만, 지금은 만들지 않고 모든 상태가 검사를 받는다는 현행 규칙을 유지한다(잠정).
- 대체 그림(`walk` 로 `climb` 을 대신)은 이미 검사를 통과한 상태라 문제가 없다.

## 10. 설정 [기준 12]

| 항목 | 값 | 저장 위치(잠정, Q7) |
|---|---|---|
| 기능 전체 켜기/끄기 | `terrain.enabled`(불리언, 후보 이름) | `settings.json` 전역 |
| 제외 앱 | 실행 파일 이름 문자열 배열, 항목 최대 64개·이름 길이 ≤ 64(후보), 대소문자 무시 | `settings.json` 전역 |
| 오르기 확률 | 0–1, 후보 기본 0.4 | 팩 `behavior.climbChance` + 사용자 `characterBehavior`(캐릭터별) |
| 내려가기 확률 | 0–1, 후보 기본 0.5 | 팩 `behavior.descendChance` + 사용자 `characterBehavior` |

- **끄면 M7 그대로.** `terrain.enabled === false`(또는 `process.platform !== "win32"`, 스크립트 불활성)이면 `TerrainSource` 를 시작하지 않고 `PetMovement` 를 만들지 않는다. 드래그를 놓으면 그 자리에 머물고(현재 동작), 화면 끝은 클램프, 걷기는 좌우뿐이다. 끌 때 진행 중이던 이동은 즉시 `grounded` 로 두고 현재 위치에서 `fitCurrentPosition` 한다(공중에 멈춰 있지 않도록 화면 바닥으로 내리는지 그 자리에 두는지는 구현 결정: **추천은 그 자리, 기능을 끈 것은 이동 규칙을 M7 으로 돌리는 것**).
- **확률 두 값을 `behavior` 에 두는 이유.** 캐릭터의 성격(활발한 펫은 자주 오른다)에 속하고, `resolveBehavior`(코드 기본 < 팩 < 사용자)와 `configure` 즉시 반영·초기화 흐름을 그대로 쓴다. 범위: 각 0–1(후보). `BEHAVIOR_RANGES`·`validateBehavior` 에 키를 더하며 모르는 키를 무시하는 기존 앱에는 영향 없다. 단 `CharacterAnimationOptions` 에 키를 넣는 것은 머신이 쓰지 않는 값을 옮기는 것이므로 `resolveBehavior` 가 돌려주는 객체의 일부를 `PetMovement` 가 가져가게 한다(`CharacterAnimationMachine` 은 무시).
- **제외 앱과 기능 켜기는 전역.** 어떤 캐릭터를 쓰든 같은 앱을 발판에서 빼고 싶으므로 캐릭터별이 아니다. `parseSettings` 의 기존 패턴(`Object.fromEntries` 프로토타입 오염 방지, 잘못된 값은 버림)으로 읽는다.
- **설정 창 위치(잠정, Q7 과 함께).** [일반] 탭에 "화면 위 이동" 섹션을 더해 켜기·제외 앱을 둔다. 확률은 [캐릭터] > [행동] 하위 탭의 수치 입력에 두 칸을 더한다(기존 행동 편집기와 같은 저장·초기화). 제외 앱 입력은 텍스트로 이름을 추가하고 목록에서 지우는 방식이며, "실행 중 앱에서 고르기"는 창 제목을 읽어야 해 보여서 이번에는 만들지 않는다(후보: 실행 파일 이름만 열거하는 고르기를 나중에 추가 가능, 15장).
- **IPC.** 새 채널(후보 `settings:terrain-load`·`settings:terrain-save`)은 허용 채널 목록(`apps/desktop/src/main/settings-window.ts` 의 `settings:*`) 갱신 대상이다. main 이 범위·길이를 다시 검증한다(ADR-0008 S8). 팩 문자열은 `textContent` 로만 넣는다(`innerHTML` 금지, 게이트).

## 13. 기존 기능과의 공존 [기준 13]

- **말풍선 따라가기.** 펫 창 이동이 모두 `moveWindowTo` 를 지나므로 말풍선(`bubbleWindow?.refresh()`)이 이미 따라간다. 새로 할 일은 이동 중 갱신 빈도다: 공중에서 16ms 마다 `refresh` 가 불리면 말풍선 창 `setBounds` 가 잦다. 후보: 말풍선 갱신을 50ms 로 묶는다(구현 때 측정). 말풍선이 화면 위쪽에 뜨는 규칙(`placeBubble` 의 `above`/`below`)은 그대로이고, 펫이 위로 던져져 화면 위 가장자리에 가까우면 `below` 로 바뀐다. 화면 끝 넘김으로 반대쪽에서 나오면 말풍선도 따라 이동한다(`bubbleAnchor` 가 현재 `foot`·`displays` 로 계산).
- **알림.** 알림이 표시될 때 `playReaction` 은 상태를 재생한다. 이동 중(`falling`/`thrown`/`climbing`/`descending`)에는 **알림 말풍선은 바로 뜨고 표정 재생은 착지(또는 `grounded` 복귀) 뒤로 미룬다**(7-2 "이동 그림이 이김"). `grounded` 에서는 기존과 같다. 알림이 이동을 멈추지는 않는다(걷는 중 알림이 와도 걷기는 계속되는 현재 동작과 같다).
- **순서 있는 동작(시퀀스, ADR-0008 6장).** 시퀀스 중에는 `grounded` 에서 걷기를 시작하지 않는 현재 규칙(시퀀스는 창을 옮기지 않는다, 6-6)이 유지된다. 즉 시퀀스 진행 중 낭떠러지·벽 판정을 하지 않는다. **서 있던 발판이 사라지거나 창이 움직여서 생기는 이동(따라가기·낙하)은 시퀀스를 끊지 않고 따라간다**(펫이 허공에 서 있지 않도록 위치는 따라가고, 그림은 시퀀스가 이긴다). 사용자가 시퀀스 중 드래그하면 기존대로 끊긴다. 시퀀스 중 낙하가 시작되면(발판 사라짐) 시퀀스를 끊고 `fall` 로 간다(잠정; 공중에서 큰절 같은 그림이 이상하므로).
- **상호작용(우클릭 메뉴).** 탭 반응은 `grounded` 에서만 재생한다. 공중에서는 메뉴가 열리지 않는 것이 자연스러우나, 펫 창이 움직이는 중 클릭 판정은 기존 `refreshHitTest` 가 따라간다. 메뉴로 누른 상호작용은 `USER_DIRECT` 라 방해 금지를 받지 않는 기존 규칙 그대로이며, 이동 중이면 착지 뒤에 재생한다(잠정).
- **잠들기.** `sleep` 은 `grounded` 이면서 `idle` 일 때만 들어간다(머신 규칙 그대로). 잠든 상태에서 서 있던 창이 움직이면 따라가며(위치 이동) 그림은 `sleep` 을 유지한다. 서 있던 발판이 사라지면 잠이 깨고 `fall`. 착지 후 잠들기 시간을 다시 센다(`request` 의 `quietSinceMs` 갱신).
- **방해 금지.** 방해 금지는 알림 표시를 보류하는 것이지 펫의 움직임을 멈추지 않는다(현재 걷기가 방해 금지에서도 계속되는 것과 같다). 이동 규칙은 변하지 않는다.
- **전체 화면 보류.** `FullscreenWatcher` 가 `true` 이면 알림이 보류된다(`quiet()`). 이 상태에서 **지형 조회는 멈추고 지형은 화면 바닥만**으로 간주한다(전체 화면 앱 창은 발판이 아니고, 게임 위에서 펫이 이리저리 움직이면 방해). 펫은 바닥 높이로 `falling` 해서 서고 걷기는 기존처럼 계속한다(펫 창이 항상 위라 현재도 보임). 전체 화면이 끝나면 조회를 다시 시작하고 새 스냅샷에 맞춰 선다. 이 항목은 잠정이며 실사용에서 "게임 위에서 펫이 거슬린다"는 보고가 있으면 펫 숨김 옵션을 별도 질문으로 올린다.
- **위치 저장·복원 [기준 13].** `SavedPosition`(`{foot, display}`)은 그대로다. 복원은 `placeFoot` 로 작업 영역 안에 놓은 뒤 지형 첫 스냅샷이 오면 **발이 창 윗변 위에 있었다면 거기에 서고, 아니면 `falling` 으로 가장 가까운 아래 발판에 선다**. 즉 "창 위에 있던 위치"는 좌표로 저장되고 재시작 후 같은 좌표에 같은 창이 같은 위치에 있으면 같은 곳에 선다. 창 id 는 저장하지 않는다(재시작 후 의미가 없고 개인정보 최소화). 이동 중(공중)에 종료하면 마지막 좌표를 저장하고 복원 시 낙하한다. 저장은 `grounded` 가 되는 순간과 걷는 중 2초마다 하는 기존 규칙(`savePosition`)을 `landing` 이 끝날 때 한 번 더 부르는 정도로 확장한다(공중에서는 저장하지 않음: 쓰기 빈도).
- **숨김.** `hidePet` 이 시계를 멈추므로 이동도 멈춘다. 숨겨진 동안 지형 조회를 정지한다(CPU). 다시 보이면 조회를 시작해 첫 스냅샷에서 서 있던 발판이 사라졌으면 `falling`.
- **캐릭터 전환·팩 저장.** `selectCharacter` 가 머신을 새로 만들 때 `PetMovement` 의 속도·상태를 `grounded` 로 초기화하되 발 위치는 유지(`currentFoot()`)한다. 캐릭터가 바뀌면 `cellSize`·`anchor`·`contentRect` 가 달라 `windowSize()` 가 바뀌므로 발 기준으로 재배치(`placeFoot`)한 뒤 지형에 다시 맞춘다.
- **드래그 놓기 직전의 표본.** 개발 제어 `startDrag(cursor, injected)` 의 주입 드래그에서도 표본을 기록한다(개발 제어가 커서 좌표를 시계 시각과 함께 주는 방식으로 던지기 e2e 를 만든다, 14장).

## 14. 테스트 방법 [기준 6–10, 14]

원칙: e2e 가 실제 PC 의 다른 창에 기대지 않는다(AGENTS.md "e2e 는 PC 환경 입력을 고정").

- **가짜 지형 주입.** 개발 제어 `setTerrainForTest`(후보, 기존 `setFullscreenForTest` 와 같은 형식: `--dev-control` 개발 실행에서만, 값 검증, 요청한 효과가 끝난 뒤 응답) 가 스냅샷 `[{id, x, y, w, h, platform}]` 를 직접 넣는다. 이 값이 있으면 실제 `TerrainSource`(PowerShell)를 시작하지 않는다(`DesktopApp.launch` 가 항상 가짜 빈 지형으로 고정 — 전체 화면 값을 false 로 고정하는 것과 같은 방식). 새 환경 의존 입력이므로 AGENTS.md 규칙대로 `DesktopApp.launch` 에서 고정한다. 코드에는 같은 파서·가림 계산(`terrain.ts`)을 거치므로 가림·최소 폭 규칙도 주입으로 검증한다.
- **시계로 물리 검증.** `clock` 의 `pause` 후 `advanceMs` 로 당겨(7-6 의 고정 간격 적분이 큰 값도 처리) "던지기 → 정점 → 낙하 → 착지" 를 결정적으로 검증한다. 단언은 사용자가 보는 결과: 창 위치(`bounds`), 재생 상태·프레임(`state`), 서 있는 발판의 y. 로그 줄만 보지 않는다(AGENTS.md).
- **던지기 주입.** 기존 `startDrag`(`injected`)와 커서 좌표를 시각과 함께 여러 번 주는 개발 제어(기존 `drag` 계열 명령을 확장하거나 후보 `moveCursorForTest`)로 놓기 직전 속도를 만든다. 실제 마우스 입력에 기대지 않는다.
- **단위 테스트(`packages/core`).** `terrain.ts`(가림 구간 빼기, 최소 폭, 머리 위 공간, 전체 화면 창 제외, 제외 앱 표시), `movement.ts`(전이 표, 착지 판정 터널링, 던지기 속도 계산, 확률 0/1 고정 난수, 화면 끝 넘김, 합집합 틈 처리, 낭떠러지 한 번만 판정), `DEFAULT_MOVEMENT_FALLBACKS`·`motions.json` 파서(왕복, 파생 팩 대체, 기존 팩 변화 없음).
- **스크립트 감시자 단위 테스트.** `fullscreen-watcher.test.ts` 와 같은 틀: 가짜 `PowerShellChild` 로 stdout 줄 파싱(잘못된 줄 무시), 재시작 1회, 두 번째 죽음 후 불활성, `stop()` 대기를 검증한다. **스크립트 문자열 자체의 실행은 단위 테스트가 못 하므로** 실제 PowerShell 로 한 번 돌려 형식을 확인하는 수동·옵션 점검(선택, CI 불필요)을 둔다.
- **실제 창이 필요한 확인은 H.** 실제 창 위에 서기·창 끌 때 따라가기·다중 모니터·서로 다른 배율은 사용자가 쓰며 보고한다(백로그 H 기준). e2e 는 주입으로 규칙을, 사용자는 실제 환경을 맡는다.
- **기준 14(CPU).** 창 감시를 켠 대기 상태에서 앱+PowerShell 자식의 CPU 를 다시 잰다. 목표 1% 미만. 넘으면 원인(주기·스크립트·타이머)을 기록한다. 실험 값(500ms 약 0.27% 코어)이 기대치이지만 앱 전체와 합친 값은 **미측정**이다.
- **기능 끔.** `terrain.enabled === false` 에서 기존 e2e 전체가 변화 없이 통과해야 한다(회귀 방지): 기존 e2e 는 가짜 빈 지형 또는 기능 끔으로 고정한다.

## 15. 보안·개인정보·성능 [기준 6, 14]

- **읽는 범위(5-4).** 다른 창의 위치·크기·보임 여부와 스타일 비트, 소속 프로세스 id(자기 창 판정), 제외 앱 목록이 있을 때만 실행 파일 이름. 읽지 않는 것: 제목, 클래스, 내용, 전체 경로, 캡처.
- **보관.** 메모리에만 둔다(스냅샷은 최신 한 개, 이전 것은 따라가기 비교용 한 개). 디스크·로그·`pet-position.json` 에 쓰지 않는다. 개발 제어 `state` 응답이 발판 목록을 돌려주는 것은 `--dev-control` 개발 실행 한정이고 packaged 앱에는 없다.
- **스크립트 입력.** 인자는 ① 정수 프로세스 id ② 제외 앱 이름 목록. 이름은 설정 저장 때 `^[A-Za-z0-9._ -]{1,64}$`(후보)로 검증하고, PowerShell 로 넘길 때는 `-EncodedCommand` 안의 문자열 리터럴이 아니라 **JSON 을 base64 로 인코딩한 인자**로 넘겨 구문 주입을 막는다(구현 때 확인). 고정 스크립트 문자열 자체는 사용자 입력을 포함하지 않는다.
- **외부 쓰기 없음.** 이 기능은 읽기와 펫 창 이동뿐이다. 다른 창을 움직이거나 입력을 보내지 않는다. 리뷰 기준(CLAUDE.md "외부 시스템 쓰기 동작이 사용자 버튼 없이 실행되는 경로가 없는지")에 해당하는 새 경로가 없다.
- **게이트.** milestones.md M8 게이트대로 기준 6 은 다른 창의 위치를 읽는 코드라 머지 전 리뷰 + gate 승인 대상이다. 확인 항목: 창 제목·내용·프로세스 경로를 저장하거나 로그에 남기지 않는지(5-4), 제외 앱 이름 입력 검증, 자기 창 제외. 설정 창 IPC 채널 추가(10장·9-3)는 허용 채널 목록 검토 대상이고 팩 문자열 `innerHTML` 을 쓰지 않는다.
- **성능.** 대기 시 조회 500ms(Q2). 숨김·전체 화면 보류·기능 꺼짐에서 정지. 공중·오르내리기 동안만 16ms 타이머를 쓰고 땅에 서면 50ms 로 돌린다(CPU 영향은 14장 기준 14 에서 측정). 스냅샷이 바뀔 때만 가림을 계산하고 변화가 없으면 아무 일도 하지 않는다.
- **실패 시.** 스크립트가 못 뜨거나(보안 프로그램·실행 정책) 두 번 죽으면 `TerrainSource` 가 "지형 없음"을 돌려주고 펫은 화면 바닥만 발판으로 동작한다(M7 의 걷기·드래그와 거의 같음). 로그에는 "terrain watcher gave up" 같은 생명 주기 한 줄만 남고 설정 창은 "창 위치를 읽을 수 없어 화면 바닥에서만 움직여요" 같은 안내를 보인다(문구는 구현 때 정함, 기능을 끄는 것은 사용자). `process.platform !== "win32"` 면 시작하지 않는다. 변환 API 예외(`screenToDipRect`)나 스냅샷 파싱 예외는 try/catch 로 그 스냅샷만 버린다.

## 17. 보충: 점프와 등반 (D-054, 2026-10-09)

사용자 실사용 피드백("내려가는 건 잘 되는데 올라가지 않고 브라우저 앞을 그냥 지나간다")에 따라 Q6 을 다시 정한다. 원인: Q6 (a) 의 "펫 키 이내의 단차만 오른다" 때문에 바닥에서 보통 브라우저 창(펫 키의 약 7배)으로는 오를 수 없었고, 높은 벽에서 돌아서야 할 때 그냥 지나가는 버그도 있었다.

**결정.** 오르내리기를 높이 차이에 따라 두 동작으로 나눈다. 기준 높이(`jumpMaxHeight`)는 캐릭터별 설정이다.

| 높이 차이 h | 올라갈 때(벽 앞) | 내려갈 때(낭떠러지) |
|---|---|---|
| h ≤ 기준 높이 | **점프**(`jump`): 포물선으로 뛰어 윗변에 착지(`land`) | **뛰어내리기**(`hop-down`): 가볍게 뛰어 아래 발판에 사뿐히 착지 |
| h > 기준 높이 | **등반**(`climb-ready` → `climb`): 창 옆면을 타고 높이 제한 없이 윗변까지 오름 | **타고 내려가기**(`climb-down`): 창 옆면을 타고 아래 발판(또는 바닥)까지 내려감 |

- 확률은 지금처럼 `climbChance`(올라가기)·`descendChance`(내려가기) 두 개이고 점프·등반 모두에 적용한다. 확률에 걸리지 않으면 돌아선다. 확률 0 이면 절대 하지 않는다.
- **벽 판정 수정.** 걷는 방향 앞의 창이 발 높이를 가리면(창의 세로 범위가 발 y 를 포함) 그 창은 벽이다. 벽 앞에서는 오르거나 돌아서며, 앞을 그냥 지나가지 않는다. 창의 아랫변이 발보다 위에 있는(떠 있는) 창은 벽이 아니라 그 밑을 지나간다.
- **Q6 높이 한도는 없앤다.** 등반과 타고 내려가기는 높이 제한이 없다. 7-5 의 "h > maxClimbHeight 이면 돌아선다"는 이 절로 대체된다.
- **새 상태와 기본 대체(그림이 없을 때).** `jump` → `happy`, `hop-down` → `fall` 의 대체, `climb-down` → `climb` 의 대체. 9-1 표에 더한다.
- **캐릭터별 설정(팩 `behavior` + 사용자 `characterBehavior`, ADR-0008 4장 3단 해석).** `jumpMaxHeight`(기준 높이, 후보 기본 150 DIP, 범위 0–2000), `climbChance`·`descendChance`(0–1), `climbSpeed`(등반·타고 내려가기 속도, 후보 120 DIP/s, 범위 20–1000), `jumpClearance`(점프 정점이 윗변보다 높은 여유, 후보 24 DIP, 범위 0–300), `gravity`(낙하·점프·던지기 공통 중력, 후보 2000 DIP/s², 범위 200–10000). 7-3 의 "물리 수치는 사용자 설정으로 노출하지 않는다"는 중력에 한해 이 절로 대체된다. 종단 속도·던지기 최대 속도는 코드 상수로 둔다.
- 기준 번호: 8(오르내리기), 11(새 상태 그림 매핑), 12(설정).
## 18. 보충: 창 사이 뛰어넘기 (D-056, 2026-10-10)

- **언제.** 걷다가 낭떠러지(서 있는 발판 끝)에 닿았을 때, 걷는 방향으로 발판 끝에서 수평 거리 `gapJumpDistance` 안에 시작하는 다른 발판이 있으면 후보다. 후보가 여럿이면 가장 가까운 것. 건너편 윗변이 더 높으면 높이 차가 `jumpMaxHeight` 이하일 때만 후보, 더 낮으면 높이와 상관없이 후보.
- **판정 순서.** 후보가 있으면 `gapJumpChance` 로 뛰어넘을지 정한다. 뛰지 않거나 후보가 없으면 7-5·17장대로 `descendChance` 로 내려가기(뛰어내리기·타고 내려가기) 또는 돌아서기.
- **동작.** 17장 점프와 같은 포물선(`gravity`, 정점은 두 윗변 중 높은 쪽 + `jumpClearance`)으로 건너편 발판 위 한 걸음 안쪽에 착지(`land`). 재생 요청은 `jump`. 비행 중 지형이 바뀌어 대상이 사라지면 `falling`.
- **설정(캐릭터별, 팩 `behavior` + 사용자 `characterBehavior`).** `gapJumpDistance`(기본 200 DIP, 0–1000, 0 이면 뛰어넘지 않음), `gapJumpChance`(기본 0.5, 0–1).
- 기준 번호: 8, 12.

## 19. 보충: 이동 도중의 예외 (D-057, 2026-10-10)

| 이동 상태 | 사건 | 처리 |
|---|---|---|
| `climbing`·`climbing-down` | 붙잡은 창의 위치가 2 DIP 이상 바뀜, 창이 닫힘·최소화·지형에서 사라짐 | 그 자리에서 `falling` |
| `climbing`·`climbing-down` | 매 틱, 펫의 발 높이가 붙잡은 창의 세로 범위(윗변~아랫변) 밖이거나, 그 높이의 옆면이 더 위 z 순서의 창에 가려짐 | 그 자리에서 `falling`(허공을 기지 않음) |
| `climb-ready` | 붙잡을 창이 위 조건으로 사라짐 | `grounded` 로 돌아가 돌아섬 |
| `jumping`(점프·뛰어넘기)·`hop-down` | 착지 목표 창이 2 DIP 이상 움직이거나 사라짐 | 목표를 버리고 현재 속도로 비행을 이어감(`falling` 과 같은 착지 규칙: 위에서 아래로 지나는 첫 발판 또는 바닥) |

- 2 DIP 문턱은 D-055 와 같다. 판정은 지형 갱신 때와 매 이동 틱 모두에서 한다.
- 기준 번호: 7, 8.

## 20. 구현에서 확정·변경된 점 (M8 종료, 2026-10-10)

- **Q6 (a)** 는 17장(D-054)으로 대체됐다. 높이 한도는 없고, 높이 차이에 따라 점프와 등반으로 나뉜다.
- **서 있던 창이 움직이면**(7-4) 따라가지 않는다. 2 DIP 이상 움직이면 그 자리에서 떨어진다(D-055).
- **9-2 `motions`.** 키는 17장의 새 상태를 더한 9개(`climb-ready`·`climb`·`climb-down`·`descend`·`jump`·`hop-down`·`fall`·`land`·`thrown`)이고, 값은 `{ play }` 만 받는다. **시퀀스 매핑(`{ sequence }`)은 만들지 않았다.** 해석 순서: `motions[동작].play` → 동작 이름의 상태 → 팩 `fallbacks` → `DEFAULT_MOVEMENT_FALLBACKS` → `idle`.
- **착지 길이**는 사뿐 400ms, 일반 300ms 고정이다(후보 200ms + 낙하 속도 비례 대신). 값은 `MOVEMENT_PHYSICS`(`packages/core/src/movement.ts`)에 있다. wolf-maid 는 `"soft"`.
- **9-3 설정 창.** 탭 이름은 [캐릭터] > [이동]으로 확정했다. 동작마다 재생 상태와 실제로 재생될 그림을 보여 주고, `idle` 로 떨어지면 경고하며, 미리보기와 착지 방식 라디오가 있다. 팩의 `motions.json` 이 깨져 있으면 저장과 초기화가 비활성이다. 저장 경로는 기존 팩 저장과 같다(`saveMotions`, IPC `settings:motions-load`·`settings:motions-save`).
- **15장 성능.** 측정 결과 창 감시를 켠 대기 CPU 는 평균 0.157–0.377%로 목표(1% 미만)를 충족했다. 창 감시 PowerShell 의 몫은 0.007–0.044%p 이고, 메모리는 85 / 68 MB 늘었다(`docs/progress/idle-cpu.md` M8 재측정).
- **아직 확인하지 않은 것(16장).** 배율이 다른 모니터의 좌표, 창이 많을 때의 비용, 보안 프로그램의 영향은 실사용에서 확인한다.
