# ADR 0007: 캐릭터 팩 에셋 형식

## 상태

**Q4·Q6 은 ADR-0008 에서 재검토 후 유지(D-047).**

**1단계 구현 완료 (M6, 2026-10-09).** 폴더 + 파생 팩(`extends`), 사용자 팩 선택·삭제, 어투·상호작용·정보 편집기가 구현됐다. 컨테이너(`.deskpack`)는 하지 않았다(D-045, 백로그). 구현하며 이 문서와 달라진 점은 맨 아래 "M6 구현에서 확정·변경된 점" 절에 있다. 아래는 이전 상태 기록이다.

**1단계 방향 결정됨 (2026-10-08, D-037).** 아래 "사용자 결정" 절의 항목(Q1·Q2·Q4·Q6·Q9)은 확정이고, 나머지는 추천 잠정 채택이며 컨테이너(.deskpack) 단계에서 Q5·Q7·Q11 을 다시 묻는다. 구현은 M6 에서 `/milestone-start 6` 으로 완료 기준을 동결한 뒤 task 로 만든다. 처음 제안 상태: 제안(미승인). 사용자 결정 D-036(`docs/progress/decisions.md`)의 방향을 구체화한 초안이다. 이 문서의 "추천"은 결정이 아니다. 10장의 질문을 사용자가 하나씩 정한 뒤 상태를 바꾼다. 수치 중 "후보"라고 적은 것은 근거 없이 제안하는 값이다.

## 1. 배경과 현황

D-036은 캐릭터 팩을 어투·상호작용 대사에 그치지 않고, 그림 시트·매니페스트·어투(voice)·상호작용(interactions)·메타데이터를 담는 하나의 에셋 형식으로 정의하고, 앱 안에서 편집·복제·선택·삭제·내보내기·가져오기를 지원하는 방향으로 정했다. 이 장은 지금 팩이 무엇이고 어떻게 다뤄지는지를 코드 근거와 함께 적는다.

### 1-1. 팩은 지금 무엇인가

팩은 `characters/<id>/` 폴더 하나다. 저장소에는 네 개가 있다.

| 폴더 | 내용 | 비고 |
|---|---|---|
| `characters/placeholder` | `manifest.json` + `sheets/*.png` 9장, 셀 256×256 | 어투 없음(매니페스트에 `voice` 필드 없음) |
| `characters/placeholder-alt` | 같은 구성 | 어투 없음 |
| `characters/wolf-maid` | `manifest.json` + `sheets/*.png` 9장 + `voice.json`, 셀 130×192, `anchor` [65,191], `scale` 0.8 | 어투 7종(done·waiting·failed·info·deadline·reminder·alert) |
| `characters/mochi` | `sheets/.gitkeep` 만 있음 | 매니페스트 없음. 기획안 6-3 예시 이름만 남은 빈 폴더 |

시트 파일은 작다. `characters/wolf-maid/sheets/` 의 PNG는 장당 약 3.5–6 KB(`ls -l` 로 확인), 한 팩의 시트 합계는 수십 KB 수준이다. 한도(8 MiB·64 MiB)는 실제 사용량보다 훨씬 넉넉하다.

팩을 만드는 도구는 `tools/sprite-pipeline`이다. 명세 JSON(`docs/art/pack/wolf-maid.json`)을 받아 `manifest.json` 과 `sheets/<상태>.png` 를 출력한다(`tools/sprite-pipeline/README.md`의 "Build a character pack"). 명세에는 `voice` 가 없고 `tools/sprite-pipeline/src/` 에서도 `voice` 를 찾지 못했다. 그래서 `wolf-maid` 의 `voice` 필드와 `voice.json` 은 도구 출력이 아니라 손으로 더한 것으로 보인다(출처 기록은 미확인). 재생성하면 `voice` 필드가 사라질 수 있다는 뜻이므로 구현 때 확인해야 한다.

### 1-2. 어떻게 검증되는가

- 매니페스트 규약은 ADR-0002다. 필수 필드 `id`·`name`·`apiVersion`("1")·`cellSize`·`anchor`·`scale`·`states`·`fallbacks`, 선택 필드 `voice`(D-029), 상태별 `next`·`facing`. 모르는 필드는 허용하고 무시한다(`packages/core/src/schemas.ts` 의 `additionalProperties: true`, D-012).
- `packages/core/src/validate.ts` 의 `validateCharacterManifest` 가 모양·범위·상태 간 참조·`anchor` 범위·`sheet`/`voice` 경로 규칙(`..`·절대 경로·역슬래시·콜론·제어문자·끝의 점/공백 거부)을 검사한다. 이 함수는 `id`·`name` 의 길이나 문자를 제한하지 않는다(문자열이기만 하면 통과). `states` 개수와 `frames` 상한도 없다(픽셀 상한이 간접적으로 막는다).
- `apps/desktop/src/main/character.ts` 의 `loadCharacter` 가 로드 때 추가로 확인한다. `validCharacterId`(경로 구분자·`..`·콜론 거부), `realpath` 로 팩 폴더·`manifest.json`·시트가 `characters` 폴더 밖으로 이어지지 않는지(junction·심볼릭 링크), `manifest.id` 와 폴더 이름 일치, 시트 8 MiB·팩 시트 합계 64 MiB·16,777,216 픽셀(`packages/core/src/schemas.ts` 의 `CHARACTER_SHEET_MAX_*`), PNG 시그니처·IHDR, 시트 크기가 `cellSize × frames` 와 같은지. 그다음 `nativeImage` 로 디코드해 불투명 영역(`contentRect`)을 계산한다.
- 어투는 `loadVoiceTemplates`(같은 파일)가 읽는다. 파일 64 KiB 상한, 같은 경로 안전 검사, `parseVoicePack`(`packages/core/src/voice.ts`)이 종류 7가지·변형 최대 8개·변형당 400 코드 포인트·슬롯 4종(`{task}` `{result}` `{folder}` `{message}`)만 허용하고, 잘못된 변형은 버리고 `problems` 에 남긴다. 파일이 깨져도 던지지 않고 빈 템플릿으로 동작한다.
- 결과 문구는 `renderVoice` 가 변형을 순환 선택하고, 슬롯이 비면 건너뛰며, 120 코드 포인트로 자른다.

### 1-3. 어떻게 신뢰되는가

지금 팩은 사실상 **신뢰한다고 가정한 로컬 파일**이다. 팩은 저장소(내장)에서만 오고, 사용자가 임의 팩을 넣는 경로는 정의돼 있지 않다. 다만 로더는 처음부터 팩을 방어적으로 읽는다(위 1-2의 링크 거부·크기 한도). 이 방어는 D-005("외부 콘텐츠는 신뢰할 수 없는 데이터")와 ADR-0005의 원칙, 곧 "보안 검사는 모두 main 에서 하고 보내는 쪽은 믿지 않는다"와 같은 방향이다. 팩에는 실행 코드가 없다. 팩이 앱에 줄 수 있는 것은 이미지, 숫자, 문자열뿐이다. 말풍선은 `textContent` 로 문구를 넣는다(`apps/desktop/src/renderer/bubble.ts`). 설정 창·펫 창·말풍선 창에 `Content-Security-Policy` 메타가 있다(`apps/desktop/src/renderer/*.html`).

### 1-4. 선택·저장 위치

- 어떤 팩을 쓸지는 시작 인자 `--character=<id>`, 없으면 `"placeholder"` 고정이다(`apps/desktop/src/main/index.ts` 의 `characterId`). 사용자가 바꿔도 **영속화되지 않는다.** 개발용 제어 명령 `setCharacter` 와 `selectCharacter` 가 있을 뿐이고, 사용자용 선택 UI는 미확인(찾지 못했다).
- 팩 폴더는 `--characters-dir=` 인자, 없으면 `resolve(app.getAppPath(), "../../characters")` 다(같은 파일). 개발 레이아웃 기준이다.
- 설치 파일은 M8 범위다(`docs/plan.md` 12장 로드맵). 설치본에서 팩이 어디에 놓일지는 아직 정해지지 않았다(미확인). 일반적으로 설치 폴더(Program Files 아래의 리소스)는 사용자 권한으로 쓸 수 없고 앱 업데이트 때 덮어써진다. **그래서 설치본의 내장 팩은 읽기 전용이라고 가정하고, 편집·가져오기는 `app.getPath("userData")` 아래에만 쓴다.** `userData` 는 이미 `settings.json`·`pet-position.json`·`logs/` 를 두는 곳이다(`index.ts`).

### 1-5. 어투·상호작용의 현재 상태

- 어투: 팩 안 `voice.json` 이 원본이고, 설정 창은 현재 캐릭터의 어투를 **보고 미리보고 펫에게 보내는 것**만 한다(`apps/desktop/src/main/settings-window.ts` 의 `settings:voice-load`·`voice-preview`·`voice-send`, `apps/desktop/src/renderer/voice-panel.ts`). 편집·저장 경로는 없다.
- 상호작용: 지금은 코드 상수다. `BUILTIN_INTERACTIONS`(쓰다듬기·말 걸기·놀래키기, `apps/desktop/src/main/pet-menu.ts`)가 `{id, label, mood, text}` 를 가지고, 누르면 `info` 어투 슬롯 `{message}` 로 보낸다. **D-035(설정 창에서 편집, 저장은 settings.json)는 결정만 기록됐고 구현은 이 브랜치에 없다**(`git show --stat a584685` 가 `docs/progress/decisions.md` 한 줄만 바꾼다. `apps/desktop/src/main/settings.ts` 의 `DeskpetSettings` 에도 `interactions` 가 없다). D-036 이 저장 위치를 사용자 팩으로 바꾸므로 settings.json 에 먼저 구현하면 이중 작업이 된다. 8장과 10장 Q9에서 다룬다.

### 1-6. 문제

1. 사용자가 팩을 고르거나 만들 방법이 없다(선택 미영속, 편집 UI 없음).
2. 어투·상호작용을 바꾸려면 파일을 직접 고치고 재시작해야 한다(D-035의 근거).
3. 내장 팩은 설치본에서 읽기 전용이라 편집 결과를 둘 곳이 필요하다.
4. 외부에서 받은 팩을 안전하게 받는 규칙이 없다. 지금 로더는 검증은 하지만 "신뢰할 수 없는 입력" 전제의 한도(파일 개수, JSON 깊이, 압축 폭탄, 이름 규칙)는 부족하다.

## 2. 목표와 비목표

### 목표

- 팩 하나에 그림·매니페스트·어투·상호작용·메타데이터가 들어가는 형식을 정의한다.
- 앱 안에서 팩을 선택(영속)·복제·편집·삭제·내보내기·가져오기 할 수 있다.
- 내장 팩은 읽기 전용으로 두고 편집은 항상 사용자 팩 복제본에 한다.
- 가져온 팩은 신뢰할 수 없는 데이터로 다루며, 팩이 할 수 있는 일은 "그림·문구 표시"로 한정한다. 코드 실행·외부 쓰기·네트워크 접근 수단을 만들지 않는다.
- 기존 `characters/<id>/` 폴더와 `voice.json` 이 수정 없이 계속 유효하다.

### 비목표 (이 ADR 이 정하지 않는다)

- 마켓·온라인 배포·검색·평점·자동 업데이트, 유료 판매, 서명·인증 체계(제작자 신원 보증).
- 그림 편집기(픽셀 편집, 스프라이트 시트 제작 도구). 그림은 `tools/sprite-pipeline` 으로 만든 PNG 를 가져다 쓴다. 앱 안에서 그림을 그리는 기능은 이번 범위가 아니다(편집 대상 범위는 10장 Q6).
- 플러그인과 팩의 결합(팩이 플러그인을 요구하는 것 등), 팩 안 실행 코드·스크립트.
- 보조 펫·다중 펫 창 구조(백로그 "보조 펫", `docs/progress/backlog.md`). 형식은 이를 막지 않게만 한다.
- 새 애니메이션 상태 이름 정의(`celebrate`·`typing` 등은 ADR-0002 `fallbacks` 로 이미 다룬다).
- 설치 파일 구조(M8). 단, 5장은 설치본이 읽기 전용이라는 전제를 둔다.

## 3. 형식 후보 비교

| 구분 | (A) 폴더만 유지 | (B) 단일 파일 컨테이너 + 개발용 폴더 병행 | (C) 폴더 + 파생 팩(`extends`) | (D) B + C 조합 |
|---|---|---|---|---|
| 개요 | 지금처럼 `characters/<id>/`. 내보내기·가져오기는 폴더 통째 복사 | `.deskpack`(zip) 한 파일로 내보내고 가져온다. 설치된 팩은 풀린 폴더로 둔다. 개발 중에는 폴더 그대로 쓴다 | 사용자 팩이 `extends: "<원본 id>"` 로 원본의 그림·크기·상태를 이어받고 voice·interactions·메타·일부 상태 설정만 덮어쓴다. 그림은 복사하지 않는다 | 사용자 팩은 파생(C)으로 만들 수 있고, 공유는 `.deskpack`(B)로 한다 |
| 장점 | 구현 없음. 위험 추가 없음. 기존 도구와 그대로 맞음 | 한 파일로 주고받기 쉽다. 메타·미리보기를 앞에서 읽어 확인 대화상자에 쓸 수 있다. 사용자에게 "팩 = 파일"로 보인다 | 어투만 바꾸는 흔한 경우 매우 작다(JSON 두 개). 그림 중복이 없다. 복제가 즉시이고 디스크를 안 쓴다. 가져올 때 신뢰할 이미지가 줄어든다 | B와 C의 장점 모두. 어투만 바꾼 팩은 수 KB 파일로 공유된다 |
| 단점 | 사용자는 파일 탐색기로 폴더를 옮겨야 한다. 압축·메타 확인 없음. 폴더 통째 복사는 링크·거대 파일 같은 위험을 사용자에게 떠넘긴다 | zip 읽기·쓰기 구현이 필요하다(새 의존성 금지와 충돌, 6장). zip 특유의 공격면(경로 이탈·폭탄)이 생긴다 | 원본이 지워지거나 바뀌면 파생이 깨진다(의존성). 파생을 내보내면 원본을 같이 보내야 하는지 정해야 한다. 상속 규칙·충돌 규칙이 복잡하다. 의미 변경 시 버전 정책에 영향 | 둘의 복잡도가 합쳐진다. 파생을 내보낼 때 "원본 필요" 처리가 가장 어렵다 |
| 구현 규모 | 0 (S) | M–L (zip 구현 포함, 안전 추출 라이브러리가 핵심) | M (해석기, 병합 규칙, 순환·삭제 처리) | L |
| 보안 위험 | 낮음(새 경로 없음). 단 가져오기 경로가 없으므로 사용자가 폴더를 직접 넣을 때는 현행 로더 검사에만 의존 | **가장 크다**: zip-slip, 압축 폭탄, 심볼릭 링크, 중복·겹치는 항목. 대응은 6장 | 낮음–중간: 원본 id 해석 오류, 사용자 팩이 내장 팩을 사칭해 덮어쓰는 경로(id 충돌 규칙으로 막는다), 순환 | B의 위험 + C의 해석 위험 |
| 사용자 체감 | "파일을 옮기세요." 비개발자에게 불편 | "파일을 열면 끝." 공유에 좋다 | "내 말투 버전 만들기"가 가벼움. 원본이 사라지면 곤란 | 가장 자연스러우나 처음 구현량이 크다 |

### 추천

**단계적 D: 먼저 C(복제 편집의 기본 방식)를 만들고, B(.deskpack)는 그다음 단계로 둔다.** 이유는 다음과 같다.

1. 사용자의 가장 흔한 요구는 "어투·상호작용을 내 취향으로 고치기"(D-035의 근거)다. 이때 그림은 바뀌지 않으므로 그림을 복사하는 전체 복제는 낭비이고, 파생 팩이 가장 가볍다. 그림까지 가진 완전한 팩이 필요하면 전체 복제를 선택지로 둔다(10장 Q4).
2. zip 구현은 이 ADR 에서 가장 위험한 부분이다. 폴더 형식 기반 편집기(위 1·2·3 task)를 먼저 끝내면 보안 리뷰를 내보내기/가져오기 한 곳에 집중할 수 있다.
3. 파생 팩의 "원본 없음" 문제는 `extends` 가 내장 팩만 가리키게 제한하면 크게 줄어든다(10장 Q2). 내장 팩은 앱과 함께 있어 사라지지 않는다.

위 추천이 채택돼도 형식 자체(매니페스트 확장 필드)는 A·B·C·D 어느 쪽이든 같게 설계해 둔다. 컨테이너를 나중에 붙이는 일이 매니페스트를 바꾸지 않도록 하기 위해서다.

## 4. 에셋 구성 정의

### 4-1. 폴더 레이아웃

```
characters/<id>/            (내장)   userData/characters/<id>/   (사용자 팩)
├─ manifest.json            필수
├─ voice.json               선택 (매니페스트 voice 가 가리킴)
├─ interactions.json        선택 (매니페스트 interactions 가 가리킴)
├─ preview.png              선택 (매니페스트 preview 가 가리킴)
├─ sounds/                  선택, 후속 단계 (10장 Q10)
│   └─ pat.ogg
└─ sheets/
    ├─ idle.png
    └─ ...
```

`.deskpack` 은 위 구조를 `<id>/` 접두 없이 루트에 그대로 담은 zip 이다(채택될 때).

### 4-2. 매니페스트 확장 필드

기존 필드(ADR-0002)는 모두 그대로다. 아래는 추가하는 **선택** 필드이며 필드 추가이므로 `apiVersion` 은 `"1"` 을 유지한다(ADR-0002 버전 정책).

| 필드 | 형식 | 필수 | 제약·의미 (후보 포함) |
|---|---|---|---|
| `meta.author` | `string` | 아니요 | 제작자 표시. 최대 80 코드 포인트(후보), 제어문자 금지 |
| `meta.version` | `string` | 아니요 | 팩 자체의 버전(예: `"1.2.0"`). 앱 `apiVersion` 과 무관. 최대 32자(후보) |
| `meta.license` | `string` | 아니요 | 라이선스 표시 문자열(예: `"CC-BY-4.0"`, `"All rights reserved"`). 최대 80자(후보). 앱은 법적 판단을 하지 않고 표시만 한다 |
| `meta.description` | `string` | 아니요 | 설명. 최대 500 코드 포인트(후보) |
| `meta.createdWith` | `string` | 아니요 | 만든 도구(예: `"deskpet-editor"`). 표시용 |
| `preview` | `string` | 아니요 | 목록·확인 대화상자에 쓸 미리보기 PNG 의 팩 상대 경로. `sheet` 와 같은 경로 규칙. 크기 후보: 최대 256×256 픽셀, 512 KiB. 없으면 `idle` 첫 프레임을 쓴다 |
| `extends` | `string` | 아니요 | 이어받을 팩 id. 4-3. `extends` 가 있으면 `cellSize`·`anchor`·`states`·`scale` 은 선택이 된다 |
| `voice` | `string` | 아니요 | 이미 있다(D-029). 파일 형식도 그대로(`{"version":1,"templates":{…}}`) |
| `interactions` | `string` | 아니요 | 상호작용 목록 파일의 팩 상대 경로. 4-4 |
| `sounds` | `Record<string,string>` | 아니요 | 이름 → 오디오 파일 경로. 후속 단계, 10장 Q10. 첫 구현에서는 만들지 않는다 |

`name` 은 이미 필수다. `meta` 를 중첩 객체로 둔 이유는 최상위 이름 공간을 아끼고, 앞으로 메타를 더해도 충돌하지 않게 하기 위해서다. 최상위 `author` 처럼 평평하게 둘 수도 있다(10장 Q3 하위 선택).

예시(파생 팩):

```json
{
  "id": "wolf-maid-casual",
  "name": "늑대 메이드 (편한 말투)",
  "apiVersion": "1",
  "extends": "wolf-maid",
  "meta": { "author": "me", "version": "1.0.0", "license": "All rights reserved",
            "description": "wolf-maid 의 그림에 반말 어투를 입힌 버전" },
  "preview": "preview.png",
  "voice": "voice.json",
  "interactions": "interactions.json"
}
```

### 4-3. `extends` 의 의미 (후보 규칙)

| 항목 | 규칙 |
|---|---|
| 이어받는 것 | `cellSize`·`anchor`·`scale`·`states`(시트 포함)·`fallbacks`. 기본값으로 원본 값을 쓴다 |
| 덮어쓸 수 있는 것 | `name`·`meta`·`preview`·`voice`·`interactions`, 상태의 **재생 설정**(`fps`·`loop`·`next`)과 `fallbacks`, `scale`. 지정한 키만 덮어쓰고 나머지는 원본을 쓴다 |
| 덮어쓸 수 없는 것 | `sheet`·`frames`·`cellSize`·`anchor`. 그림이 바뀌면 파생이 아니라 완전한 팩이어야 한다. 이를 막아 "그림은 복사하지 않는다"를 유지하고 시트 치수 검증도 원본 것만 쓴다 |
| 깊이 | 1단계만. `extends` 가 가리키는 팩은 `extends` 를 가질 수 없다(순환·긴 체인 차단) |
| 대상 | 후보: 내장 팩 id 만(10장 Q2). 사용자 팩끼리도 허용하면 삭제·내보내기 처리가 복잡해진다 |
| 원본 없음 | 원본이 없으면 그 팩은 `invalid`(목록에 "원본 없음"으로 표시, 선택 불가). 조용히 다른 팩으로 대체하지 않는다 |
| 원본 버전 고정 | 원본이 앱 업데이트로 바뀔 수 있다. 상태 이름이 바뀌어 `next` 가 깨지면 로드 단계 검증이 실패해 `invalid` 로 표시한다. 원본의 `meta.version` 을 `extendsVersion`(선택)으로 기록해 불일치 때 경고만 하는 안은 10장 Q2에 포함한다 |

해석은 로더가 한다. 병합 결과(합성 매니페스트)를 만든 뒤 기존 `validateCharacterManifest` 에 넣고 같은 로드 검사를 한다. 병합 결과는 디스크에 쓰지 않는다.

### 4-4. 상호작용 파일 (`interactions.json`)

```json
{
  "version": 1,
  "items": [
    { "id": "pat", "label": "쓰다듬기", "mood": "happy", "bubble": true,
      "lines": ["헤헤, 기분 좋아요!", "더 해 주세요!"] },
    { "id": "scare", "label": "놀래키기", "mood": "surprised", "bubble": false, "lines": [] }
  ],
  "hidden": ["talk"]
}
```

- `items[].id`: 영문 소문자·숫자·`-`(후보 `^[a-z0-9][a-z0-9-]{0,31}$`). 목록 안에서 유일.
- `label`: 메뉴 표시. 최대 20 코드 포인트(후보).
- `mood`: `PetEvent.mood` 허용 값(`packages/core/src/contracts.ts`).
- `bubble`: 말풍선 사용 여부. `false` 면 표정만 바꾼다(D-035).
- `lines`: 대사. 누를 때마다 하나씩 순환. 항목당 최대 16줄(후보), 줄당 120 코드 포인트(후보. 말풍선 문구 상한 120과 맞춘다). 쓴 그대로 나오고 어투 템플릿을 거치지 않는다(D-035).
- `hidden`: 기본 항목 중 숨길 id. 파생 팩에서 원본의 항목을 숨기는 용도다. 항목 수 최대 32(후보).
- 현재 `BUILTIN_INTERACTIONS`(`apps/desktop/src/main/pet-menu.ts`)는 "기본 항목"이 된다. 팩에 `interactions` 가 없으면 이 기본 목록을 쓴다.

### 4-5. 파일 종류와 확장자 허용 목록 (후보)

| 종류 | 허용 확장자 | 비고 |
|---|---|---|
| 매니페스트·어투·상호작용 | `.json` (이름 고정: `manifest.json` 필수, 나머지는 매니페스트가 가리킨 파일) | UTF-8, BOM 허용 여부는 구현 때 정함 |
| 시트·미리보기 | `.png` 만 | 현행 로더가 PNG 만 읽는다(IHDR 검사). GIF·APNG·WebP·SVG 는 거부 |
| 사운드(후속) | `.ogg`, `.wav` 중 택일 | 10장 Q10 |
| 그 밖 | 모두 거부 | `README.md`·`LICENSE.txt` 같은 텍스트를 허용할지는 미결(후보: 허용하지 않고 라이선스는 `meta.license` 한 줄) |

### 4-6. 크기·개수 상한 후보

기존 한도는 그대로 유지하고(시트 8 MiB, 시트 16,777,216 픽셀, 팩 시트 합계 64 MiB, voice.json 64 KiB), 신뢰할 수 없는 입력용으로 아래를 **후보**로 더한다. 근거는 현재 실사용량(팩 시트 합계 수십 KB, 파일 11개 안팎)에 비해 몇 배~수십 배 여유를 둔 것이다.

| 대상 | 상한 후보 |
|---|---|
| 팩당 파일 수 | 64 |
| 팩 압축 해제 총량 | 80 MiB (시트 합계 64 MiB + 여유) |
| 컨테이너(.deskpack) 파일 크기 | 40 MiB |
| 파일 하나 | PNG 8 MiB(기존), JSON 256 KiB(voice.json 은 기존 64 KiB 유지) |
| 상태 수 | 32 |
| 상태당 `frames` | 64 |
| `cellSize` 한 변 | 1024 (기존 한도는 픽셀 총량뿐) |
| 압축률 | 항목 하나의 (해제 크기 ÷ 압축 크기) 100 초과 시 거부. PNG 는 이미 압축돼 정상 값은 낮다 |
| JSON 깊이 / 키 수 | 깊이 8 / 객체당 키 256 (`__proto__` 키는 거부) |
| 문자열 | `id` 48 이하, 팩 상대 경로 160 이하, 구성 요소 64 이하 |

### 4-7. `id` 와 이름 규칙 (후보)

- `id`: `^[a-z0-9][a-z0-9-]{0,47}$`. 현재 4개 id(`placeholder`·`placeholder-alt`·`wolf-maid`·`mochi`)는 모두 통과한다. 지금의 `validCharacterId` 보다 엄격하다. 대소문자만 다른 id 가 Windows 에서 같은 폴더가 되는 문제, 예약 이름(`con`·`nul` 등), 끝의 점·공백을 한꺼번에 막는다. Windows 예약 이름은 별도 목록으로 거부한다.
- 폴더 이름 = `id` (현행 `manifest.id !== id` 검사 유지).
- `name`·`meta.*`: 제어문자와 방향 제어 문자(U+202A–U+202E, U+2066–U+2069) 거부, 길이 상한. 앱은 항상 `textContent` 로 표시하고 마크업으로 해석하지 않는다.

### 4-8. `apiVersion` 정책

- 필드 추가(이 장의 모든 선택 필드)는 `"1"` 을 유지한다. 모르는 필드는 계속 무시한다.
- 기존 필드의 의미나 형식이 바뀌면 `"2"` 로 올린다. 예: `states` 의 재해석, `extends` 를 필수로 만드는 변경, `meta` 구조 변경.
- `"2"` 를 만들면 ADR-0002 와 기획안 5-5 에 따라 코어는 현재와 직전 버전을 함께 읽는다. 앱은 `"1"` 팩을 읽을 때 메모리에서 `"2"` 모양으로 변환하는 마이그레이션 함수를 가진다. 디스크의 사용자 팩을 자동으로 고쳐 쓰지 않고, 편집기가 저장할 때 새 버전으로 쓴다(저장 전 `.bak` 한 벌을 남기는 안은 구현 때 정한다).
- 지금 단계에서 `"2"` 가 필요한 변경은 없다고 본다. `interactions` 파일의 `version`·`voice.json` 의 `version` 은 매니페스트 `apiVersion` 과 별개로 파일마다 올린다.

## 5. 설치 위치와 우선순위

| 구분 | 내장 팩 | 사용자 팩 |
|---|---|---|
| 위치 | 앱 리소스의 `characters/` (개발 중에는 저장소의 `characters/`, 현재 `apps/desktop/src/main/index.ts` 의 `charactersDir`) | `app.getPath("userData")` 아래 `characters/<id>/` |
| 쓰기 | 읽기 전용. 앱은 쓰지 않는다 | 앱이 쓴다(편집기·가져오기·복제) |
| 삭제 | 불가 | 가능(확인 후) |
| 편집 | 불가. "복제해서 편집"만 | 가능 |

규칙(모두 후보. 10장의 해당 질문에서 확정):

1. **id 충돌**: 사용자 팩은 내장 팩과 같은 id 를 가질 수 없다. 가져오기에서 충돌하면 거부하지 않고 "다른 id 로 가져오기"(예: `wolf-maid-2`)를 제안한다. 내장 팩을 가리는(shadow) 동작은 만들지 않는다. 가려지면 사용자가 모르게 내장 팩이 바뀐 것처럼 보이고, 악성 팩이 신뢰하던 이름으로 위장할 수 있다.
2. **사용자 팩끼리 id 충돌**: 같은 id 가 이미 있으면 가져오기 때 "덮어쓰기 / 다른 id / 취소"를 묻는다. 덮어쓰기는 기존 폴더를 `.trash`(후보)로 옮긴 뒤 새 폴더를 놓고, 성공하면 휴지통을 비운다. 설치가 실패하면 기존 팩이 그대로 남는다.
3. **선택 영속화**: 선택한 캐릭터 id 를 `settings.json` 의 새 필드(후보 `characterId`)에 저장한다(`apps/desktop/src/main/settings.ts` 의 `parseSettings` 패턴). 시작 인자 `--character=` 가 있으면 인자가 우선(개발·e2e 용)이다. 저장된 id 의 팩이 없거나 `invalid` 면 `placeholder` 로 대체하고 알림 한 번 남긴다. 대체 팩 `placeholder` 는 내장 팩이므로 항상 있다.
4. **복제**: 내장 팩을 복제하면 기본은 파생 팩(`extends` + 어투·상호작용 사본, 그림 없음)이다. "그림까지 복사"는 별도 항목이다(10장 Q4). 새 id 는 `<원본>-copy`, 충돌하면 `-2`, `-3`…
5. **삭제**: 사용자 팩만. 현재 선택된 팩을 삭제하면 `placeholder` 로 돌아간다. 다른 사용자 팩이 `extends` 로 가리키는 팩이면(사용자 팩끼리의 `extends` 를 허용하는 경우) 삭제를 막고 이유를 보여 준다. 삭제는 폴더 통째 제거이며 되돌릴 수 없다는 확인을 거친다.
6. **목록**: 내장 팩 + 사용자 팩을 한 목록으로 보이되 "내장"/"내 팩" 표시. 로드 실패 팩은 숨기지 않고 이유와 함께 `invalid` 로 보인다(사용자가 삭제할 수 있게).
7. **스캔**: 시작 때 두 폴더를 훑어 `manifest.json` 의 메타(이름·미리보기)만 가볍게 읽는다. 전체 검증과 시트 디코드는 선택·미리보기 시점에 한다(팩이 많아져도 시작이 느려지지 않게). 구체 시점은 구현 때 정한다.

## 6. 보안·신뢰 모델

D-005에 따라 외부에서 온 팩은 신뢰할 수 없는 데이터다. 팩에는 코드가 없으므로 위험은 (1) 파일 시스템에 쓰는 과정(압축 해제), (2) 디코더와 파서에 주는 입력의 크기, (3) 사용자에게 보이는 문구로 나뉜다. 팩이 외부 시스템에 쓰는 경로는 만들지 않는다(기획안 3장 원칙 3, `CLAUDE.md` 리뷰 기준과 같은 방향). 가져오기는 사용자가 누른 버튼과 파일 선택 대화상자로만 시작하며, 파일 연결·프로토콜 핸들러·드래그 앤 드롭 자동 설치·URL 다운로드는 만들지 않는다.

### 6-1. 위협과 대응

| # | 위협 | 대응 |
|---|---|---|
| T1 | zip-slip: `../`·절대 경로·드라이브 문자·UNC·`\` 가 든 항목 이름으로 `userData` 밖에 쓴다 | 항목 이름은 쓰지 않는다. 허용 목록(`manifest.json` 과 매니페스트가 가리킨 경로)에 있는 항목만 읽고, 디스크에 쓰는 이름은 **앱이 검증된 매니페스트에서 계산한 경로**로만 정한다. 이름은 현행 경로 규칙(`isSafePackRelativePath` 와 같은 규칙: 구성 요소 `.`/`..` 거부, 제어문자·`\`·`:` 거부, 끝의 점/공백 거부)을 통과해야 한다. 쓰기 직전 `realpath` 가 아닌 **정규화한 최종 경로가 스테이징 폴더 아래인지** 확인한다. 스테이징 폴더 자체는 앱이 만든다 |
| T2 | 압축 폭탄: 작은 파일이 해제 때 거대해진다, 항목 수를 폭증시킨다, 겹치는 항목(overlapping entries)·재귀 zip | 해제 전에 중앙 디렉터리의 항목 수·선언 크기 합을 4-6의 상한과 비교한다. 해제 중에는 **선언 크기를 믿지 않고** 실제 출력 바이트를 세어 항목·총량 상한을 넘으면 중단한다(`inflate` 출력 한도). 항목 간 압축 데이터 범위가 겹치면 거부. 항목 압축률 100 초과 거부. 허용 목록 밖 항목(안의 zip 포함)은 읽지 않고 거부 사유로 센다 |
| T3 | 이미지 폭탄: 작은 PNG 가 거대한 픽셀 수로 디코드되어 메모리를 먹는다 | **디코드 전에** IHDR 를 직접 읽어 폭·높이·픽셀 수(기존 16,777,216)·`cellSize × frames` 일치·`cellSize` 한 변 1024(후보)를 확인한다(현행 `loadCharacter` 와 같다). 압축 해제 크기를 IHDR 로 계산해 zlib 출력 한도로 쓴다(ADR-0002 구현 한도 절). 디코드(`nativeImage`)는 이 검사를 모두 통과한 뒤에만 한다. 현재 `nativeImage` 가 main 프로세스에서 디코드한다는 점이 남는 위험이다(OS 이미지 디코더의 취약점은 이 ADR 이 막지 못한다. 완화: 입력 크기 제한, 디코드 실패는 팩 거부) |
| T4 | JSON 폭탄·프로토타입 오염: 깊은 중첩, 거대한 배열, `__proto__` | JSON 은 파일 크기 상한(256 KiB 후보, voice 64 KiB) 안에서 파싱하고, 깊이 8·키 수 상한을 파싱 후 재귀로 확인한다. `__proto__`·`constructor`·`prototype` 키는 거부한다. 이미 `settings.ts` 가 `Object.fromEntries` 로 프로토타입 오염을 피하는 선례가 있다. 검증을 통과한 값만 새 객체로 **복사해** 쓴다(원본 객체를 그대로 보관하지 않는다) |
| T5 | 심볼릭 링크·junction·하드 링크: zip 항목이 링크이거나 설치된 폴더에 링크가 있다 | zip 의 외부 속성이 심볼릭 링크(Unix 모드 `0120000`)이거나 Windows 재분석 지점 속성이면 거부한다. 우리가 쓰는 파일은 앱이 일반 파일로 새로 만들므로 링크가 생길 수 없다. 설치된 사용자 팩 폴더를 읽을 때는 기존 `realpath` 검사를 유지한다(사용자가 폴더에 직접 링크를 넣는 경우) |
| T6 | 실행 파일·스크립트·이중 확장자: `a.png.exe`, `.lnk`, `.bat`, `.js`, `.dll` | 4-5의 확장자 **허용 목록**만 받는다. 목록 밖은 이름이 어떻든 거부한다. 이중 확장자(`x.png.exe`)는 마지막 확장자로 판정하되, 구성 요소에 점이 둘 이상이거나 허용 확장자가 이름 중간에 들어간 경우도 거부한다. 허용 파일도 **내용으로 재확인**한다(`.png` 는 PNG 시그니처, `.json` 은 UTF-8 JSON). 저장한 파일은 실행 권한이 없는 일반 파일이며 앱은 팩 파일을 실행하지 않는다 |
| T7 | 이름·id 로 인한 파일 시스템 혼란: 예약 이름(`CON`·`NUL`), 대소문자 중복, NTFS 대체 데이터 스트림(`a.png:evil`), 유니코드 정규화 중복 | 4-7의 id 규칙(소문자 ASCII 만). 항목 이름 중복은 대소문자 무시로 판정해 거부. `:` 는 이미 경로 규칙에서 거부. 허용 파일 이름은 `manifest.json` 이 가리킨 경로와 정확히 같은 것만 |
| T8 | 사용자가 속아서 설치: 위조된 제작자·라이선스, 그럴듯한 이름 | 가져오기 때 **main 프로세스가 띄우는 확인 대화상자**에서 이름·id·제작자·버전·라이선스·설명·미리보기·파일 수·크기·`extends` 대상·id 충돌 여부를 보여 준다. 메타는 주장일 뿐이라는 문구를 붙이고 서명은 하지 않는다(비목표). 확인 없이 설치하는 경로는 없다. 대화상자는 렌더러가 아니라 main 이 만들어 팩 내용이 대화상자를 조작할 수 없게 한다 |
| T9 | 어투 문구가 알림 의미를 바꾼다: 예) `failed` 어투에 "성공했어요" 를 넣어 실패를 가린다 | 어투 템플릿은 "문장 꾸미기"이지만 사용자에게 보이는 의미를 바꿀 수 있다. 완화: 확인 대화상자에서 각 종류의 첫 변형 한 줄씩을 보여 준다. 말풍선의 표정(`mood`)과 우선순위는 이벤트가 정하고 팩이 바꿀 수 없다. 잔여 위험으로 인정하고 사용자가 믿는 팩만 쓰도록 한다 |
| T10 | 표시 경로 주입: 팩 문자열이 HTML/스크립트로 해석된다 | 팩에서 온 텍스트는 `textContent` 로만 넣는다(말풍선은 이미 그렇다, `apps/desktop/src/renderer/bubble.ts`). `innerHTML` 로 팩 문자열을 쓰지 않는다는 규칙을 편집기에 적용한다. 설정 창 CSP(`apps/desktop/src/renderer/settings.html`)는 `img-src` 가 없어 미리보기 이미지를 표시하려면 `img-src data:` 를 더해야 한다. 이때 `default-src 'none'; script-src 'self'` 는 유지한다 |
| T11 | 부분 설치·중간 실패로 깨진 팩이 남는다 | 원자적 설치: (1) `userData/characters/.staging-<난수>/` 에 해제·정규화·쓰기, (2) 스테이징 폴더에서 로더와 같은 전체 검증(매니페스트·시트 치수·voice 파싱) 수행, (3) 통과하면 최종 `<id>/` 로 `rename`(같은 볼륨), (4) 어느 단계든 실패하면 스테이징 폴더를 지우고 아무것도 남기지 않는다. 시작 때 남아 있는 `.staging-*` 는 지운다. `.staging-*` 폴더는 팩 목록에서 무시한다(`.` 시작 id 는 4-7 규칙으로 불가) |
| T12 | 쓰기 위치 우회: 가져오기가 `userData` 밖을 건드린다 | 팩 관련 쓰기는 `userData/characters/` 아래로 한정하는 단일 함수를 거친다. 기존 `resolveInside` 류 헬퍼(`apps/desktop/src/main/index.ts` 가 `userData` 아래 캡처 경로에 쓰는 데 사용)와 같은 접근이다. 내장 `characters/` 에는 쓰지 않는다 |
| T13 | 내보내기에서의 정보 유출·덮어쓰기 | 내보내기는 사용자가 고른 경로에 **새 파일만** 쓴다(기존 파일 덮어쓰기는 저장 대화상자가 묻는다). 팩에 든 파일만 담고 `settings.json`·토큰·로그는 절대 담지 않는다(허용 목록 기반으로 팩 폴더에서만 읽는다). 로컬 경로가 파일에 새지 않도록 매니페스트에 절대 경로를 쓰지 않는다 |
| T14 | 가져온 뒤 로드 성능 공격(수천 개 팩, 느린 검증) | 사용자 팩 개수 상한(후보 64), 목록 스캔은 메타만 읽기(5장 7). 가져오기·검증은 main 의 비동기 작업이고 한 번에 한 건 |

### 6-2. 편집기 저장 경로의 보안

편집기가 쓰는 값(어투 변형, 상호작용 대사, 메타)도 같은 파서·상한으로 저장 전에 **main 에서** 다시 검증한다. 렌더러의 검증은 사용성 때문이고, 신뢰하지 않는다(ADR-0005: 보안 검사는 모두 main). 저장은 임시 파일에 쓰고 `rename` 하는 원자적 쓰기로 한다(`apps/desktop/src/main/settings.ts` 의 `writeFileSync`/`renameSync` 선례).

### 6-3. zip 처리와 의존성 (사용자 승인 필요)

프로젝트에는 새 의존성 추가 금지 규칙이 있다(`docs/orchestration-guide.md` 의 worker 코드 규칙, "필요하면 ask로 확인"). `.deskpack`(zip)을 읽고 쓰려면 둘 중 하나가 필요하다.

| 선택지 | 내용 | 장점 | 단점·위험 |
|---|---|---|---|
| Z1 | Node 내장 `node:zlib` 로 zip 의 필요한 부분만 직접 구현 | 의존성 0. 지원 범위를 우리가 정해 공격면이 작다(암호화·zip64·다중 디스크·스트리밍 데이터 기술자 모두 거부) | 파서를 직접 짜는 위험(경계 오류). 리뷰·퍼징 테스트 필요. 구현량 중간 |
| Z2 | 검증된 라이브러리 도입(예: 이름만 후보로 `yauzl` 류 읽기 + `yazl`/`archiver` 류 쓰기. 이 문서는 버전·보안 이력을 확인하지 않았다: 미확인) | 구현이 빠르다. 널리 쓰이는 파서는 경계 사례가 이미 많이 다듬어져 있다 | 새 의존성(공급망 위험, 라이브러리 업데이트 관리). 일부 라이브러리는 기본 설정이 위 위협 대응에 충분하지 않아 래퍼가 필요하다(경로 이탈·폭탄 한도). 도입 전 사용자 승인과 보안 이력 확인이 필요하다 |
| Z3 | zip 을 만들지 않고 컨테이너를 쓰지 않음(3장 A·C) | 위험 없음 | 단일 파일 공유가 안 된다 |

**추천: Z1.** 우리 형식은 "허용 목록의 소수 파일, 암호화·압축 방식은 stored/deflate 만"이라 필요한 zip 부분집합이 작다. 직접 구현하면 6-1의 T1·T2·T5(겹침 검출, 실제 출력 바이트 계수, 외부 속성 거부)를 라이브러리의 기본 동작에 기대지 않고 코드로 보장할 수 있다. 그 대신 파서는 작게(중앙 디렉터리 읽기 + `inflateRaw`) 유지하고, 악성 샘플(zip-slip, 폭탄, 겹침, 심볼릭 링크, 암호화, zip64, 중복 이름, CRC 불일치, 잘린 파일) 테스트를 필수로 하며 5단계 보안 리뷰 gate 를 거친다. 첫 단계에서 컨테이너를 만들지 않는 3장 추천과도 맞아, Z1 의 결정은 컨테이너 단계 직전까지 미룰 수 있다.

## 7. 편집 UX

설정 창에 "캐릭터" 탭을 둔다(현재 설정 창은 `apps/desktop/src/renderer/settings.ts`·`settings.html`, 어투 보기는 `voice-panel.ts`). 어투와 상호작용 편집은 이 탭 안의 편집기다(별도 탭으로 쪼개지 않는다. D-035의 "상호작용" 탭 구상은 이 편집기로 흡수된다. 10장 Q9).

### 7-1. 캐릭터 탭 구조

```
┌ 캐릭터 ─────────────────────────────────────────────────────────┐
│ 팩 목록                              │ 선택한 팩                  │
│ ┌──────────────────────────────┐ │ ┌──────┐ 늑대 메이드         │
│ │ ● [img] 늑대 메이드   내장    │ │ │preview│ id: wolf-maid      │
│ │   [img] Placeholder   내장    │ │ └──────┘ 제작자: –          │
│ │   [img] Placeholder Alt 내장  │ │ 버전 1.0 · 라이선스 –       │
│ │   [img] 편한 말투 판  내 팩   │ │ 설명 …                      │
│ │ ! [ ] 깨진 팩    원본 없음    │ │ 상태: 정상 / 경고 1건        │
│ └──────────────────────────────┘ │                              │
│ [가져오기…]                       │ [이 캐릭터 쓰기]  (● = 현재)  │
│                                   │ [복제해서 편집] [내보내기…]    │
│                                   │ [삭제]  (내 팩만)             │
└──────────────────────────────────────────────────────────────────┘
```

- ●는 현재 사용 중인 팩. "이 캐릭터 쓰기"는 선택을 바꾸고 영속화한다(5장 3).
- 내장 팩에는 [편집] 대신 [복제해서 편집]만 있고 [삭제]는 없다. 내 팩에는 [편집]이 있다.
- 깨진 팩(`invalid`)은 이유(예: "원본 팩 wolf-maid 없음")와 [삭제]만 있다.
- [가져오기…]는 파일 선택 대화상자를 열고, 검증 뒤 6-1 T8 의 확인 대화상자를 거친다.
- [내보내기…]는 저장 대화상자를 열고 `.deskpack`(채택 시) 한 파일을 쓴다. 컨테이너 전 단계에는 비활성이거나 폴더 열기로 대체한다.

요구 동작:

- **종류별 변형 행 그 자리 편집.** 종류는 `done`·`waiting`·`failed`·`info`·`deadline`·`reminder`·`alert`(`packages/core/src/voice.ts` 의 `kinds`). 행을 클릭하면 바로 입력 상태가 된다. 종류별로 변형은 최대 8개(`VOICE_MAX_VARIANTS`)이고 추가 버튼은 8개에서 비활성이다. 한 변형은 400 코드 포인트 이하(`VOICE_MAX_VARIANT_CODE_POINTS`)이고 입력 옆에 남은 글자 수를 보인다.
- **결과 미리보기가 즉시 갱신.** 오른쪽에 샘플 슬롯 4개(`task`·`result`·`folder`·`message`)의 입력칸을 두고, 입력이 바뀌면 각 변형이 어떻게 보이는지 곧바로 다시 그린다. 계산은 `renderVoice` 와 같은 규칙(슬롯 한 번만 치환, 공백 정리, 120 코드 포인트 초과 시 119자 + `…`)을 써야 하므로 같은 함수를 공유한다. 렌더러에 복제하지 않고 `@deskpet/core` 를 번들로 써도 되고(`voice-panel.ts` 가 이미 미리보기를 요청하는 `settings:voice-preview` 구조를 확장할 수도 있다), 어느 쪽이든 로직 원본은 하나로 한다.
- **슬롯이 비면 건너뜀 표시.** 샘플 값이 비어 있어 쓸 수 없는 변형은 "건너뜀(slot 이름 비어 있음)"으로 표시한다. 순환 선택에서 실제로 쓰이는 규칙과 같다. 모든 변형이 건너뛰어지면 "이 샘플로는 원래 문구(text)가 그대로 나옴"을 경고로 보인다.
- **경고.** 알 수 없는 슬롯(`{이름}` 이 4종에 없음)과 400자 초과는 행에 경고를 보이고 저장 시 해당 변형은 버려진다는 설명을 붙인다(파서가 버리는 동작과 일치시킨다). 120자 결과 잘림도 미리보기에 표시한다. 저장은 막지 않고 경고를 보여 주되, 파서가 버리는 변형(알 수 없는 슬롯·빈 문자열·400자 초과)이 있으면 저장 확인을 한 번 더 묻는다(후보).
- **슬롯 삽입 버튼.** 슬롯 4개 목록에서 고르면 커서 위치에 `{task}` 를 삽입한다.
- **순서 이동.** 변형은 순환 순서(카운터로 돌아가며 선택)이므로 위/아래 버튼으로 순서를 바꾼다. 끌어다 놓기는 후속(접근성 때문에 버튼이 기본).
- **추가·삭제.** 변형 추가/삭제. 삭제는 즉시 반영되고 취소 버튼으로 편집 전체를 되돌릴 수 있다. 한 종류의 변형을 전부 지우면 그 종류는 어투 없음(보낸 `text` 그대로)이 된다는 안내를 보인다.
- **종류별 기본값으로 되돌리기.** 기본값의 출처는 파생 팩이면 원본 팩의 값, 완전한 팩이면 복제 당시 원본(없으면 비활성)이다. 출처를 확정하지 못하면 이 버튼은 숨긴다. 구현 때 "기본값 출처"를 정해야 한다(10장 Q8 하위 선택).
- **행별 펫에게 보내기.** 그 변형을 현재 샘플 값으로 채워 펫 말풍선으로 보낸다. 기존 `settings:voice-send` 가 하는 일을 변형 단위로 확장한 것이다(저장 전 내용으로도 보낼 수 있어야 한다. 이때 보내는 것은 렌더링된 문구가 아니라 "임시 템플릿으로 렌더링한 결과"이며 팩 파일을 건드리지 않는다).
- **저장 전 변경 표시·취소.** 편집한 것이 저장 전이면 편집기 상단에 "변경 있음"과 변경 개수를 보인다. [취소]는 저장 전 상태로 되돌린다. 창을 닫거나 다른 팩으로 전환할 때 저장하지 않은 변경이 있으면 "저장 / 버리기 / 계속 편집" 확인을 띄운다.
- 저장은 6-2의 규칙(main 에서 재검증, 원자적 쓰기)을 따른다. 저장하면 현재 사용 중인 팩인 경우 어투가 바로 적용된다(`loadVoiceTemplates` 재호출).

### 7-3. 편집기: 상호작용

```
┌ 상호작용 ──────────────────────────────────────── [+ 새 상호작용] ┐
│ ☑ 쓰다듬기  표정(happy ▾)  ☑ 말풍선  ▲▼ [숨김] [삭제]             │
│     대사 (누를 때마다 하나씩 순환)                                 │
│     1 [ 헤헤, 기분 좋아요!            ] 🗑                         │
│     2 [ 더 해 주세요!                 ] 🗑   [+ 대사 추가]          │
│ ☑ 말 걸기   표정(neutral ▾) ☑ 말풍선 ...                          │
│ ☐ 놀래키기  (숨김)                                    [다시 보이기]│
│ [기본 항목으로 되돌리기]                                           │
└────────────────────────────────────────────────────────────────────┘
```

- 항목마다 라벨, 표정(`mood`), 말풍선 사용 여부, 대사 여러 줄을 편집한다(D-035).
- 새 항목 추가, 기본 항목 숨기기(`hidden`), 사용자가 만든 항목 삭제. 기본 항목은 삭제가 아니라 숨기기다.
- 말풍선을 끄면 표정만 바뀐다. 대사는 어투 템플릿을 거치지 않고 쓴 그대로 나온다(D-035).
- 대사 줄 수·길이·항목 수는 4-4의 상한을 따르고 같은 방식으로 경고한다.
- 항목 순서는 메뉴 순서가 된다.
- 말풍선을 켠 항목에 대사가 0줄이면 경고(켜 놓고 할 말이 없음).
- 같은 id 의 연타 제한(`INTERACTION_MIN_INTERVAL_MS`, `apps/desktop/src/main/pet-menu.ts`)은 유지한다.
- 행별 [펫에게 보내기]도 어투 편집기와 같은 방식으로 제공한다.

### 7-4. 메타·그림 편집 (범위)

메타(이름·제작자·버전·라이선스·설명)는 폼으로 편집한다. 미리보기 이미지는 "원본의 `idle` 첫 프레임에서 자동"이 기본이고 직접 PNG 를 고르는 기능은 후속이다. 그림(시트) 교체는 이 ADR 의 범위 밖이다(10장 Q6).

## 8. 마이그레이션과 호환

### 8-1. 기존 폴더·voice.json

- `characters/<id>/manifest.json` 과 `voice.json` 은 **그대로 유효하다.** 새 필드는 모두 선택이고 `apiVersion` 은 `"1"` 이다. 현재 팩 4개(실질 3개)를 바꿀 필요가 없다.
- `tools/sprite-pipeline` 이 만든 `manifest.json` 은 새 필드 없이도 유효하다. 팩 도구가 `voice` 를 보존하지 않는 문제(1-1)는 이 ADR 구현 task 에서 확인하고 필요하면 도구 명세에 `voice` 통과 필드를 추가한다(도구는 이번 문서의 변경 대상이 아니다).
- 로더가 알 수 없는 필드를 무시하는 현재 동작을 유지하므로, 이 ADR 이전 버전의 앱도 새 필드가 든 팩을 읽을 수 있다(새 기능만 무시). 다만 `extends` 만 있고 `states` 가 없는 파생 팩은 옛 앱에서 `states must be an object` 로 거부된다. 새 앱에서 만든 파생 팩은 옛 앱과 호환되지 않는다는 점을 가져오기 확인 대화상자에 명시한다(후보. 옛 앱을 쓸 일은 개인용 단계에서 낮다).

### 8-2. D-035 의 `settings.json` interactions → 사용자 팩

D-035 는 구현 전이므로(1-5) **마이그레이션이 필요 없게 하는 것이 최선**이다: D-035 를 구현할 때 처음부터 팩 형식 위에 만들어 settings.json 에 `interactions` 를 쓰지 않는다(추천, 10장 Q9). 이미 settings.json 에 `interactions` 가 생긴 뒤라면 아래 1회 규칙을 쓴다.

1. 새 앱 시작 때 `settings.json` 에 `interactions` 가 있고 `settings.json` 의 `migrations.interactionsToPack`(후보 키)이 없으면 실행한다.
2. 현재 선택된 팩이 내장이면 그 팩을 `extends` 하는 사용자 팩 `<원본>-mine`(충돌 시 번호)을 만들고, 값을 `interactions.json` 으로 옮긴다. 선택된 팩이 사용자 팩이면 그 팩의 `interactions.json` 에 쓴다(이미 있으면 덮어쓰지 않고 `-mine` 파생 팩으로 만든다).
3. 새 팩을 만들고 검증이 통과하면(6-1 T11 과 같은 원자적 설치) `settings.json` 에서 `interactions` 를 지우고 `migrations.interactionsToPack` 을 기록한다. 지우기 전 `settings.json.bak` 한 벌을 남긴다. 어느 단계든 실패하면 `settings.json` 은 그대로 두고 다음 시작에 다시 시도하며 경고를 남긴다.
4. 사용자에게 한 번 알림을 보인다("상호작용 설정을 '<이름>' 팩으로 옮겼어요").

**동작 차이 주의(미결, 10장 Q9):** D-035 는 "캐릭터를 바꿔도 유지된다"고 했다. 팩 안에 두면 캐릭터를 바꿀 때 상호작용도 팩 단위로 바뀐다. 이는 D-036 이 말한 "성격을 팩 단위로 묶기"(D-029 와 같은 철학)와 일치하지만 D-035 의 동작을 바꾼다. 둘을 모두 만족하려면 "팩에 interactions 가 없으면 사용자 공통 목록(settings.json)을 쓴다"는 계층을 둘 수 있다. 이 계층은 복잡해서 추천하지 않는다.
