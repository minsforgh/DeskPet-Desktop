# reminders 설정 화면 설계 (M6 기준 13)

> 상태: **승인 (2026-10-09, 사용자).** 기준 14 구현 task 의 명세다.
> 입력: M5 기준 16 H 미충족(D-038), 백로그 2026-10-07(①24시간제 착각 ②지난 시각 안내 없음 ③다음 알림 표시 ④형식 오류 표시 ⑤저장 안 하면 미적용), 2026-10-08 사용자 피드백(시각 드롭다운, 알림별 저장). 결정: 2026-10-09 사용자(위치·분 입력·우선순위).

## 1. 지금 무엇이 헷갈리나

reminders 에는 전용 화면이 없다. [플러그인] 탭이 JSON 스키마로 자동 생성한 폼을 그린다(`apps/desktop/src/renderer/settings.ts` 의 `objectRow`·`flatArrayControl`). 그래서 사용자가

- `ID` 를 직접 지어야 하고,
- 시각을 `HH:MM` 문자열로 써야 하며(`11:28` 을 밤 11시로 착각),
- 요일을 숫자 0–6 체크박스로 고르고,
- 우선순위를 영어 `low/normal/high/urgent` 로 고르며,
- 맨 아래 플러그인 [저장] 하나로 모든 규칙을 한 번에 저장한다(어느 알림이 저장됐는지 알기 어려움).

## 2. 결정 사항

| 항목 | 결정 |
|---|---|
| 위치 | 설정 창 최상위 **[알림] 탭**. 탭 순서 [일반][캐릭터][알림][플러그인]. [플러그인] 탭의 reminders 항목에는 켜기/끄기·권한만 남기고 "규칙은 [알림] 탭에서 편집" 링크를 둔다 |
| 단위 | 알림 하나 = **카드 하나**. 카드마다 자기 [저장]·[삭제]·[▶ 미리보기] |
| 시각 | `(오전 ▾) (11 ▾)시 (00 ▴▾)분` — 오전/오후 드롭다운, 시 드롭다운(1–12), 분 숫자 입력(0–59, ▲▼, 두 자리 표시). 저장 형식은 지금처럼 24시간제 `HH:MM` 문자열(플러그인·스키마 변경 없음) |
| 요일 | `[일][월][화][수][목][금][토]` 토글 칩 + 빠른 선택 `매일 · 평일 · 주말`. 아무것도 안 고르면 "매일"(현재 규칙과 같음) |
| 우선순위 | 체크박스 하나 **"방해 금지 중에도 알림"**. 끄면 보통(normal, 저장 시 필드 생략), 켜면 긴급(urgent). 기존 규칙의 `low`·`high` 값은 보존하고 카드에 "기타 우선순위(low/high) 유지 중" 으로 표시만 한다(체크를 바꾸면 그때 normal/urgent 로 바뀜) |
| ID | 사용자에게 보이지 않는다. 새 카드는 앱이 `r-<시각 기반 36진수>` 로 만들고, 기존 규칙의 ID 는 그대로 둔다 |

## 3. 화면

```
[일반][캐릭터][알림][플러그인]

알림                                              [+ 새 알림]
reminders 플러그인이 꺼져 있어요 [켜기]      ← 꺼져 있을 때만

┌ 새 알림 · 아직 저장 안 됨 ─────────────────────────────┐
│ (오후 ▾) (11 ▾)시 (00 ▴▾)분                            │
│ [일][월][화][수][목][금][토]   매일 · 평일 · 주말        │
│ 문구 [ 학습 종료 누르기                        ] 9/120   │
│ ☐ 방해 금지 중에도 알림                                  │
│ 다음 알림: 오늘 오후 11:00                               │
│                           [▶ 미리보기] [취소] [저장]     │
└──────────────────────────────────────────────────────────┘
┌ ● 변경 있음 ──────────────────────────────────────────┐
│ (오전 ▾) (9 ▾)시 (30 ▴▾)분   [월][화][수][목][금]        │
│ 문구 [ 회의 준비                               ]         │
│ 다음 알림: 내일 오전 9:30  (오늘 9:30 은 이미 지났어요)   │
│                       [▶ 미리보기] [되돌리기] [저장]      │
└──────────────────────────────────────────────────────────┘
┌ 저장됨 ───────────────────────────────────────────────┐
│ …                                        [▶ 미리보기] [삭제] │
└──────────────────────────────────────────────────────────┘
```

## 4. 동작

1. **[+ 새 알림]**: 목록 맨 위에 빈 카드를 만든다(기본 시각 = 다음 정각, 요일 없음 = 매일, 문구 비어 있음, 문구 칸에 포커스). 헤더는 "새 알림 · 아직 저장 안 됨". [저장]을 눌러야 확정된다. 저장 전 [취소]는 카드를 바로 없앤다(확인 없음).
2. **카드별 저장**: [저장]은 그 카드 하나만 반영한다. 요청은 "마지막으로 저장된 규칙 목록에서 이 카드만 바꾸거나 추가한 목록"이며, 다른 카드의 저장 안 된 편집은 그대로 화면에 남는다. main 이 기존처럼 전체 규칙을 다시 검증(`validatePluginInput` + 플러그인 `validateReminderRules`)하고 원자적으로 저장한 뒤 플러그인이 즉시 다시 등록한다. 성공하면 헤더가 "저장됨"(잠깐 "저장했어요" 표시), 실패하면 그 카드에 이유를 보인다.
3. **변경 표시**: 저장된 값과 다르면 헤더에 "● 변경 있음", 버튼은 [되돌리기]·[저장]. 같으면 "저장됨", 버튼은 [삭제]. 창을 닫을 때 저장 안 된 카드가 있으면 기존 이탈 확인(설정 창 dirty 경로)으로 "저장하지 않은 알림 N개" 를 묻는다.
4. **삭제**: 저장된 카드의 [삭제]는 카드 안에서 "이 알림을 삭제할까요? [삭제] [취소]" 로 한 번 묻고, 확인하면 그 규칙만 뺀 목록을 바로 저장한다.
5. **다음 알림**: 각 카드 아래에 기존 `describeRules`·`nextOccurrence`(플러그인 schedule 모듈 공유)로 "다음 알림: 오늘 오후 11:00 / 내일 / 수요일 …" 을 보인다. 표시는 **오전/오후 12시간제**로 바꾼다. 오늘 시각이 이미 지났으면 "(오늘 HH:MM 은 이미 지났어요)" 를 덧붙인다(백로그 ②). 편집 중에는 저장 전 값으로 미리 계산해 보이되 "저장하면" 을 앞에 붙인다.
6. **형식 오류**: 기존 settings.json 에 형식이 깨진 규칙이 있으면 카드로 보이고 "이 알림은 형식이 맞지 않아 울리지 않아요: <이유>" 와 [삭제]를 보인다(백로그 ④). 고쳐서 저장할 수 있게 원래 값을 최대한 채운다.
7. **[▶ 미리보기]**: 저장하지 않고 지금 값(문구, 어투 포함)으로 펫 말풍선을 한 번 띄운다. 규칙·스케줄은 바꾸지 않는다.
8. **정렬**: 저장된 카드는 다음 알림 시각 순. 편집 중인 카드는 저장 전까지 자리를 옮기지 않는다.
9. **문구**: 1–120자, 남은 글자 수 표시. 빈 문구면 [저장] 비활성 + 이유.

## 5. 범위 밖

- reminders 를 독립 "스케줄링 기능" 으로 승격(반복 주기·날짜 지정·스누즈 등): 백로그 유지.
- 플러그인 config 스키마·저장 형식 변경: 없음. 화면만 바꾼다.
- cron 5필드(M7 후보).

## 6. 검증 (기준 14)

- 단위: 12시간제 ↔ `HH:MM` 변환(오전 12시 = 00, 오후 12시 = 12, 분 0–59 경계·범위 밖 거부), 카드별 저장 요청 구성(다른 카드 편집 미포함), 기존 low/high 보존, 새 ID 충돌 없음, 지난 시각 안내 문구.
- e2e: [알림] 탭에서 새 알림을 드롭다운으로 만들고 저장 → settings.json 규칙이 24시간제로 저장되고 시계를 당겨 말풍선이 실제로 뜸, 다른 카드의 저장 안 된 편집은 저장되지 않음, 삭제 확인 후 규칙 제거.
- H: 사용자가 실제로 알림을 만들고 고치며 헷갈리지 않는지 확인.
