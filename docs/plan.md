## 1. 개요

### 1-1. 한 줄 정의

**바탕화면 위에 사는 캐릭터가, 내가 신경 써야 할 일(에이전트 작업 완료, 출석 마감, 메신저 멘션)을 대신 지켜보다가 표정과 말풍선으로 알려 주는 앱.** 모든 기능은 플러그인으로 붙고 뗄 수 있다.

### 1-2. 배경

- 여러 AI 에이전트(Orca worker, Claude Code, Codex)를 병렬로 돌리면 "누가 끝났는지, 누가 나를 기다리는지" 확인하느라 창을 오가게 된다.
- 크래프톤 정글 생활에는 놓치면 안 되는 시간대(학습 시작 04–10시, 학습 종료 23–04시)가 있다.
- Slack, Discord, OS 알림이 각자 울려서 중요한 것과 아닌 것이 섞인다.

**하나의 캐릭터가 이 신호들을 모아 우선순위를 매겨 알려 주면**, 알림 피로는 줄고 놓치는 일은 줄어든다.

### 1-3. 목표

| 목표 | 측정 기준 |
|---|---|
| 에이전트 작업 완료와 입력 대기를 놓치지 않는다 | 완료 후 30초 안에 펫 반응 |
| 정글 출석 마감을 놓치지 않는다 | 마감 30분 전부터 단계적 알림 |
| 새 연동을 코어 수정 없이 추가한다 | 새 플러그인 = 폴더 하나 추가 |
| 방해가 되지 않는다 | 전체 화면, 방해 금지 시간에는 조용함 |
| 가볍다 | 대기 상태 CPU 1% 미만 |

### 1-4. 하지 않는 것 (비목표)

- **출석 버튼 자동 클릭 같은 "대신 행동하기"는 하지 않는다.** 펫은 알리고, 페이지를 열어 주고, 행동은 사람이 한다.
- 비밀번호를 저장하거나 대신 입력하지 않는다.
- 범용 채팅 앱이나 메신저 클라이언트를 만들지 않는다. 메신저는 "알림 소스"로만 쓴다.
- 1차 버전에서는 3D, Live2D 캐릭터를 다루지 않는다. 스프라이트로 시작한다.

## 2. 사용 시나리오

### 시나리오 A. 에이전트 병렬 작업

> 오케스트레이션으로 worker 3개를 돌려 놓고 다른 공부를 한다. 하나가 끝나자 펫이 기뻐하며 "billing-tests 끝! 커버리지 83%"라고 말한다. 다른 worker가 질문을 남기자 펫이 놀란 표정으로 흔들리고, 말풍선의 [열기]를 누르면 Orca의 해당 터미널로 이동한다. coordinator가 "공용 컴포넌트 변경 머지할까요?" 게이트를 만들자 펫 말풍선에 [예] [아니오]가 뜨고, 바로 답한다.

### 시나리오 B. 정글 출석

> 아침 9시 30분, 아직 학습 시작을 안 눌렀다. 펫이 놀란 표정으로 "10시까지 30분!"이라고 말한다. [출석 페이지 열기]를 눌러 브라우저에서 직접 버튼을 누르고 돌아오면, 1분 안에 펫이 "좋아, 오늘도 시작!"이라며 조용해진다. 밤 11시에는 "이제 학습 종료 누를 수 있어"라고 알려 준다.

### 시나리오 C. 메신저

> 팀 Slack 채널에서 나를 멘션하면 펫이 손을 흔들며 미리보기를 보여 준다. Discord 스터디 서버의 공지 채널에 새 글이 올라오면 작은 말풍선으로만 알린다. 집중 모드를 켜 두면 high 우선순위 외에는 모아 두었다가 집중 모드가 끝날 때 한 번에 요약한다.

### 시나리오 D. 새 기능 추가

> 세탁기 종료 알림을 넣고 싶어졌다. `plugins/laundry/` 폴더를 만들고 `manifest.json`과 `index.ts`를 작성해 펫 이벤트를 보내면 끝이다. 코어는 건드리지 않는다. 트레이 메뉴의 플러그인 목록에 자동으로 나타나고, 설정 화면도 스키마로부터 자동 생성된다.

## 3. 설계 원칙

1. **코어는 작게, 기능은 플러그인으로.** 코어는 캐릭터를 그리고, 이벤트를 받고, 알림을 정리하는 일만 한다. Claude Code 연동조차 플러그인이다.
2. **규약이 먼저다.** 캐릭터 형식, 이벤트 형식, 플러그인 API 세 가지를 버전 관리한다. 규약이 안정되면 구현은 언제든 갈아 끼울 수 있다.
3. **알리기만 하고, 행동은 사람이.** 외부 시스템에는 읽기 위주로 접근한다. 쓰기 행동(게이트 승인 등)은 사람이 펫에서 버튼을 눌렀을 때만 실행한다.
4. **조용한 것이 기본.** 이벤트가 많아도 펫은 우선순위를 매겨 꼭 필요한 것만 말한다.
5. **로컬 우선.** 서버 없이 PC 안에서 동작한다. 외부로 나가는 통신은 각 플러그인이 권한으로 선언한 곳으로만 한다.
6. **실패해도 펫은 산다.** 플러그인 하나가 죽어도 코어와 다른 플러그인은 계속 동작한다.

### 4-1. 코어 모듈

| 모듈 | 역할 |
|---|---|
| 펫 창 | 투명·프레임 없음·항상 위·작업 표시줄 숨김. 캐릭터 픽셀 위에서만 클릭을 받는다. 이동 제한은 창이 아니라 보이는 캐릭터(팩의 모든 프레임에서 불투명한 범위) 기준이라 캐릭터가 화면 가장자리에 닿는다. 배율이 다른 모니터에서는 논리 크기를 유지하고 보이는 크기는 OS 배율을 따른다 |
| 말풍선 창 | 펫 옆에 뜨는 별도 작은 창. 텍스트, 버튼 최대 3개 |
| 상태 머신 | idle, walk, sleep 같은 기본 행동 + 이벤트에 따른 반응 상태 |
| 이벤트 버스 | 모든 입력을 `PetEvent`로 통일해 받는다 |
| 알림 큐 | 우선순위 정렬, 중복 합치기, 방해 금지 시 보류 |
| 반응 규칙 | 이벤트 → 표정·애니메이션·말풍선 결정. 플러그인이 규칙을 추가할 수 있다 |
| 액션 레지스트리 | 말풍선 버튼과 트레이 메뉴가 호출할 동작 목록 |
| 스케줄러 | 플러그인의 주기 작업, 특정 시각 작업, 잠자기 복귀 처리 |
| 설정·시크릿 저장소 | 플러그인별 설정과 토큰. 토큰은 `safeStorage`로 암호화 |
| 플러그인 호스트 | 플러그인 로드, 권한 검사, 격리 실행, 오류 시 재시작 |
| 로컬 이벤트 서버 | 플러그인이 없는 도구도 HTTP로 이벤트를 보낼 수 있는 통로 |
| 펫 메뉴 | 펫 우클릭 메뉴. 상호작용(쓰다듬기·말 걸기 등, 현재 캐릭터 팩의 `interactions.json`), 플러그인 트레이 항목, 설정·방해 금지·숨김·오류 기록 폴더 열기·종료. 사용자가 직접 누른 상호작용은 방해 금지·전체 화면 보류를 받지 않는다 (M5 기준 밖 추가, M6 기준 3·12) |
| 설정 창 | [일반][캐릭터][알림][플러그인] 탭. [캐릭터]는 팩 선택·삭제와 어투·상호작용·정보 편집(ADR-0007, D-042), [알림]은 reminders 규칙 카드 편집(D-043), [일반]의 개발자 모드는 내장 팩 직접 편집(D-044, 설치본에서는 숨김) M7: [캐릭터]에 하위 탭 [행동](행동 수치, settings.json 캐릭터별)·[동작](순서 있는 동작)·[알림 반응](알림 종류별 동작)·[애니메이션](개발자 모드에서 시트 교체·새 상태 추가, 상태 미리보기)이 더해졌다(ADR-0008, D-047·D-049) |

## 5. 확장 구조

**이 기획의 핵심입니다.** 새 기능은 아래 확장 지점 중 하나 이상에 끼워 넣는 방식으로 추가합니다.

### 5-1. 확장 지점 (Extension Points)

| 확장 지점 | 하는 일 | 예시 |
|---|---|---|
| **이벤트 소스** | 펫에 `PetEvent`를 보낸다 | Slack 멘션, worker 완료, 출석 마감 임박 |
| **액션** | 이름 붙은 동작을 등록한다. 말풍선 버튼과 트레이 메뉴가 호출한다 | `orca.openWorktree`, `jungle.open-attendance` |
| **트레이 메뉴 항목** | 트레이에 메뉴를 추가한다 | "출석 다시 확인", "Slack 일시 정지" |
| **스케줄** | 주기 또는 특정 시각 작업을 등록한다 | 출석 상태 10분마다 조회, 매일 04:00 리셋 |
| **설정 스키마** | 설정 항목을 선언하면 설정 화면이 자동 생성된다 | Slack 토큰, 감시할 채널 목록 |
| **반응 규칙** | 이벤트 → 펫 반응 매핑을 추가하거나 덮어쓴다 | "orca escalation이면 3초간 흔들기" |
| **캐릭터 상태** | 캐릭터 팩에 새 애니메이션 상태를 추가한다 | `celebrate`, `typing` |
| **상태 표시(배지)** | 펫 옆 작은 배지나 툴팁에 지속 정보를 표시한다. M12 부터 화면에 그린다: 펫 머리 위 칩(경고·일반만, 정상 `ok` 는 트레이에만), 마우스를 올리면 플러그인별 목록, 트레이 플러그인 줄과 아이콘 툴팁. 규약 v2 배지는 선언된 액션을 붙일 수 있어 칩·목록 줄을 누르면 그 액션이 실행된다(트레이 항목과 같은 경로) | "학습 중 · 종료 가능까지 2:13", "확인 대기 2건" |
| **로컬 HTTP / CLI** | 앱 밖에서 이벤트를 보낸다 | Claude Code hook에서 `curl` |

향후 확장 지점 후보는 **패널**(플러그인 전용 작은 UI 창), **음성**(TTS 출력), **대화**(LLM 채팅)입니다. 1차 범위에서는 빼되 API 이름은 미리 예약해 둡니다.

### 5-2. 플러그인 매니페스트 (`manifest.json`)

```json
{
  "id": "jungle",
  "name": "정글 출석",
  "version": "0.1.0",
  "apiVersion": "1",
  "entry": "dist/index.js",
  "description": "크래프톤 정글 출석 상태를 읽고 마감 전에 알려 준다",
  "permissions": {
    "network": ["jungle-lms.krafton.com", "accounts.google.com"],
    "windows": ["lms-checker"],
    "secrets": false,
    "shell": false
  },
  "contributes": {
    "actions": ["jungle.show-login", "jungle.check-now", "jungle.open-attendance"],
    "trayItems": ["jungle.show-login", "jungle.check-now", "jungle.open-attendance"],
    "badges": ["jungle.status"]
  }
}
```

- **`apiVersion`:** 코어가 지원하지 않는 버전이면 로드하지 않고 이유를 표시합니다.
- **`permissions`:** 선언하지 않은 권한은 호스트가 막습니다. 처음 켤 때 사용자에게 권한 목록을 보여 줍니다.
- **`contributes`:** 코어가 플러그인을 실행하기 전에도 트레이와 설정 화면을 구성할 수 있게 미리 선언합니다.

### 5-3. 플러그인 API v1

```ts
// packages/plugin-sdk
export interface PluginContext {
  // 이벤트
  emit(event: PetEvent): void;

  // 액션 (말풍선 버튼, 트레이 메뉴에서 호출)
  registerAction(id: string, handler: (args?: unknown) => Promise<void> | void): Disposable;

  // 트레이
  addTrayItem(item: { id: string; label: string; action: string }): Disposable;

  // 스케줄
  schedule: {
    every(ms: number, fn: () => Promise<void>): Disposable;
    at(cron: string, fn: () => Promise<void>, opts?: { tz?: string }): Disposable;
    onResume(fn: () => void): Disposable;      // 잠자기에서 복귀
  };

  // 반응 규칙
  addReactionRule(rule: ReactionRule): Disposable;

  // 상태 배지
  setBadge(id: string, badge: { text: string; tone?: "neutral" | "warn" | "ok" } | null): void;

  // 설정과 시크릿
  config: Readonly<Record<string, unknown>>;
  onConfigChange(fn: (next: Record<string, unknown>) => void): Disposable;
  secrets: { get(key: string): Promise<string | null>; set(key: string, v: string): Promise<void> };

  // 권한이 있을 때만 동작
  openExternal(url: string): Promise<void>;
  fetch: typeof globalThis.fetch;              // 허용된 호스트만
  windows: { create(id: string, opts: CheckerWindowOptions): Promise<CheckerWindowHandle> };
  exec?: (cmd: string, args: string[]) => Promise<{ stdout: string; code: number }>;

  log: Logger;
}

export interface PluginDefinition {
  configSchema?: ConfigSchema;
  activate(ctx: PluginContext): Promise<void> | void;
  deactivate?(): Promise<void> | void;
}

export function definePlugin(def: PluginDefinition): PluginDefinition;
```

**최소 플러그인 예시:**

```ts
// plugins/hello/index.ts
import { definePlugin } from "@deskpet/plugin-sdk";

export default definePlugin({
  activate(ctx) {
    ctx.registerAction("hello.wave", () =>
      ctx.emit({ source: "hello", type: "react", mood: "happy", text: "안녕!" })
    );
    ctx.addTrayItem({ id: "hello.wave", label: "인사하기", action: "hello.wave" });
  },
});
```

### 5-4. 플러그인 수명주기와 격리

```
발견 (plugins/ 스캔)
  → 매니페스트 검증 (apiVersion, 권한 형식)
  → 사용자 허용 (최초 1회, 권한 목록 표시)
  → 활성화 (utilityProcess에서 activate 호출)
  → 실행 중 (오류 3회 연속 시 비활성화 + 펫이 알림)
  → 비활성화 (deactivate, Disposable 정리)
```

- 플러그인은 Electron `utilityProcess`에서 실행합니다. 플러그인이 멈추거나 죽어도 펫 창과 다른 플러그인은 영향을 받지 않습니다.
- 플러그인과 코어는 메시지로만 통신합니다. `PluginContext`는 이 메시지를 감싼 프록시입니다.
- 1차 버전은 내 플러그인만 쓰므로 격리 수준을 단순하게 시작해도 되지만, **구조는 처음부터 격리 전제로** 만듭니다. 나중에 바꾸기 어렵기 때문입니다.

### 5-5. API 버전 정책

- `apiVersion`은 정수 값을 담은 문자열입니다. 기존 필드를 바꾸거나 지우면 버전을 올립니다. 필드 추가만 하면 그대로 둡니다.
- 코어는 현재 버전과 직전 버전을 함께 지원합니다.
- 규약 변경은 `docs/adr/`에 기록합니다.

## 6. 핵심 규약

### 6-1. PetEvent

```ts
export interface PetEvent {
  source: string;                     // 플러그인 id 또는 "http"
  type: "notify" | "react" | "status";
  key?: string;                       // 같은 key는 하나로 합침 (예: "jungle.deadline")
  text?: string;                      // 말풍선 내용 (최대 120자)
  detail?: string;                    // 펼쳐 보기 내용
  mood?: "happy" | "surprised" | "sleepy" | "worried" | "neutral";
  priority?: "low" | "normal" | "high" | "urgent";
  actions?: Array<{ label: string; action: string; args?: unknown }>;  // 최대 3개
  ttlMs?: number;                     // 지나면 큐에서 제거
  timestamp?: number;
}
```

- **`notify`:** 말풍선으로 알린다 (큐를 거친다).
- **`react`:** 표정·동작만 바꾼다 (말풍선 없음).
- **`status`:** 지속 상태만 갱신한다 (배지, 툴팁).

### 6-2. ReactionRule

```ts
export interface ReactionRule {
  match: { source?: string; type?: PetEvent["type"]; mood?: PetEvent["mood"]; priority?: PetEvent["priority"] };
  play: string;                       // 캐릭터 상태 이름
  durationMs?: number;
  repeat?: number;
  sound?: string;
}
```

코어에는 기본 규칙(`surprised` → surprised 애니메이션 등)이 있고, 플러그인 규칙이 우선합니다.

### 6-3. 캐릭터 팩 (`characters/<id>/manifest.json`)

```json
{
  "id": "mochi",
  "name": "모치",
  "apiVersion": "1",
  "cellSize": [256, 256],
  "anchor": [128, 240],
  "scale": 0.6,
  "states": {
    "idle":      { "sheet": "sheets/idle.png",      "frames": 8, "fps": 8,  "loop": true },
    "blink":     { "sheet": "sheets/blink.png",     "frames": 4, "fps": 12, "loop": false, "next": "idle" },
    "walk":      { "sheet": "sheets/walk.png",      "frames": 6, "fps": 10, "loop": true },
    "sleep":     { "sheet": "sheets/sleep.png",     "frames": 4, "fps": 3,  "loop": true },
    "happy":     { "sheet": "sheets/happy.png",     "frames": 6, "fps": 10, "loop": false, "next": "idle" },
    "surprised": { "sheet": "sheets/surprised.png", "frames": 5, "fps": 12, "loop": false, "next": "idle" },
    "worried":   { "sheet": "sheets/worried.png",   "frames": 6, "fps": 8,  "loop": true },
    "talk":      { "sheet": "sheets/talk.png",      "frames": 4, "fps": 8,  "loop": true },
    "drag":      { "sheet": "sheets/drag.png",      "frames": 4, "fps": 8,  "loop": true }
  },
  "fallbacks": { "worried": "surprised", "celebrate": "happy" }
}
```

- **`anchor`:** 발 위치. 모든 상태에서 같은 기준점을 써서 떨림을 막는다.
- **`fallbacks`:** 캐릭터 팩에 없는 상태를 플러그인이 요청하면 대체 상태를 쓴다. 덕분에 플러그인이 새 상태를 요구해도 캐릭터가 깨지지 않는다.
- **선택 필드 (모두 `apiVersion` "1" 유지):** `voice`(어투 템플릿 파일, D-029), `interactions`(우클릭 상호작용 파일), `meta`(제작자·버전·라이선스·설명), `preview`, `extends`(내장 팩을 원본으로 하는 파생 팩: 그림은 원본 것을 쓰고 어투·상호작용·메타·재생 설정만 덮어쓴다). 상세는 ADR-0007.
- **내장 팩과 사용자 팩:** 내장 팩은 앱의 `characters/`(읽기 전용), 사용자 팩은 `userData/characters/`. 내장 팩을 편집해 저장하면 "(내 버전)" 파생 팩이 생긴다(D-042). 개발 실행에서 개발자 모드를 켜면 내장 팩을 직접 고친다(D-044). 선택한 팩은 `settings.json`에 저장된다.
- **M7 선택 필드 (모두 `apiVersion` "1" 유지, ADR-0008):** `behavior`(잠들기까지 시간·깜빡임·걷기 간격·걷는 시간·속도의 팩 기본값, 사용자 값은 `settings.json` 캐릭터별), `sequences`(순서 있는 동작 파일 `sequences.json`: 단계마다 상태·시간·대사, 최대 8단계·30초), `reactions`(알림 종류별 동작 파일 `reactions.json`: 완료·대기·실패 등 7종류에 재생 동작 또는 순서 있는 동작). 상호작용 항목에는 `play`(재생할 상태)와 `sequence`(순서 있는 동작 id)를 둘 수 있다. 우선순위는 팩 매핑 > 플러그인 반응 규칙 > 표정 규칙이고, 외부 이벤트는 동작을 직접 지정할 수 없다.
- **그림 교체 (D-047):** 파생 팩은 그림을 원본과 공유한다(ADR-0007 Q4·Q6 유지). 시트 교체와 새 상태 추가는 개발 실행의 개발자 모드에서 내장 팩에만 할 수 있고 설치본에는 없다.

### 6-4. 로컬 HTTP API

| 메서드 | 경로 | 용도 |
|---|---|---|
| POST | `/event` | `PetEvent` 하나 보내기 |
| POST | `/action/:id` | 등록된 액션 실행 (설정에서 허용한 액션만) |
| GET | `/status` | 펫 상태, 활성 플러그인 목록 |

- `127.0.0.1`에만 바인딩합니다. 요청마다 `Authorization: Bearer <토큰>`이 필요하고, 토큰은 설정 창에서 확인·재발급합니다.
- 같은 기능의 CLI(`deskpet event --text "..." --mood happy`)를 제공해서 hook에서 쓰기 쉽게 합니다.
- 요청 하나의 헤더와 본문은 합쳐 5초 안에 다 받아야 하고, 넘으면 연결을 끊습니다. 본문은 64 KiB, 동시 연결은 16개까지입니다. Host 나 Authorization 헤더가 중복되면 거부합니다.
- 앱은 서버가 열린 뒤 userData 의 `event-server.json` 에 `{port, token, pid}` 를 한 번에 기록하고, 종료하거나 서버를 열지 못하면 `port` 를 지웁니다. CLI 는 `port` 가 없거나 `pid` 의 프로세스가 없으면 요청을 보내지 않습니다(다른 로컬 서비스로 토큰이 새는 것을 막음). 저장소 루트의 `deskpet.cmd` 가 CLI 를 감싸므로 그 폴더를 PATH 에 넣으면 `deskpet` 으로 실행합니다. 자세한 내용은 ADR-0004.

### 7-2. `claude-code`

- Claude Code와 Codex의 hook에서 `deskpet event` CLI나 `curl`로 이벤트를 보냅니다.
- 이벤트에 현재 작업 경로를 포함해서 말풍선에 worktree 이름을 표시합니다.
- Orca 없이도 동작하는 가장 단순한 개발 알림입니다.
- M7: Codex 는 별도 플러그인 `codex`(출처 `codex`)로 나뉘었습니다. 기존 `notify` 래퍼 설정은 그대로 동작하고, 플러그인을 끄면 그 플러그인의 반응 규칙만 빠지며 말풍선과 기본 표정 반응은 남습니다.

### 7-3. `orca`

M11 에서 구현했습니다(ADR-0012, D-066). 처음 계획했던 `check --peek --all` 은 Orca CLI 가 바뀌어 쓸 수 없었습니다(`--peek` 와 `--all` 을 함께 못 씀, 메시지함이 터미널·Run 단위).

- 플러그인은 Orca CLI 를 직접 실행하지 않습니다. 규약 v2 의 `ctx.orca` 로 호스트에 요청하고, 호스트(main)가 `orca.exe` 를 허용 목록·`shell:false`·시간과 출력 상한 안에서 실행합니다. 권한은 `orcaRead`·`orcaGateResolve`·`orcaOpenTerminal` 셋입니다.
- 상태를 읽는 명령은 `run-list`·`task-list`·`gate-list`·`worker-list`·`terminal show` 와 메시지를 가져가지 않는 `inbox --full --json` 입니다. **메시지를 가져가는 기본 `check` 는 부르지 않습니다.**
- **빠른 감지(M12):** 호스트가 `%APPDATA%\orca\orchestration.db-wal` 의 수정 시각만 1초마다 확인하고(내용은 읽지 않음) 바뀌면 바로 읽습니다. 읽기 사이는 최소 3초, 30초마다 전체 읽기를 안전망으로 유지합니다. 빠른 읽기는 진행 중인 Run(끝나지 않은 task·살아 있는 worker·대기 게이트가 있는 Run)과 새 Run 만 동시에 4개씩 읽고, 끝난 Run 은 30초 전체 읽기에서 다시 봅니다. 이 PC(Run 18개) 실측: 전체 읽기 22.4초 → 7.7–10.8초, 빠른 읽기 2.9–3.3초, 게이트 생성 → 말풍선 3.5초. 파일을 못 쓰면 30초 확인으로 내려가고 `/status` 에 "빠른 감지 꺼짐".
- **놓친 게이트(M12):** 대기 게이트는 펫 칩 "확인 대기 N건"과 트레이에 남고, 첫 알림 뒤 5분마다 최대 3번 다시 알립니다. 말풍선이 닫혀도 재알림은 계속되고, 말풍선의 [다시 알리지 않기]만 그 게이트의 재알림을 멈춥니다(배지·다시 보기는 유지). 칩·트레이 "대기 중인 Orca 확인 다시 보기"로 버튼 있는 말풍선을 다시 띄웁니다.
- **복구 뒤(M12):** 확인 불가에서 복구한 첫 결과는 이미 본 것으로만 기록해 지난 질문·게이트를 다시 알리지 않습니다.
- 이미 알린 것은 `<userData>/orca-notification-ledger.json` 에 ID·종류만 기록해 재시작 뒤에도 다시 알리지 않습니다. Orca 가 꺼져 있거나 형식이 바뀌면 "Orca 상태를 확인할 수 없어" 를 한 번 알리고, 깨진 Run 하나는 건너뜁니다.

| Orca 상태 | 펫 반응 |
|---|---|
| worker 완료 / 실패 | "{작업}이 끝났어" / "{작업}에 실패했어" + [열기] (Orca 터미널 탭 전환) |
| 게이트 생성 | 높은 우선순위 "{작업} 확인이 필요해" + 게이트 선택지 원문 버튼 → 직전 재확인 뒤 `gate-resolve` |
| question, escalation | 높은 우선순위 "{작업} 질문이 왔어" / "{작업}에서 문제가 생겼어" |
| coordinator 대기 (agentWait 양성) | "{작업}에서 나를 기다려" |
| 종료된 worker 가 완료 없이 끝남 | "{작업}이 멈춘 것 같아" (시간 기준은 실측 뒤) |

- 쓰기 동작은 게이트 승인 하나뿐이며 사용자가 버튼을 눌렀을 때만 실행합니다. [열기]의 터미널 탭 전환은 Orca 화면만 바꾸는 동작으로 사용자 결정으로 허용했습니다.
- 실사용에서 드러난 것(2026-10-13): 30초 간격이라 알림이 평균 15초 늦고, 말풍선이 닫힌 게이트는 다시 알리지 않아 자리를 비우면 놓쳤습니다. M12 에서 위의 빠른 감지·놓친 게이트 처리로 해소했습니다(ADR-0012 보강).

### 7-4. `jungle`

상세 설계는 별도 문서 `docs/jungle-plugin-design.md`를 따릅니다. 요약하면 이렇습니다.

- **방식:** 직접 설계했습니다(D-026, Jungle Bell 은 사용 방식만 참고). 앱 안 LMS 창(`lms-checker`) 하나에서 사용자가 직접 로그인하고, 호스트가 그 창의 세션으로 홈 출처(`https://jungle-lms.krafton.com`)에 GET 두 개(`/api/v2/me/cohorts`, `/api/v2/me/cohorts/{id}/attendance/today`)를 보내 상태를 읽습니다(ADR-0006, 요청은 main 의 `net.request`).
- **판정:** 응답의 `checkedAt`이 있으면 학습 시작, `checkedOutAt`이 있으면 학습 종료로 봅니다. 04·10·23시 경계로 `NeedStart`, `StartOverdue`, `Studying`, `NeedEnd`, `Complete` 상태를 계산합니다.
- **반응:** 마감 30분 전부터 단계적으로 알리고, [출석 페이지 열기]와 [로그인]은 같은 앱 안 창을 새로 열어 `/check-in`(로그아웃이면 로그인 화면)을 보여 줍니다(D-039·D-040, 시스템 브라우저를 쓰지 않아 로그인이 하나로 합쳐짐). 출석은 사용자가 그 창에서 직접 누릅니다. 사용자가 직접 누른 확인은 항상 현재 상태를 한 줄로 알립니다.
- **확장 후보:** Jungle Bell이 제공하는 세탁실, 식단 정보는 별도 `jungle-life` 플러그인으로 분리합니다. 데이터 출처와 이용 조건은 확인한 뒤 진행합니다.

### 7-5. `slack`

- **Socket Mode**를 씁니다. 공개 서버나 URL 없이 PC에서 바로 이벤트를 받을 수 있습니다.
- **M10 구현(ADR-0011):** 토큰은 앱 수준 토큰(`xapp-`)과 설치 사용자 토큰(`xoxp-`)입니다. 봇 토큰(`xoxb-`)은 봇에게 온 메시지만 볼 수 있어 "나를 멘션"을 받지 못합니다. 연결은 플러그인이 아니라 호스트가 열고(규약 `apiVersion "2"`, `ctx.slack`), 플러그인은 토큰 값을 읽지 못합니다. 버튼 없이 Slack 에 보내는 것은 연결 열기와 수신 확인(ack) 두 가지뿐입니다(D-062).
- 설정 항목은 두 토큰, 내 멤버 ID, 지정 채널, 키워드, 멘션만 알림(DM 은 유지), 본문 숨기기입니다. 앱 만들기 안내는 `docs/slack-setup.md`.
- **한계(D-064):** 개인이 만든 앱은 관리자 승인 없이 남이 관리하는 워크스페이스(기업용)에 설치할 수 없습니다. 직접 만든 워크스페이스용으로 남기고, 메신저 알림은 Windows 알림 읽기로 받는 방향을 검토합니다.

### 7-6. `discord`

- 봇이 게이트웨이에 직접 접속하므로 별도 서버가 필요 없습니다.
- 메시지 내용을 읽으려면 개발자 포털에서 **Message Content intent**를 켜야 합니다 (권한이 필요한 intent).
- 설정 항목은 서버와 채널 목록, 멘션만 알림 여부입니다.

### 7-7. `reminders`

- 사용자가 설정 화면에서 반복 알림을 등록합니다 (예: "매일 12:20 점심").
- 다른 플러그인 개발 전에 스케줄러와 설정 스키마를 검증하는 **기준 플러그인** 역할도 합니다.
- 규칙은 설정 창 [알림] 탭에서 알림별 카드로 편집합니다: 오전/오후·시 드롭다운과 분 입력, 요일 칩, "방해 금지 중에도 알림", 카드마다 저장·삭제·미리보기, 다음 알림 시각 표시(D-043, `docs/reminders-ux.md`). 저장 형식은 24시간제 `HH:MM` 그대로입니다.
- 알림 문구에는 현재 캐릭터의 어투(`reminder`)가 입혀집니다. jungle 알림도 같습니다(M6 기준 2). M12 부터는 아래 "플러그인 대사"로 바뀌었습니다.

**플러그인 대사(M12, ADR-0013):** 내장 플러그인 6종과 Claude Code·Codex 훅의 말풍선은 모두 각 플러그인의 대사 목록(`lines.json`: 대사 id·이름·종류·변수·기본 문장)에서 나옵니다. 알림은 문장 대신 대사 id 와 변수를 보내고, 문장은 **사용자가 고친 대사 → 현재 캐릭터 팩의 대사(`voice.json` 의 `lines`) → 플러그인 기본 문장** 순서로 고릅니다. 종류별 어투(`templates`)는 대사 id 가 없는 알림(외부 v1 플러그인, 직접 보낸 HTTP 이벤트)에만 씁니다. 동작은 사용자 대사별 지정 → 팩 대사별 → 종류별 → 플러그인 규칙 → 기분 순서입니다. 사용자는 설정 [어투]·[반응] 아래 플러그인별 섹션에서 대사마다 문장(여러 개)과 동작을 고치고, 고친 값은 캐릭터 팩별로 `settings.json` 에 저장됩니다. 기본 팩 wolf-maid 는 모든 대사를 "주인님" 말투로 담고 있습니다. 코드에 말풍선 문장을 직접 쓰는 것은 검사 테스트(`scripts/line-hardcoding.test.ts`)가 막습니다.

## 8. 알림 정책

알림이 많아질수록 펫이 시끄러워지면 금방 꺼 버리게 됩니다. 코어가 일관되게 관리합니다.

### 8-1. 우선순위

| 우선순위 | 표시 방식 | 방해 금지 중 |
|---|---|---|
| `urgent` | 말풍선 + 반복 애니메이션 + 소리 | 표시 |
| `high` | 말풍선 + 애니메이션 | 보류 (전체 화면이면 보류) |
| `normal` | 말풍선 | 보류 |
| `low` | 표정만 바꾸고 배지 갱신 | 보류 후 요약에 개수로 포함 (2026-10-07 결정, 구현에 맞춤) |

### 8-2. 규칙

- **합치기:** 같은 출처의 같은 `key` 이벤트는 최신 하나로 합칩니다. 같은 출처에서 30초 안에 3개 이상 오면 "Slack 메시지 4개"처럼 묶습니다. `key` 가 있는 이벤트도 묶음에 들어갑니다.
- **속도 제한:** 말풍선은 최소 5초 간격으로 표시합니다. `urgent` 도 예외가 아니며 우선순위만 앞섭니다 (2026-10-07 결정).
- **방해 금지:** 수동 토글, 시간대 설정, 전체 화면 앱 감지 시 자동으로 켭니다. `urgent` 는 방해 금지 중에도 바로 보입니다. M3 에서 시간대는 userData 의 `settings.json` 을 편집해 정하고(설정 화면은 M4), 전체 화면은 Windows 알림 상태(`SHQueryUserNotificationState`)를 2초 간격으로 확인합니다.
- **요약:** 방해 금지가 끝나면 보류한 알림을 한 번에 요약해서 보여 줍니다. 보류한 알림이 하나뿐이면 요약하지 않고 원문을 보여 줍니다. 보류 중 만료된 알림은 요약에서 빠집니다.
- **만료:** `ttlMs`가 지난 알림은 버립니다 (예: 이미 지난 출석 마감 알림).

## 9. 캐릭터와 아트

### 9-1. 콘셉트 방향

- 2등신 치비 스타일이나 픽셀 아트. 128–256px 크기에서도 실루엣과 표정이 잘 보이는 디자인.
- **오리지널 캐릭터**로 만듭니다. 기존 캐릭터(예: 루미)를 본뜨면 배포 시 저작권 문제가 생깁니다.

### 9-2. 필수 애니메이션 상태 (1차)

`idle`, `blink`, `walk`, `sleep`, `happy`, `surprised`, `worried`, `talk`, `drag` 9개. 상태당 4–8프레임.

### 9-3. AI 아트 파이프라인

```
1. 디자인 시안 ─▶ 2. 기준 이미지 확정 ─▶ 3. 애니메이션 생성 ─▶ 4. 후처리 ─▶ 5. 검수 ─▶ 캐릭터 팩
   (이미지 생성)     (정면, 투명 배경)     (상태별)              (배경 제거,    (밝은·어두운
                                                                 셀·발 정렬)    배경, 루프)
```

| 단계 | 도구 후보 | 비고 |
|---|---|---|
| 디자인 | 이미지 생성 AI | 여러 안 → 하나 확정 |
| 애니메이션 (쉬움) | PixelLab, AutoSprite, FrameSprite | 기준 이미지 한 장 → 상태별 시트 |
| 애니메이션 (고품질) | 영상 생성 AI + LayrKits/Sprite-Pipeline | 영상 → 프레임 추출 → 정리. AI 에이전트용 skill 포함 |
| 후처리 | 자체 스크립트 (`tools/sprite-pipeline/`) | 배경 제거, 256×256 셀, 발 위치 정렬, 시트 패킹 |
| 검수 | 자체 뷰어 (`tools/sprite-viewer/`) | 밝은·어두운 배경, 실제 크기, 루프 이음새 |

### 9-4. 아트 품질 기준

- 모든 프레임의 발 위치가 `anchor`와 일치한다 (오차 2px 이내).
- 어두운 배경에서 흰 테두리(halo)가 보이지 않는다.
- `idle`, `walk`, `sleep`, `talk`는 첫·마지막 프레임이 자연스럽게 이어진다.
- 실제 표시 크기(약 150px)에서 표정이 구분된다.
- 발 위치는 `pnpm sprites:check <팩 폴더>`로 확인한다. 판정 정의(불투명 기준, 잡점, 반투명 잔여)는 `tools/sprite-pipeline/README.md`에 있다.

### 9-5. 주의

- 사용하는 생성 도구의 약관에서 생성물의 상업적 이용 가능 여부를 확인합니다.
- AI로만 만든 이미지의 저작권 인정 여부는 국가마다 해석이 다르고 정리 중인 영역입니다. 판매나 공개 배포 전에는 확인이 필요합니다.

| 조회 빈도 | 외부 서비스에 부담을 주지 않도록 넉넉한 간격과 지수 백오프를 쓴다 |

## 13. 개발 방식

앞서 구성한 Orca 오케스트레이션 구조로 개발합니다.

### 13-1. 역할

| 역할 | 담당 | 맡는 일 |
|---|---|---|
| coordinator | Claude (Pro 이상, 계획 단계만 Opus) | M0 규약 설계, 작업 분해, 머지 판단 |
| 구현 | Codex Sol | 이벤트 서버, 알림 큐, 플러그인 호스트, 각 플러그인 |

| 막힌 작업 | Claude Sonnet | 설계 판단이 필요한 구현 |

| task | worker | 의존성 |
|---|---|---|

## 16. 진척 관리

품질 점검이 "이 작업이 제대로 됐는가"를 본다면, 진척 관리는 **"프로젝트가 목표를 향해 제대로 가고 있는가"**를 봅니다.

### 16-1. 원칙

1. **활동이 아니라 완료 기준으로 측정한다.** 커밋 수, 끝난 task 수는 바쁘다는 신호일 뿐이다. 진척은 "마일스톤 완료 기준 중 몇 개를 검증했는가"로만 센다.
2. **시간은 제약이 아니다. 진짜 제약은 따로 있다.** 이 프로젝트는 투입 시간에 제한을 두지 않는다. 대신 실제로 속도를 묶는 것은 다음 세 가지이며, 진척 관리는 이 셋을 지킨다.
   - **AI 한도:** Claude Pro, Codex Plus의 5시간·주간 한도
   - **사람의 주의력:** 확인, 결정, QA를 처리하는 속도
   - **범위:** 시간 제한이 없으면 범위가 끝없이 늘어나 "완성"이 오지 않는다
3. **기록은 자동으로, 판단은 사람이.** 숫자는 coordinator와 스크립트가 모으고, 사람은 방향과 결정만 덧붙인다.
4. **문서가 코드를 따라간다.** 구현 중에 바뀐 결정은 마일스톤 종료 전에 기획안과 ADR에 반영한다. 다음 마일스톤의 coordinator가 틀린 문서로 계획하지 않게 하기 위해서다.

### 16-2. 점검 축

| 축 | 질문 | 지표 | 수집 |
|---|---|---|---|

| **M8** 마감 | 설치 파일 | 새 PC에 설치 후 자동 시작 (H) · 플러그인 가이드로 예제 플러그인 작성 성공 (R) · 오리지널 캐릭터 팩 (H) | M |

**v1의 정의는 M5까지**입니다. M5를 통과하면 "매일 쓰는 도구"가 완성된 것으로 보고, M6 이후는 v1을 쓰면서 우선순위를 다시 정합니다.

### 16-4. 점검 주기

| 주기 | 누가 | 내용 | 산출물 |
|---|---|---|---|
| 작업 세션 종료 | coordinator (자동) | 머지·실패·blocked·사람 확인 대기·한도 메모 | `STATUS.md` 갱신 |
| 매일 | 사람 (5–10분) | STATUS 확인, 사람 확인 대기와 결정 대기 처리 | `decisions.md` 갱신 |
| 매주 | 사람 + coordinator | 6축 점검, 경고 신호 확인, 다음 주 목표 | `weekly/YYYY-Www.md` |
| 마일스톤 종료 | 사람 + coordinator | 데모, 출구 기준 전수 확인, 리스크·기획안·ADR 갱신, 다음 단계 판단 | `milestones.md` 갱신 |

### 16-5. 경고 신호와 대응 규칙

신호가 보이면 고민하지 않고 정해진 대응을 먼저 실행합니다.

| 신호 | 의미 | 대응 |
|---|---|---|
| 마일스톤 소모량이 규모 추정의 1.5배 초과 | 범위가 크거나 가정이 틀림 | 완료 기준 일부를 다음 마일스톤으로 넘기고 남은 것만 마무리 |
| task 재시도율 30% 이상 | 명세가 모호함 | 신규 task를 멈추고 분해 단계와 명세 템플릿 점검 |
| 같은 리뷰 지적 2회 이상 | 규칙 부재 | AGENTS.md 규칙이나 자동 검사로 승격 |
| 사람 확인 대기 5개 이상 | 사람이 병목 | QA 묶음 처리 시간을 잡고, 반복되는 확인은 검증 도구로 자동화 |
| 미머지 브랜치 3일 이상 | 통합 부채 | 신규 task 중단, 통합 먼저 |
| 주 중반에 주간 한도 80% 소진 | 속도 과다 | 병렬 수 축소, Luna 비중 확대, Opus 사용 중지 |
| 기획안에 없는 기능이 머지됨 | 범위 증가 | 되돌리거나 백로그로 옮기고 기획안에 명시 |
| 2주 연속 펫을 켜지 않음 | 가치 문제 | 새 기능을 멈추고 알림 정책·사용성 재검토 |

### 16-6. 범위 관리

시간 제한이 없기 때문에 **범위 관리가 사실상 일정 관리**입니다.

- **마일스톤 범위 동결:** 마일스톤의 ① 계획 단계에서 정한 완료 기준 외의 작업은 그 마일스톤에서 하지 않는다.
- **아이디어는 백로그로:** 진행 중 떠오른 기능 아이디어는 `docs/progress/backlog.md`에 한 줄로 적고, 마일스톤 종료 시에만 검토한다. worker가 제안한 개선도 같다.
- **WIP 상한:** 동시에 진행하는 마일스톤은 하나. 아트 작업만 예외로 병행한다.
- **완성의 정의:** v1(M5) 통과 후에는 "새 플러그인 추가"가 아니라 "v1을 2주 써 본 결과"로 다음 작업을 정한다.

### 16-7. 마일스톤 종료 판단

마일스톤 종료 점검에서 다음 셋 중 하나를 고르고, 이유를 `milestones.md`에 남깁니다.

| 판단 | 조건 | 다음 행동 |
|---|---|---|
| **계속** | 출구 기준 전부 충족, 경고 신호 없음 | 다음 마일스톤 ① 계획 |
| **조정** | 출구 기준 80% 이상 충족, 남은 기준이 다음 단계를 막지 않음 | 남은 기준을 다음 마일스톤으로 이월하고 진행 |
| **멈춤** | 핵심 기준 미충족, 또는 가치 신호가 나쁨 | 원인 분석 마일스톤(M*n*.5)을 만들거나 계획 재검토 |

### 16-8. 진척 문서 구조와 자동 갱신

```
docs/progress/
├── STATUS.md          # 현재 상태 한 장 (세션마다 coordinator가 갱신)
├── milestones.md      # 마일스톤별 출구 기준 체크 현황과 종료 판단
├── decisions.md       # 결정 대기 / 결정 완료
├── backlog.md         # 범위 밖 아이디어
└── weekly/
    └── 2026-W41.md    # 주간 점검 기록
```

- `orchestrate` skill의 완료 보고 단계에서 `STATUS.md`를 갱신합니다 (Orca `task-list --json`, `git log`, 테스트 결과 기반).
- 수치 수집과 초안 작성은 Luna worker나 스크립트(`scripts/progress-snapshot`)에 맡기고, 사람은 가치·방향·결정만 덧붙입니다.
- 진척 문서는 coordinator가 매 세션 읽지 않습니다. 세션 시작 시에는 `STATUS.md`만 읽고, 나머지는 필요할 때만 참조합니다.
