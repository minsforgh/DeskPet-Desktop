# 옆모습과 걷기 프레임

사용자 결정(2026-10-07): 걷기는 옆에서 본 모습으로 만든다. 도형으로 그린 시안은 앞모습보다 거칠어 기각했고, 앞모습(`base_final.png`)을 참조해 이미지 생성 도구로 만든 후보 4장(`gen/`) 중 **candidate-01** 을 기준으로 골랐다(D-020).

- `gen/` — ART-6 후보 raw 원본, 정리 결과, 비교 그림, 프롬프트(`NOTES.md`)
- `make-master.mjs` — candidate-01 의 팔레트 정리본을 106x192 마스터로 만들고, 앞모습과 의복 색감을 맞춘다(치마·소매의 어두운 `shoe` 색 → `dress`, 의복 안쪽 `outline` 점 → `dress-shadow`). `node docs/art/side/make-master.mjs` → `side_base.png`
- `parts-side.json` — 옆모습 부위 지도(귀, 얼굴, 포니테일, 꼬리, 손, 앞·뒤 다리). 발 아랫변 행 191, 발 중심 x64.5
- `states-side.json` — 옆모습 프레임 spec. 만드는 명령:
  `pnpm sprites:frames --spec docs/art/side/states-side.json --out docs/art/side/out --preview-scale 4`
- `out/walk/frame-01..06.png`, `out/walk.strip.preview.png` — 걷기 6프레임 v1 (오른쪽 진행. 왼쪽은 좌우 반전)

## 걷기 v2 (2026-10-07)

한 걸음 6프레임: 땅에 닿은 발은 4프레임 동안 몸 쪽으로 밀려가고(+4px → -4px), 2프레임 동안 3px 들려 앞으로 돌아온다. 앞발과 뒷발은 3프레임 차이다(v1 보폭 ±3px → ±4px). 꼬리는 좌우 ±2px, 위아래 ±1px, 포니테일은 ±1px 로 걸음에 맞춰 살랑거린다.

신발이 깨지던 원인: 앞·뒤 다리 영역의 경계를 앞다리 스타킹 한가운데(x63/64)에 잘못 잡았고, 두 발이 서로 엇갈릴 때 먼저 옮겨진 픽셀을 다음 이동이 다시 옮겼다. 고친 방법: 경계를 두 신발 사이(x61/62)로 옮기고, 한 프레임의 모든 이동을 같은 원본에서 동시에 읽는 `shift-set` 연산을 추가했다(`tools/sprite-pipeline/README.md`).

## 약점 (직접 열어 보고 적음)

- AI 생성 후 정리한 도트라 앞모습(사용자가 손본 도트)보다 잡티와 거친 윤곽이 있다. 잔 픽셀 정리가 필요하다.
- 보폭은 ±4px 이다. 더 크게 하면 발이 몸에서 떨어져 보일 수 있다.
- 몸 전체의 위아래 흔들림(bob)이 없다(발 아랫변 고정 검사 때문에 몸만 움직이는 방식이 필요).
- 얼굴이 작아 표정(눈 감기, 입)은 옆모습에서는 만들지 않았다.
