# 마일스톤 종료 점검

대상 마일스톤: M$ARGUMENTS

번호가 없으면 `docs/progress/STATUS.md`의 현재 마일스톤을 대상으로 한다.

## 절차

1. **완료 기준 확인.** `docs/progress/milestones.md`의 완료 기준을 하나씩 검증 근거와 함께 확인한다.
   - A(자동): 명령을 실제로 실행하고 결과를 근거로 적는다. 테스트 통과만으로 끝내지 않고, 사용자가 쓰는 경로(PowerShell에서 README에 적힌 명령 그대로)로도 한 번 실행한 뒤 충족으로 적는다.
   - R(에이전트 리뷰): 리뷰 worker의 보고를 근거로 적는다. 없으면 리뷰 task를 제안한다.
   - H(사람 확인): 직접 판정하지 않는다. "잘 됨 / 안 됨"만 묻지 말고, 실행 방법부터 단계별로 적은 플레이 테스트 절차를 먼저 안내한다. 사용자가 알려 준 증상이 모호하면 추측으로 고치지 말고 스크린샷이나 재현 순서를 요청한다.
2. **데모 산출물.** 16-3장의 데모 형태에 맞는 산출물을 만들고 경로를 적는다 (스크린샷, GIF, 문서 목록).
   만들 수 없는 형태면 사용자가 해야 할 일로 넘긴다.
3. **문서 반영 목록.** `docs/plan.md` 14장 리스크 중 해소되거나 새로 생긴 것, 구현 중 바뀐 결정을 기획안과 ADR에 반영할 목록을 보여 준다. 승인받기 전에는 기획안과 ADR을 고치지 않는다.
4. **규칙화 후보.** 리뷰에서 두 번 이상 반복된 지적을 AGENTS.md 규칙이나 자동 검사로 바꿀 후보를 제안한다.
5. **권고.** `docs/plan.md` 16-7장 기준으로 계속 / 조정 / 멈춤 중 하나를 이유와 함께 권한다.
   - 계속: 출구 기준 전부 충족, 경고 신호 없음
   - 조정: 80% 이상 충족, 남은 기준이 다음 단계를 막지 않음
   - 멈춤: 핵심 기준 미충족, 또는 가치 신호가 나쁨

## 결정은 사용자가 한다

- 권고만 하고 `milestones.md`의 "판단" 칸은 사용자가 답한 뒤에 적는다.
- 사용자가 결정하면 `milestones.md`의 종료 점검과 요약 표, `STATUS.md`를 갱신한다.
- M1을 닫을 때는 S/M/L 규모의 실제 소모량을 확정해 요약 표에 적는다.
- 다음 마일스톤은 여기서 시작하지 않는다. `/milestone-start`로 따로 시작한다.
